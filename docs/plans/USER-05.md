## 명세 점검
- 상태 전이
  - 사용자: `활성` → `삭제됨`(`deleted_at`, `toss_anon_key` NULL). 되돌리지 않는다 (복구 없음, Q-102)
  - 그 사용자의 현재 멤버 행: `현재 멤버` → `나감`(`DATA_DELETED`). 모든 멤버 행(예전에 나간 행 포함)의 `user_id`를 NULL로 끊는다
  - 방: 마지막 멤버면 삭제, 방장이면 위임, 인증 중 전원 인증이 되면 투표 시작·투표 중 전원 투표면 마감 (ROOM-07과 같음)
  - 같은 `anonKey`로 다시 로그인: 새 사용자 행 (`isNewUser: true`)
- 동시성
  - 사용자 행 락을 먼저 잡는다. 같은 사용자의 방 만들기·입장·나가기도 사용자 행 락을 잡아서 하나씩 처리된다 (10번)
  - 그다음 참여 중인 방을 방 ID 순서로 하나씩 방 행 락을 잡고 `removeMember`를 부른다. 사용자 → 방 순서는 나가기·입장과 같다. 방이 여러 개여도 같은 순서로 잡아 교착을 막는다
  - 다른 멤버의 나가기·내보내기·마지막 인증과는 방 행 락으로 하나씩 처리된다
  - 삭제 직후 같은 토큰으로 오는 요청은 필터가 `deleted_at`을 보고 거절한다 (이미 구현). 삭제 트랜잭션이 커밋되기 전 요청은 사용자·방 락을 기다린다
- 권한: 로그인한 본인
- 외부 연동 실패: 없음. 사진 저장소(CERT-04)가 아직 없어 사진 삭제는 CERT-04 구현 때 붙인다
- 금액: 공양미 기록을 모두 지운다. 나가기 차감(RICE-03)은 하지 않는다 (2번). 이미 다른 사람에게 준 공양미(톡톡 보상 등)는 그 사람 기록이라 건드리지 않는다
- 제외 범위: 한 줄·금액 6개월 뒤 정리(CLEAN-01), 사진 파일 삭제(CERT-04)

## 설계

### API 계약
- `DELETE /api/users/me`: 응답 200 데이터 없음. 에러 `COMMON_008`
- 로그인 `POST /api/auth/login`: 응답 모양 그대로. 삭제한 사용자의 `anonKey`로 오면 `isNewUser: true`

### 엔티티
- `KickBlock` (`kick_blocks`): anonKeyHash(CHAR 64), room, expiresAt. `UNIQUE (anon_key_hash, room_id)`
- `User`: `deleteData(now)` (삭제 시각, 식별키 NULL). `isRestorable`, `restore` 제거
- `RoomMember`: 사용자 연결 끊기는 벌크 update 한 문장 (`update RoomMember set user = null where user.id = :userId`)

### 주요 결정
1. **사용자 행은 남긴다**: 방 멤버, 회차의 지목 사용자 등이 `users`를 참조한다. 개인정보(식별키)만 비운다. 알림 토글 값은 빈 행에 남아도 누구인지 알 수 없어 그대로 둔다
2. **삭제 순서**: 사용자 락 → 방마다 락·`removeMember(DATA_DELETED)` → 내보내진 방 해시 저장 → 공양미 기록·방어권·알림 동의 삭제 → 멤버 행 연결 끊기 → 식별키 비우고 삭제 시각 저장. 해시는 식별키를 비우기 전에 만든다
3. **해시**: SHA-256 16진수. 토스 익명키는 추측할 수 없는 값이라 별도 비밀값(salt) 없이도 원래 키를 되돌릴 수 없다. 입장할 때 새 사용자의 키를 같은 방식으로 해시해 비교한다
4. **내보내진 방 범위**: 그 사용자의 멤버 행 중 `leave_type = KICKED`인 방 전부. 내보내진 시각과 상관없이 삭제 시각부터 6개월
5. **입장 막기**: INVITE-02 판단 3번(내가 이 방에서 내보내졌다)에 "내 식별키 해시로 만료 전 차단 기록이 있다"를 함께 본다. 미리보기와 입장이 같은 판단을 써서 둘 다 막힌다 (`UNAVAILABLE` → 입장은 `ROOM_006`)
6. **CLEAN-02 배치**: 매일 04:00에 만료된 차단 기록을 지운다. 입장 판단은 만료 시각을 직접 비교해 배치가 늦어도 문제없다
7. **로그인**: `anonKey`로 찾은 사용자가 삭제 상태면(식별키가 남은 예전 데이터) 키를 비우고 새로 만든다. 정상 흐름에서는 삭제할 때 키를 비워서 찾히지 않는다
