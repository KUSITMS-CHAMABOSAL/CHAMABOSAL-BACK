## 명세 점검
- 상태 전이
  - 멤버: 연속 지목 0 → 1 → 2 → 3(다음 회차 날짜를 휴식으로 지정) → 휴식이 끝나면 0, 휴식 날짜 비움
  - 결과가 발표될 때(VOTE-04 마감) 한 번 갱신한다. 지목되면 +1, 다른 사람 지목·모두 보살·모두 무사면 0 (3번)
  - 방어(`DEFENDED`)는 발표 뒤에 `PICKED`가 바뀌는 것이라 발표 때 이미 지목으로 +1 된 상태가 맞다 (1번 "방어 성공 포함"). 다른 사람의 방어도 발표 때 다른 사람 지목으로 0이 된다 (Q-23)
- 동시성: 투표 마감은 세 경로(전원 투표, 15:00 배치, 나가기) 모두 방 행 락 안에서 한 번만 일어난다. 연속 지목 갱신도 같은 트랜잭션에서 해서 따로 막을 것이 없다. `RoomMember`는 `@DynamicUpdate`라 다른 요청이 바꾸는 컬럼(본 결과·한 솥 확인)을 덮어쓰지 않는다
- 권한: 새 API 없음
- 외부 연동 실패: 없음
- 제외 범위
  - 이번 달 지목 횟수 화면 표시 (2번, 오늘 탭·내 보살). 지목 횟수는 회차의 지목된 사용자로 셀 수 있어 따로 저장하지 않는다
  - 방어권 사용으로 결과가 `DEFENDED`로 바뀌는 처리 (SHIELD-02)

### 주요 결정
1. **갱신 시점**: `VoteCloseService`가 결과를 발표할 때(`round.announce` 직후) 같은 트랜잭션에서 그 방의 **현재 멤버**만 갱신한다. 나간 멤버는 건드리지 않는다 (Q-35)
2. **휴식 날짜**: 3회 연속이 되면 `발표한 회차 날짜 + 1일`을 휴식 회차 날짜로 둔다 (ERD "다음 회차 날짜 지정"). 다음 회차는 이 회차 투표가 마감돼야 인증이 열리므로, 그 회차의 투표 시작 스냅샷이 항상 이 값을 본다
3. **휴식 끝 처리**: 따로 이벤트를 만들지 않고, 결과를 발표할 때 휴식 날짜가 이번 회차 날짜 이하인 멤버의 휴식을 먼저 정리(연속 0, 휴식 날짜 비움)한 뒤 이번 결과를 반영한다 (5번). 휴식 회차에는 그 멤버를 고를 수 없어서 결과가 어떻든 0에서 다시 시작한다
4. **3회 이상**: 휴식이 끝나기 전에 다시 지목될 길이 없어(휴식 회차에는 후보에서 빠짐) 연속은 3을 넘지 않는다. 3에 닿을 때만 휴식 날짜를 지정한다
