## 설계

### API 계약

### 엔티티
- `votes` (ERD 그대로): `round_id`, `voter_member_id`, `target_member_id`(NULL이면 "오늘은 모두 보살"), `UNIQUE (round_id, voter_member_id)`. 변경 불가라 수정 메서드 없음.
- `Round`: `announce(now, resultType, pickedMember)` 추가. `pickedMember`가 null이 아니면 `pickedUser`도 그 멤버의 `user`로 채운다.

### 주요 결정
- **마감 처리 (`VoteCloseService`, 방 행 락을 잡은 트랜잭션 안에서 부름. VOTE-01의 `VoteStartService`와 같은 구조)**
  1. 회차 상태를 다시 읽고 `VOTING`이 아니면 아무것도 하지 않는다 (동시 마감 방지).
  2. 그 회차의 `Vote` 전체를 읽는다.
  3. **판정 (RESULT-01):** 실제 투표자(= 표를 낸 사람 수)의 절반을 초과해 "오늘은 모두 보살"이면 `ALL_BOSAL`. 아니면 "오늘은 모두 보살"이 아닌 표만 모아 득표를 센다. 최다 득표가 단독이면 `PICKED`, 비어 있거나 동점이면 `ALL_SAFE` (0표·동점·전원 보살 아님이 모두 이 한 분기로 처리된다).
  4. `Round.announce`로 마감 시각·판정 결과를 기록한다.
- **조기 마감 조건 (VOTE-04 1·5·6·7번, Q-36 결정)**
  - "남은 명단 중 투표권 있는 사람"(필수 투표자) = 그 회차 `round_participants.can_vote = true`인 멤버 중, 지금도 현재 멤버(`left_at IS NULL`)이고 `joined_at <= round.vote_started_at`인 사람. 나간 멤버는 빼고(투표하지 않고 나가면 기권), 투표 시작 뒤 나갔다가 다시 들어온 멤버도 뺀다(Q-36: 투표할 수 없으니 기다리지 않음).
  - 필수 투표자 전원이 `Vote`를 냈으면(필수 투표자가 0명이어도 포함) 즉시 마감한다.
  - 나간 멤버가 마감 전에 낸 표는 그대로 집계한다(컬럼 변경 없음, ERD 그대로).
- **세 경로**
  - 나가기: `RoomService.removeMember`에서 방이 남아 있으면, 전원 인증 확인(VOTE-01) 다음에 전원 투표 확인도 같은 락 안에서 한다. 회차는 많아야 하나(`VOTING` 또는 `CERTIFYING` 중 있는 쪽)라 두 확인이 겹치지 않는다.
  - 15:00 배치: `VoteCloseScheduler` (`VoteStartScheduler`와 같은 패턴). `VOTING` 회차를 모두 읽어 `Round.getVoteClosesAt() <= now`인 것만 방 행 락을 잡고 마감한다. 날짜 비교 쿼리 대신 전체를 읽어 자바에서 거르는 쪽을 택했다(방마다 `VOTING` 회차가 많아야 1개라 양이 적음). 회차마다 트랜잭션을 따로 열어 하나가 실패해도 나머지는 계속하고 실패는 로그로 남긴다.
  - 투표 제출(VOTE-03): 이번 PR에는 없다. 다음 PR에서 "표 저장 뒤 같은 락 안에서 조기 마감 확인"을 붙인다 (CERT-01이 `VoteStartService`를 부르는 자리와 같은 자리).
- **시각:** 주입받은 `Clock`.
