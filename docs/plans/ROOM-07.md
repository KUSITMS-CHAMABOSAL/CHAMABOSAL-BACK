# ROOM-07 나가기

## 범위
- 구현 기능: ROOM-07
- 참고 기능: ROOM-01 (방장, 방 행 락), INVITE-03 (6개월 안 재입장), ROOM-08 (내보내기), USER-05 (`DATA_DELETED`로 모든 방 나가기), VOTE-01·VOTE-04 (나간 뒤 투표 시작·마감), CERT-04 (사진 삭제), CLEAN-01 (6개월 뒤 정리)

## 명세 점검
- 상태 전이
  - 멤버: `현재 멤버 → 나감(LEFT)`. `left_at`, `leave_type`을 기록한다. 되돌리기는 INVITE-03.
  - 방장: 방장이 나가면 남은 멤버 중 가장 먼저 들어온 멤버로 바뀐다 (6번).
  - 방: 마지막 멤버가 나가면 `deleted_at`을 기록한다 (7번). 삭제된 방은 되돌리지 않는다.
- 동시성: 같은 방에서 동시에 나가도 위임과 삭제는 한 번만 (12번, ROOM-07-8). `rooms` 행 락 안에서 남은 멤버를 세고 처리한다. 사용자 락은 필요 없다 (나가기는 참여 방 수를 늘리지 않음).
- 권한: 그 방의 현재 멤버만 (`ROOM_002`). 삭제된 방은 `ROOM_005`.
- 외부 연동 실패: 없음
- 제외 범위: 회차·인증·투표·공양미·사진 기능이 없어 아래 시나리오는 해당 기능을 구현할 때 테스트한다. 그래서 구현 후에도 ROOM-07은 `미구현`으로 둔다.
  - ROOM-07-2 기록 보존, ROOM-07-10 사진 유지: CERT-01, CERT-04 (나가기는 기록·사진을 건드리지 않으므로 코드 변경 없음)
  - ROOM-07-3 공양미 유지: RICE-01 (나가기는 공양미를 건드리지 않음)
  - ROOM-07-6 표 유지, ROOM-07-7 나가서 전원 투표: VOTE-02, VOTE-04 (팀원)
  - ROOM-07-9 투표 중 마지막 멤버: VOTE-04, CERT-04 (팀원)
  - ROOM-07-11, ROOM-07-12 나가서 전원 인증: VOTE-01 (팀원)

### 주요 결정
- **처리 순서** (`@Transactional`, 모두 `rooms` 행 락 안)
  1. 방 행 락. 없거나 삭제된 방은 `ROOM_005`.
  2. 내 현재 멤버 행. 없으면 `ROOM_002`.
  3. 내 행에 `left_at = 지금`, `leave_type = LEFT`.
  4. 남은 현재 멤버가 없으면 방 삭제.
  5. 남아 있고 내가 방장이었으면 남은 멤버 중 `joined_at`이 가장 이른 멤버에게 위임.
- **위임 순서가 같을 때:** `joined_at`이 같으면 `id`가 작은 멤버. 명세의 "가장 먼저 들어온 멤버"를 먼저 저장된 행으로 읽는다.
- **다시 들어온 멤버:** INVITE-03이 `joined_at`을 새로 기록하므로 다시 들어온 시각 기준이다 (ERD `joined_at` 설명과 같음).
- **나가기 처리 재사용:** 3~5단계를 `RoomService` 안의 메서드 하나로 둔다. USER-05(`DATA_DELETED`)가 같은 규칙을 쓰므로 나간 유형만 인자로 받는다. ROOM-08은 방장을 내보낼 수 없어 위임·삭제가 없으니 이번에는 맞추지 않는다.
- **투표 연결 지점 (팀원 인계):** 9·10번(나간 뒤 남은 명단 전원 투표면 마감, 전원 인증이면 투표 시작)은 VOTE-01·VOTE-04가 생기면 이 메서드의 3단계 뒤, 같은 방 행 락 안에서 호출해야 한다. 방이 삭제되면(4단계) 호출하지 않는다 (11번). 이번에는 코드에 자리만 주석으로 남긴다.
- **시각:** 주입받은 `Clock`. 테스트는 고정 `Clock`.
