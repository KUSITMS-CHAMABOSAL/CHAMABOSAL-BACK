# CERT-04 인증 사진 삭제 (7일 뒤 삭제 작업)

## 범위
- 구현 기능: CERT-04 (5번, 시나리오 2·3·5), ROOM-07 (9번 시나리오의 사진 부분, 10번)
- 함께 고치는 기능: USER-05 4번 (내 데이터 삭제 시 사진 삭제, 시나리오 USER-05-6)
- 참고 기능: VOTE-01 (`NO_VOTE` 확정), VOTE-04·RESULT-01 (투표 마감), ROOM-07 11번 (방 삭제 시 마감되지 않은 회차), CLEAN-01 (떠난 보살 정리의 사진 삭제, 이미 구현), Q-18
- 앞 작업: `docs/plans/CERT-04.md` (업로드·등록·수정·삭제, PR #113)

## 명세 점검
- 상태 전이: 사진은 `정식` → `삭제(image_deleted_at)`로 한 번만 바뀐다. 삭제 기준 시각은 회차 상태로 정한다.
  - 투표가 마감됐으면(`vote_closed_at` 있음) 마감 시각
  - `NO_VOTE`면 확정 시각. `markNoVote`가 `vote_started_at`에 남긴다 (Q-18)
  - 그 밖에 마감되지 않은 회차이고 방이 삭제됐으면 방 삭제 시각 (ROOM-07 11번)
  - 마감되지 않았고 방도 살아 있으면 삭제하지 않는다. 투표 중이거나 인증 중인 회차다
- 동시성
  - 작업은 하나의 서버에서 `@Scheduled`로만 돈다. 두 번 겹쳐 돌아도 `image_deleted_at is null` 조건으로 표시해서, 같은 사진을 두 번 표시하지 않는다. 저장소 삭제는 없는 키도 성공이라 두 번 지워도 안전하다
  - 대상 회차는 이미 끝났거나 방이 삭제돼 수정·삭제(CERT-02)가 막혀 있다. 그래서 인증 수정과 겹치지 않는다
  - 내 데이터 삭제는 사용자 행 락 안에서 한다. 나간 방이나 삭제된 방의 인증도 내 것이면 함께 지운다
- 권한: 사용자 요청이 아닌 배치 작업이다. 내 데이터 삭제는 로그인한 본인만 한다 (기존)
- 외부 연동 실패
  - S3 삭제는 커밋 뒤에 한다(`deleteAfterCommit`). 실패하면 에러 로그만 남기고 다시 시도하지 않는다. PR #113과 같고, CERT-04 11번이다
  - 기록을 먼저 커밋하므로, 저장소 삭제가 실패해도 응답의 사진 URL은 사라진다
- 제외 범위
  - 떠난 보살 6개월 정리는 CLEAN-01이다. 이미 구현됐다
  - 신고 숨김
  - 저장소 삭제 실패 재시도는 하지 않는다 (CERT-04 11번)
  - 출력의 `삭제 예정 시각`은 화면 자리가 없어 명세에서 뺀다 (사람 결정 2026-11-16)

## 명세 변경
- CERT-04 5번: 삭제 작업은 매시 20분에 돌고, 기준 시각 + 7일이 지난 사진을 지운다. [구현 결정]
  - 예: 11/9 15:00에 기한이 되면 16:20에 지운다
  - 하루 한 번이면 최대 하루 더 남아서, 한 시간 단위로 돌린다
- USER-05 4번: "사진 저장(CERT-04)을 구현할 때 붙인다" 문장을 지운다
- CERT-04 출력에서 `삭제 예정 시각`을 지운다 (사람 결정 2026-11-16)

## 설계

### API 계약
- 새 API 없음
- 삭제한 사진은 기존 응답(투표 후보 `imageUrl`, 수정 응답)에서 `null`이다. `viewUrl`이 `image_deleted_at`을 이미 본다

### 엔티티
- 새 컬럼·테이블 없음. `certifications.image_deleted_at`, `rounds.vote_closed_at`·`vote_started_at`·`status`, `rooms.deleted_at`을 쓴다

### 주요 결정
1. **배치 `CertificationPhotoExpiryScheduler`**: 매시 20분(`0 20 * * * *`, KST)에 돈다. 흐름은 떠난 보살 정리(`LeftMemberCleanupScheduler`)와 같다. 지울 키를 읽고, `markImagesDeleted`로 표시하고, `deleteAfterCommit`으로 지운다. 기존 쿼리를 그대로 쓴다
2. **대상 쿼리** `findExpiredImageKeys(cutoff)`: `cutoff = now - 7일`. 아래 셋 중 하나이고, 사진이 있고 아직 지우지 않은 인증이다
   - `vote_closed_at <= cutoff`
   - `status = NO_VOTE and vote_started_at <= cutoff`
   - `vote_closed_at is null and status <> NO_VOTE and room.deleted_at <= cutoff`
   - `<=`이므로 11/9 15:00 정각에도 지운다 (CERT-04-2: "15:00 이후")
   - 인증이 삭제됐는지는 보지 않는다. 삭제 때 바로 지우지 못한 사진도 함께 정리한다
3. **한 번에 지우는 양**: 방이 많지 않아 페이지로 나누지 않는다. `shortcut:` 주석으로 한계를 남긴다
4. **내 데이터 삭제**: `UserService.deleteData`에서 `detachUser`보다 앞에 둔다. 멤버 행과 사용자 연결을 끊기 전이어야 하기 때문이다
   - 내 모든 멤버 행(예전에 나간 행 포함)의 인증에서 남은 사진 키를 읽는다
   - 읽은 키를 표시하고, 커밋 뒤에 지운다
   - 영속성 컨텍스트를 비우는 쿼리라, 기존 주석대로 사용자 변경 뒤에 둔다
5. **ROOM-07-10**: 나가기는 사진을 건드리지 않는다. 나간 뒤 7일이 지나기 전에 작업이 돌면 사진이 남고, 회차 종료 7일 뒤에 지워지는지 확인한다. 코드 변경은 없다
