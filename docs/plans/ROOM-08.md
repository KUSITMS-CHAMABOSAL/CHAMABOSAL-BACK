# ROOM-08 내보내기

## 범위
- 구현 기능: ROOM-08
- 참고 기능: ROOM-07(나가기 공통 처리 `removeMember`), INVITE-02·03(내보내진 사람 입장 막기, 이미 구현됨), VOTE-01(전원 인증 시 투표 시작), RICE-03(나가기 차감), RESULT-02(떠난 보살 표시)

## 명세 점검
- 상태 전이
  - 대상 멤버: `현재 멤버` → `나감`(`left_at`, `leave_type = KICKED`). 되돌리지 않는다. 같은 방에 다시 들어올 수 없다 (INVITE-02, 이미 구현)
  - 회차: 인증 중에 내보내서 남은 멤버 전원이 인증한 상태면 `인증 중` → `투표 중` (11번)
  - 방장은 내보낼 수 없어서(`ROOM_010`) 방장 위임과 방 삭제는 일어나지 않는다
- 동시성
  - 내보내기, 인증 등록(마지막 인증 → 투표 시작), 03:00 투표 시작 배치가 모두 방 행 락을 잡는다. 내보내기는 방 행 락 안에서 투표 중인 회차를 확인하므로 하나씩 처리된다 (ROOM-08-6, 8번)
    - 투표 시작이 먼저 커밋되면 내보내기는 락을 얻은 뒤 투표 중을 보고 `ROOM_008`
    - 내보내기가 먼저면 대상은 현재 멤버에서 빠져 투표 명단에 들어가지 않는다
  - 같은 대상을 동시에 두 번 내보내면 두 번째는 락 뒤에 현재 멤버가 아니어서 `ROOM_009`
  - 내보내진 사람이 같은 순간 스스로 나가도 방 행 락으로 하나만 처리되고, 뒤 요청은 현재 멤버가 아니어서 실패한다
- 권한: 방장만 (`ROOM_007`). 방 멤버가 아니면 `ROOM_002`
- 외부 연동 실패: 없음
- 금액: 내보내진 멤버의 공양미 차감은 [미정] Q-94. 지금처럼 스스로 나간 경우만 차감한다 (`removeMember`의 `LEFT` 조건 그대로)
- 제외 범위: 내보내기 해제, 신고·차단, 내보낸 사유 표시

## 설계

### API 계약
- `DELETE /api/rooms/{roomId}/members/{memberId}`: 응답 200 데이터 없음
- 확인 순서: `ROOM_005`(없거나 삭제된 방) → `ROOM_002`(내가 멤버 아님) → `ROOM_007`(방장 아님) → `ROOM_010`(대상이 나) → `ROOM_009`(대상이 이 방 현재 멤버 아님) → `ROOM_008`(방에 투표 중인 회차가 있음)
- 새 에러 code: `ROOM_007` (403) 방장만 할 수 있습니다, `ROOM_008` (409) 투표 중에는 내보낼 수 없습니다, `ROOM_009` (404) 이 방에 없는 멤버입니다, `ROOM_010` (400) 방장 본인은 내보낼 수 없습니다. 메시지는 OpenAPI 초안 그대로

### 주요 결정
1. **나가기와 같은 처리**: 방 행 락을 잡은 뒤 `RoomService.removeMember(room, target, KICKED)`를 부른다. 투표 시작 확인(VOTE-01)이 이미 이 안에 있다. 방장은 남아 있어 위임·삭제 분기는 타지 않는다
2. **투표 중 확인 범위**: 회차 날짜와 상관없이 그 방에 `VOTING` 회차가 하나라도 있으면 막는다 (2번, 어제 회차 포함). 03:00이 지났는데 배치가 아직 투표를 열지 않은 `CERTIFYING` 회차(지금 회차 날짜보다 이전)도 투표 시간이라 막는다 (8번, 코드리뷰 반영)
3. **확인 순서**: 권한·대상을 먼저 보고 투표 중을 마지막에 본다. 잘못된 요청은 회차 상태와 상관없이 같은 에러를 받는다
4. **ROOM-08-5 테스트**: 오늘 탭(ROOM-02)이 아직 없어 같은 "현재 멤버만" 확인을 쓰는 인증 캘린더(USER-02)로 `ROOM_002`를 확인한다. ROOM-02를 만들 때 오늘 탭으로 바꾼다
