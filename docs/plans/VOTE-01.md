# VOTE-01 투표 시작

## 범위
- 구현 기능: VOTE-01, CERT-05
- 함께 처리하는 남은 시나리오: CERT-01-9·10 (마지막 인증), ROOM-07-11 (나가서 전원 인증)
- 참고 기능: CERT-01 (인증 등록, 방 행 락), ROOM-07 (나가기, `removeMember`), VOTE-02 (후보), VOTE-04 (마감), RESULT-04 (휴식), CERT-03 (잠금), VOTE-05 (투표 탭의 친구 초대 상태), NOTI-02 (08:00 투표 알림)

## 명세 점검
- 상태 전이 (회차)
  - `CERTIFYING → VOTING`: 명단 3명 이상. `vote_started_at` 기록, 명단 스냅샷 저장.
  - `CERTIFYING → NO_VOTE`: 명단 3명 미만이거나 인증한 멤버가 0명. `vote_started_at`에 확정 시각을 기록하고(ERD, 사진 삭제 기준) 명단은 저장하지 않는다. 다음 회차 인증이 바로 열린다 (CERT-01의 열림 계산이 `NO_VOTE`를 보고 처리, 7번).
  - 시작 경로 세 가지: 마지막 인증(1번), 03:00 배치(2번), 나가기로 전원 인증 상태가 됨(ROOM-07 10번).
- 동시성
  - 같은 회차를 두 경로가 동시에 시작할 수 있다 (VOTE-01-5: 마지막 인증과 03:00 배치, CERT-01-10: 마지막 두 명 동시 인증).
  - 세 경로 모두 방 행 락 안에서 회차 상태를 다시 읽고 `CERTIFYING`일 때만 시작한다. `Round`의 `@Version`은 락이 빠진 경로가 생겼을 때의 안전장치.
- 권한: 사용자 요청이 아니라 다른 기능 안에서 불린다. 따로 확인할 권한 없음.
- 외부 연동 실패: 없음. 투표 시작 때 바로 보내는 알림이 없다 (6번, Q-24).
- 제외 범위
  - 출력의 "친구 초대 상태"(4번): 투표 탭(VOTE-05)이 `3명 미만`으로 보여 준다. 이번에는 회차를 `NO_VOTE`로 바꾸는 것까지.
  - VOTE-01-4 판정 데이터 고정: 투표 중 인증 삭제 거부는 CERT-02(Sprint 3)에서 테스트. 명단 스냅샷 저장은 이번에 한다.
  - VOTE-01-6 다음 날 08:00 알림 대상: NOTI-02(Sprint 5). 이번에는 시작할 때 알림을 보내지 않는 것까지.
  - 휴식 계산(RESULT-04): 휴식 데이터가 아직 없다. 스냅샷은 `room_members.resting_round_date`가 그 회차인지로 채운다.

- ROOM-07 10번 "이전 회차 투표가 열려 있으면 닫는다"와 시나리오 ROOM-07-12를 지웠다. 투표가 마감돼야 다음 회차 인증이 열려서(Q-43 결정, 기능 규칙 문서 회차 상태 표) 이 상황이 생기지 않는다. (사람 확인, 2026-11-13)

## 설계

### API 계약
- 새 API 없음
- `POST /api/rooms/{roomId}/certifications` 응답의 `isVoteStarted`: 이 등록으로 회차가 `VOTING`이 되면 `true`. `NO_VOTE`가 되면 투표가 열리지 않았으므로 `false`.

### 엔티티
- `round_participants` (ERD 그대로): `round_id`, `member_id`, `is_candidate`, `can_vote`, `is_resting`, `UNIQUE (round_id, member_id)`
- `Round`: 상태 전이 메서드 `startVote(now)`, `markNoVote(now)`. 늦어도 닫히는 시각 `getVoteClosesAt()` = 회차 날짜 다음 날 15:00 (저장하지 않고 계산)

### 주요 결정
- **투표 시작 처리 (`VoteStartService`, 방 행 락을 잡은 트랜잭션 안에서 부름)**
  1. 회차 상태를 다시 읽고 `CERTIFYING`이 아니면 아무것도 하지 않는다.
  2. 명단 = 지금 방의 현재 멤버 전원 (그날 들어온 멤버, 휴식 중인 멤버 포함).
  3. 3명 미만이거나 이 회차에 활성 인증이 하나도 없으면 `NO_VOTE`, 끝.
  4. 멤버마다 스냅샷을 만든다.
     - `can_vote` = 이 회차에 활성 인증이 있음
     - `is_resting` = `resting_round_date`가 이 회차 날짜
     - `is_candidate` = 휴식 중이 아니고, "그날 들어와서 인증하지 않음"이 아님
  5. `VOTING`으로 바꾸고 `vote_started_at` 기록.
- **"그날 들어옴"의 기준:** 들어온 시각(`joined_at`)의 회차 날짜(03:00 경계)가 이 회차 날짜와 같은 멤버. 기능 규칙 문서의 "회차 날짜 = 한국 시간 − 3시간"과 같은 기준. (사람 확인, 2026-11-13)
- **전원 인증 확인 (`startIfAllCertified`)**: 방의 `CERTIFYING` 회차(방마다 많아야 1개)를 찾고, 현재 멤버 전원이 그 회차에 활성 인증을 갖고 있으면 시작한다.
  - 인증 등록: `CertificationService.create`의 인증 저장 뒤, 같은 락 안에서 호출. 결과로 `isVoteStarted`를 채운다.
  - 나가기: `RoomService.removeMember`에서 방이 남아 있을 때만 나간 처리 뒤 호출 (방이 삭제되면 부르지 않음, ROOM-07 11번). 내보내기(ROOM-08)와 내 데이터 삭제(USER-05)도 이 메서드를 쓰므로 함께 적용된다.
- **03:00 배치**
  - `@EnableScheduling` 추가. `@Scheduled(cron = "0 0 3 * * *", zone = "Asia/Seoul")`.
  - 대상: `CERTIFYING`이고 회차 날짜가 지금 회차 날짜보다 이른 회차. 서버가 03:00에 꺼져 있었으면 다음 실행에서 처리된다.
  - 회차마다 따로 트랜잭션을 연다: 방 행 락 → 삭제된 방이면 건너뜀(Q-46) → 시작 처리. 한 방이 실패해도 다른 방은 계속하고 실패는 로그로 남긴다.
  - 배치 본문은 서비스 메서드로 두고, 테스트는 고정 시각으로 그 메서드를 직접 부른다.
- **인증한 멤버가 0명인 회차:** 콕만 있었던 날 회차 행이 생긴다. `NO_VOTE`로 확정한다 (명세 변경). 콕(POKE-01)이 아직 없어 테스트는 회차 행을 직접 만든다.
- **CERT-03 (인증 잠금 계산):** 잠금 여부를 쓰는 곳이 CERT-02(수정·삭제)와 오늘 탭이라, 이번에 만들면 쓰는 곳이 없다. CERT-02와 함께 Sprint 3로 미룬다. (사람 확인, 2026-11-13)
- **dev 머지 시점:** 이 PR만 머지되면 투표가 시작된 방은 VOTE-04 전까지 다음 회차 인증이 열리지 않는다. 리뷰까지 끝내 두고 Sprint 2의 마감 PR과 연달아 머지한다.
- **시각:** 주입받은 `Clock`. 테스트는 바꿀 수 있는 `Clock`. `CertificationCreateTest`의 `MutableClock`을 공통 테스트 코드로 옮겨 같이 쓴다.
