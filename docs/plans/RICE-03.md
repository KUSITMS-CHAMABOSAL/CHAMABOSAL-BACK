# RICE-03 방 나가기 차감 (ROOM-08 내보내기 차감 포함)

## 범위
- 구현 기능: RICE-03, ROOM-08
- 참고 기능: ROOM-07 (나가기, 사용자 → 방 락 순서), RICE-01·02 (장부, 표시 잔액), USER-05 2번 (내 데이터 삭제는 차감 안 함), STORE-02·SHIELD-01·NABAL-03 (사용자 행 락 안에서 잔액 사용)
- 기획 답변(2026-11-16): 나가기 확인 화면(8-3)에 사라질 공양미를 정확한 숫자로 보여줌, 방장이 내보낸 멤버도 차감 (Q-94)
- 기존 코드: 스스로 나가기 차감은 `RiceService.deductOnLeave`(팀원, #79)로 구현돼 있음. 이번에는 미리보기 조회와 내보내기 차감을 더함

## 명세 점검
- 상태 전이: 없음. 나가기·내보내기의 멤버 상태 전이는 ROOM-07·08 그대로
- 동시성
  - 차감은 사용자 전체 잔액을 읽고 빼므로 대상 사용자의 행 락 안에서 해야 함 (RICE-03 7번). 스스로 나가기는 이미 사용자 → 방 순서로 잡음
  - 내보내기는 방장이 요청해서 지금은 방 락만 잡음. 내보내지는 사람의 사용자 락을 방 락 뒤에 잡으면, 그 사람이 다른 방을 나가는 요청(사용자 → 방)과 순서가 반대라 교착할 수 있음
  - 그래서 내보내기도 대상 사용자 → 방 순서로 잡음. 대상 멤버의 사용자 ID를 락 없이 먼저 읽고, 그 사용자 행을 잠근 뒤 방을 잠그고, 방 락 뒤에 대상이 아직 현재 멤버인지 다시 확인함 (기존 확인 순서 유지)
  - 방장 본인의 사용자 행은 잔액을 건드리지 않아 잠그지 않음
- 권한
  - 미리보기: 그 방의 현재 멤버 본인만. 삭제된 방 `ROOM_005`, 멤버 아님 `ROOM_002` (나가기와 같은 순서)
  - 내보내기: ROOM-08 그대로 (방장만)
- 외부 연동 실패: 없음
- 제외 범위
  - 내보내지는 사람에게 차감을 알리는 화면·알림 (명세에 없음)
  - 방장 내보내기 확인 화면의 차감 석 표시 (기획 답변은 나가기 확인 화면만)
  - 내 데이터 삭제 차감 (USER-05 2번, 기록을 모두 지움)

## 설계

### API 계약
- `GET /api/rooms/{roomId}/members/me/leave-preview` (RICE-03 6번)
  - 응답: `{ "riceToLose": 200 }` — 지금 나가면 빠질 석. 목표를 채운 방이거나 잔액이 0석 이하면 0
  - 에러: `ROOM_005` (404) → `ROOM_002` (403), `COMMON_008` (401)
- `DELETE /api/rooms/{roomId}/members/{memberId}` (ROOM-08): 계약 그대로, 내보낼 때 차감 추가

### 엔티티

### 주요 결정
- 계산을 하나로: `RiceService`에 차감할 석을 계산만 하는 메서드를 두고, 실제 차감(`deductOnLeave`)과 미리보기가 같이 씀. 그래서 화면 숫자와 실제 차감이 어긋나지 않음
- 미리보기는 조회라 락을 잡지 않음 (`readOnly`). 화면을 본 뒤 다른 적립·사용이 생기면 실제 차감은 나갈 때의 값으로 함
- 차감 대상: `LEFT`, `KICKED`. `DATA_DELETED`는 그대로 제외
- 내보내기 락 순서: 대상 사용자 → 방 (위 동시성)
