# 전시 시연

전시회에서 방문객이 3분 안에 인증 → 투표 → 이마 톡톡 → 나발 → 코스튬 → 목탁을 체험하도록, 시연 방에서만 서버가 시간 조건을 건너뛰게 돕습니다. 실제 규칙(03:00 · 15:00 · 투표 마감 후 5시간)은 바꾸지 않습니다. [전시 시연 기획 컨펌 2026-11-26]

## 공통

- 시연 기능은 시연 설정이 켜져 있을 때만 동작한다. 꺼져 있으면 일반 규칙과 완전히 같다. [구현 결정]
- 시연 번호(1, 2, …)마다 시연 계정(팀원 토스 계정의 userId)과 시연 닉네임을 설정값으로 둔다. 폰 1대 = 시연 번호 1개. 시연폰은 8대다. [기획 컨펌]
- 가짜 팀원은 시연 번호마다 3명(A, B, C)이고, 닉네임은 시연 방 1에서 민서·만재·용선, 시연 방 2에서 예나·예은·윤지다. [팀 결정 2026-11-27] 가짜 팀원은 로그인할 수 없는 시연 전용 사용자다. [기획 컨펌] [구현 결정]
- 보살 색은 시연 계정 노랑, A 분홍, B 보라, C 민트다. [구현 결정]
- 시연 방은 가짜 팀원이 현재 멤버로 있는 방이다. 시연 방 1은 메인 시연, 시연 방 2는 목탁 체험용이다. [기획 컨펌] [구현 결정]
- 방문객별 기록은 저장하지 않는다. [기획 컨펌]

| 가짜 팀원 | 인증 | 한 줄 기록 | 쓴 금액 |
|---|---|---|---|
| A 민서 (방 2 예나) | 참았어요 | 편의점 앞에서 고민하다가 그냥 집에 왔어요 | - |
| B 만재 (방 2 예은) | 못 참았어요 | 추워서 퇴근길에 붕어빵이랑 어묵 사 먹었어요 | 6,000원 |
| C 용선 (방 2 윤지) | 못 참았어요 | 세일 문자 보고 결국 못 참고 질러버렸어요 | 49,210원 |

## DEMO-01 시연 리셋

상태: 구현됨

### 기능 설명
시연 번호 하나의 시연 계정을 방문객 맞이 전 상태로 되돌리고 시연 방 2개를 새로 만듭니다. 팀원이 방문객마다 Swagger에서 실행합니다. [기획 컨펌]

### 입력
- 시연 번호
- 시연 키 (헤더)

### 처리 규칙
1. 시연 설정이 꺼져 있으면 없는 API처럼 거부한다. [구현 결정]
2. 시연 키가 틀리면 거부한다. JWT 로그인은 필요 없다. [구현 결정]
3. 설정에 없는 시연 번호이거나 설정된 시연 계정이 없으면(삭제 포함) 거부한다. [구현 결정]
4. 시연 계정이 시연 방이 아닌 방에 참여 중이면 아무것도 바꾸지 않고 거부한다. 리셋은 가짜 팀원이 한 번이라도 들어왔던 방을 시연 방으로 본다. 방문객이 가짜 팀원을 모두 내보내도 리셋할 수 있어야 하기 때문이다. [구현 결정]
5. 시연 계정이 참여 중인 시연 방을 모두 삭제한다. [방 닫기](ROOM-09)처럼 멤버 전원을 `ROOM_CLOSED`로 나간 것으로 처리하고, 그 방에 있었던 멤버의 사진·한 줄 기록·쓴 금액을 바로 지운다. 나가기 차감은 하지 않는다. [기획 컨펌] [구현 결정]
6. 시연 계정의 공양미 장부를 지우고 `DEMO_RESET` +200석 한 줄을 남겨 200석으로 맞춘다. [기획 컨펌] [구현 결정]
7. 시연 계정의 빠진 나발, 꾸미기 아이템(보유·착용), 이마 방어권을 모두 지운다. [기획 컨펌] 방어권은 방문객이 사면 다음 방문객에게 남아서 함께 지운다. [구현 결정 2026-11-26]
8. 가짜 팀원이 없으면 만들고, 있으면 다시 쓴다. [구현 결정]
9. 시연 방 1은 이름 "자율 절약 방"(목표 `ETC`), 시연 방 2는 이름 "배달 끊기 방"(목표 `DELIVERY`)이다. [기획 컨펌] 두 방 모두 한 솥 목표 300석, 함께할 인원 4명이다. 멤버는 시연 계정(방장, 시연 닉네임)과 가짜 팀원 3명이다. [기획 컨펌] 방 목록에서 시연 방 1이 시연 방 2보다 먼저 보인다. [팀 결정 2026-11-27]
10. 시연 방 1: 지금 회차가 `인증 중`이고 가짜 팀원 3명이 표의 내용으로 인증해 있다. 시연 계정은 인증하지 않은 상태다. [기획 컨펌]
11. 시연 방 2: 지난 회차에서 시연 계정이 지목됐고(`PICKED`) 톡톡 마감 시각이 지나 받은 톡톡이 전달된 상태다. 받은 톡톡은 가짜 팀원 3명이 합계 10회(A 3, B 3, C 4)다. [기획 컨펌] 시연 계정은 지난 회차에 참았어요("오늘도 잘 참았어요")로 인증했고 C에게 투표했으며, 가짜 팀원 3명은 시연 계정에게 투표했다. [구현 결정] 결과는 이미 본 것으로 두고 목탁 수행은 하지 않은 상태다. 지금 회차는 `인증 중`이다. [기획 컨펌] [구현 결정]
12. 다른 시연 번호의 계정·방은 바꾸지 않는다. [구현 결정]
13. 같은 시연 번호를 동시에 리셋하면 하나씩 처리한다. [구현 결정]

### 출력
- 시연 방 1 ID, 시연 방 2 ID

### 예외
- `COMMON_001` (404): 시연 설정 꺼짐
- `COMMON_008` (401): 시연 키 틀림
- `DEMO_001` (404): 설정에 없는 시연 번호, 시연 계정 없음
- `DEMO_002` (409): 시연 계정이 일반 방에 참여 중

### 제외 범위
- 방문객별 기록·통계 (코스튬 인기는 종이 집계)
- 시연 계정 연결 화면. 시연 번호와 userId는 설정값으로 넣는다

### 완료 조건

**DEMO-01-1 시연 설정 꺼짐**
- Given 시연 설정이 꺼져 있다
- When 리셋을 요청하면
- Then 없는 API로 거부한다

**DEMO-01-2 시연 키 틀림**
- When 틀린 시연 키로 리셋을 요청하면
- Then `COMMON_008`로 거부한다

**DEMO-01-3 없는 시연 번호**
- When 설정에 없는 시연 번호나 시연 계정이 없는 시연 번호로 리셋을 요청하면
- Then `DEMO_001`로 거부한다

**DEMO-01-4 첫 리셋**
- Given 시연 계정이 참여 중인 방이 없다
- When 리셋하면
- Then 가짜 팀원 3명이 생기고 시연 방 1·2가 만들어진다
- And 시연 방 1은 "자율 절약 방", 시연 방 2는 "배달 끊기 방"이다
- And 시연 계정의 방 목록은 시연 방 1, 시연 방 2 순서다
- And 시연 방 1은 `인증 중`이고 가짜 팀원 3명만 표의 내용으로 인증해 있다
- And 시연 계정의 공양미는 200석이다

**DEMO-01-5 시연 방 2 목탁 준비**
- Given 리셋했다
- When 시연 계정이 시연 방 2 지난 회차의 받은 톡톡을 조회하면
- Then 전달된 상태로 합계 10회이고 목탁 수행을 끝내지 않았다

**DEMO-01-6 다시 리셋**
- Given 방문객이 인증·투표·톡톡·나발 심기·코스튬 구매·방어권 구매를 했다
- When 같은 시연 번호로 리셋하면
- Then 이전 시연 방 2개는 삭제되고 새 시연 방 2개가 만들어진다
- And 이전 시연 방의 한 줄 기록과 쓴 금액은 지워진다
- And 가짜 팀원은 새로 만들지 않고 다시 쓴다
- And 시연 계정의 공양미는 200석, 빠진 나발과 꾸미기 아이템, 이마 방어권은 없다

**DEMO-01-7 일반 방 참여 중**
- Given 시연 계정이 일반 방에 참여 중이다
- When 리셋하면
- Then `DEMO_002`로 거부하고 아무것도 바뀌지 않는다

**DEMO-01-8 다른 시연 번호는 그대로**
- Given 시연 번호 1, 2를 모두 리셋했다
- When 시연 번호 1을 다시 리셋하면
- Then 시연 번호 2의 방과 공양미는 그대로다

**DEMO-01-9 동시 리셋**
- When 같은 시연 번호로 리셋을 동시에 두 번 요청하면
- Then 둘 다 성공하고 시연 계정이 참여 중인 방은 2개, 가짜 팀원은 3명이다

**DEMO-01-10 가짜 팀원을 모두 내보낸 시연 방**
- Given 방문객이 시연 방 1에서 가짜 팀원 3명을 모두 내보냈다
- When 같은 시연 번호로 리셋하면
- Then 거부하지 않고 시연 방 2개를 새로 만든다

## DEMO-02 가짜 팀원 자동 투표

상태: 구현됨

### 기능 설명
시연 방에서 투표가 시작되면 가짜 팀원의 표를 넣어, 방문객이 투표하는 순간 전원 투표로 마감되고 C가 지목되게 합니다. [기획 컨펌]

### 입력
- 투표가 시작된 회차

### 처리 규칙
1. 시연 설정이 켜져 있고 시연 방일 때만 동작한다. [구현 결정]
2. 투표가 시작된 트랜잭션 안에서 A → C, B → C, C → 모두 보살로 표를 넣는다. [기획 컨펌] [구현 결정]
3. 방문객이 누구에게 투표해도 C가 2표로 최다라 C가 지목된다. [구현 결정]
4. 방문객이 투표하면 기존 규칙(VOTE-04)대로 전원 투표로 바로 마감·발표한다. [기획 컨펌]
5. 가짜 팀원 표에는 투표 보상을 주지 않는다. [구현 결정]
6. 시연 계정에게 투표권이 있을 때만(방문객이 인증해 투표가 시작됐을 때만) 표를 넣는다. 리셋하지 않고 둔 방이 03:00에 투표를 시작하면 가짜 팀원 표만으로 전원 투표가 돼도 마감되지 않고 15:00까지 남기 때문이다. [구현 결정]

### 출력
- 가짜 팀원 3명의 표

### 예외
- 없음

### 제외 범위
- 리액션 단계 (시연 시나리오에서 뺌) [기획 컨펌]

### 완료 조건

**DEMO-02-1 방문객 인증으로 투표 시작**
- Given 리셋한 시연 방 1
- When 시연 계정이 인증하면
- Then 투표가 시작되고 가짜 팀원 3명의 표가 들어가 있다
- And 가짜 팀원은 투표 보상을 받지 않는다

**DEMO-02-2 방문객 투표로 C 지목**
- Given DEMO-02-1 뒤
- When 시연 계정이 A에게 투표하면
- Then 투표가 바로 마감되고 C가 지목된다

**DEMO-02-3 일반 방은 자동 투표 없음**
- Given 시연 설정이 켜져 있고 일반 방에서 전원 인증했다
- When 투표가 시작되면
- Then 자동으로 들어간 표가 없다

**DEMO-02-4 방문객이 인증하지 않은 채 03:00이 되면 자동 투표 없음**
- Given 리셋한 시연 방 1에서 시연 계정이 인증하지 않았다
- When 다음 날 03:00에 투표가 시작되면
- Then 자동으로 들어간 표가 없다

## DEMO-03 톡톡 뒤 나발 빠짐

상태: 구현됨

### 기능 설명
시연 방에서 시연 계정이 이마 톡톡을 끝내면 나발을 1개 빼서, 홈 탭에서 바로 나발 빠짐 화면을 보여 주게 합니다. [기획 컨펌]

### 입력
- 톡톡 보내기 (RESULT-03)

### 처리 규칙
1. 시연 설정이 켜져 있고 시연 방에서 시연 계정이 톡톡을 보낼 때만 동작한다. [구현 결정]
2. 톡톡 보내기가 성공하면 건너뛰기(0회)여도 시연 계정의 나발을 1개 뺀다. 번호는 NABAL-01과 같이 남은 나발 중 랜덤이다. [기획 컨펌] [구현 결정]
3. 빠진 나발은 NABAL-02의 안 본 빠진 나발로 내 정보에 나온다. [기획 컨펌]

### 출력
- 빠진 나발 기록 (시연 방 1, 그 회차 날짜)

### 예외
- 없음

### 제외 범위
- 홈 탭 진입 때 나발 빠짐 화면 표시 (프론트)

### 완료 조건

**DEMO-03-1 톡톡 뒤 나발 빠짐**
- Given 시연 방 1에서 C가 지목됐다
- When 시연 계정이 톡톡을 5번 보내면
- Then 시연 계정의 나발이 1개 빠지고 안 본 빠진 나발에 있다

**DEMO-03-2 건너뛰기여도 빠짐**
- When 시연 계정이 톡톡을 0번 보내면
- Then 시연 계정의 나발이 1개 빠진다

**DEMO-03-3 일반 방은 안 빠짐**
- Given 시연 설정이 켜져 있다
- When 일반 방에서 톡톡을 보내면
- Then 나발은 그대로다
