# 회차 · 인증

방마다 하루 한 번 "오늘 참았는지"를 인증합니다. 회차 날짜와 회차 상태는 [`common.md`](common.md)를 따릅니다.

## CERT-01 인증 등록

상태: 미구현

### 기능 설명
사용자는 방마다 회차당 한 번 소비 절약 결과를 인증합니다. [WF 13·14·15]

### 입력
- 방 ID
- 결과: `ENDURED`(참았어요) 또는 `FAILED`(못 참았어요)
- 한 줄 기록
- 못 참았을 때 쓴 금액
- 사진 (선택)

### 처리 규칙
1. 활성 멤버만 인증할 수 있다. [정책서]
2. 사용자는 방마다 회차당 활성 인증을 하나만 가진다. [정책서]
3. 한 줄 기록은 필수이며 1~40자다. 띄어쓰기와 이모지를 포함할 수 있다. [WF 13] 글자 수를 세는 기준은 [미정] Q-29
4. `못 참았어요`이면 1~999,999원 금액이 필수다. [정책서]
5. 금액은 숫자로 저장한다. 천 단위 콤마는 화면에서 표시한다. [정책서]
6. 사진은 선택이며 1장이다. [WF 13]
7. 인증 회차는 서버가 등록 요청을 받은 시각으로 정한다. 회차 경계는 03:00이다. 03:00 전 등록은 전날 회차, 03:00 이후 등록은 그날 회차다. 03:00를 넘겨 등록하면 지난 회차는 인증 안 함으로 남는다. [정책서] [WF 13]
8. 그날 회차 인증은 이전 회차 투표가 마감되면 열린다. 이전 회차 투표가 없으면(처음 만든 방, 투표 명단 3명 미만인 회차) 바로 열린다. 열리기 전에 등록하면 거부한다. [정책서] [Q-82]
9. 등록이 마지막 인증이면 인증 저장과 투표 시작(VOTE-01)을 한 번의 일관된 처리로 수행한다. [정책서]
10. 투표가 열리지 않은 회차(`NO_VOTE`)도 그 회차에서 인증을 삭제한 멤버는 회차가 끝날 때(다음 날 03:00)까지 다시 인증할 수 있다. 그 외 멤버는 `NO_VOTE` 회차에 등록할 수 없다. (CERT-02 6번) [정책서] [Q-32]

### 출력
- 인증 ID
- 등록된 회차 날짜
- 등록 시각과 수정 가능 종료 시각
- 개인·한 솥 공양미 적립 결과
- 이 등록으로 투표가 시작됐는지 (인증 완료 화면의 "모두가 인증해서 투표가 열렸어요") [구현 결정]

### 예외
- `CERT_001` (409): 이미 인증함. 중복 인증 거부
- `CERT_006` (409): 아직 인증 시간이 아님. 이전 회차 투표가 끝나지 않았다
- `ROOM_002` (403): 이 방 멤버가 아님
- `ROOM_005` (404): 없거나 삭제된 방
- `COMMON_002` (400): 입력값 오류 (한 줄 기록 길이, 금액 범위, 금액 누락, 없거나 만료된 사진 키)
- `COMMON_008` (401): 인증 필요
- 사진 업로드 실패: 사진 없이 인증할 수 있다

### 제외 범위
- 마지막 인증 전 확인 화면 (화면에서 처리)
- 인증 수정·삭제 (CERT-02)
- 사진 저장·삭제 (CERT-04)
- 투표 시작 처리 (VOTE-01)
- 공양미 적립 계산 (RICE-01)

### 완료 조건

공통 Given: 방 인원은 A, B, C, D 4명이다.

**CERT-01-1 참았어요 인증**
- Given A가 오늘 회차에 인증하지 않았다
- When A가 `참았어요`와 한 줄 기록으로 인증하면
- Then 인증이 저장되고 수정 가능 종료 시각은 등록 10분 뒤다

**CERT-01-2 못 참았어요는 금액 필수**
- Given A가 오늘 회차에 인증하지 않았다
- When A가 `못 참았어요`를 금액 없이 보내면
- Then 거부한다

**CERT-01-3 금액 범위**
- Given A가 오늘 회차에 인증하지 않았다
- When A가 `못 참았어요`와 1,000,000원을 보내면
- Then 거부한다

**CERT-01-4 한 줄 기록 길이**
- Given A가 오늘 회차에 인증하지 않았다
- When 한 줄 기록이 비어 있거나 41자이면
- Then 거부한다

**CERT-01-5 중복 인증**
- Given A가 오늘 회차에 이미 인증했다
- When A가 다시 인증하면
- Then 거부하고 공양미를 추가로 지급하지 않는다

**CERT-01-6 활성 멤버가 아님**
- Given E는 이 방 멤버가 아니다
- When E가 인증하면
- Then 거부한다

**CERT-01-7 사진 없이 인증**
- Given A가 오늘 회차에 인증하지 않았다
- When A가 사진 없이 인증하면
- Then 인증이 저장된다

**CERT-01-8 03:00를 넘긴 등록**
- Given A가 12/1 02:59에 인증 화면을 열었다
- When 서버가 12/1 03:00:01에 등록 요청을 받으면
- Then `CERT_006`으로 거부한다
- And 11/30 회차에서 A는 인증 안 함이다

**CERT-01-11 03:00 전 등록은 전날 회차**
- Given A가 11/30 회차에 인증하지 않았다
- When 서버가 12/1 02:59에 등록 요청을 받으면
- Then 11/30 회차 인증으로 등록한다

**CERT-01-12 이전 회차 투표가 끝난 뒤 인증**
- Given 11/30 회차 투표가 12/1 15:00에 자동 마감됐다
- When 서버가 12/1 15:00:01에 A의 등록 요청을 받으면
- Then 12/1 회차 인증으로 등록하고 응답에 12/1을 담는다

**CERT-01-13 이전 회차 투표가 일찍 끝나면 일찍 인증**
- Given 11/30 회차 투표가 12/1 10:00에 전원 투표로 마감됐다
- When 서버가 12/1 10:05에 A의 등록 요청을 받으면
- Then 12/1 회차 인증으로 등록한다

**CERT-01-14 이전 회차 투표가 없으면 바로 인증**
- Given 2명 방이라 11/30 회차가 12/1 03:00에 투표 없음으로 확정됐다
- When 서버가 12/1 03:10에 A의 등록 요청을 받으면
- Then 12/1 회차 인증으로 등록한다

**CERT-01-15 처음 만든 방은 바로 인증**
- Given A가 12/1 10:00에 방을 만들었다
- When 서버가 12/1 10:05에 A의 등록 요청을 받으면
- Then 12/1 회차 인증으로 등록한다

**CERT-01-9 마지막 인증**
- Given A, B, C가 인증했다
- When D가 인증하면
- Then D의 인증이 저장되고 투표가 시작된다

**CERT-01-10 마지막 두 명이 동시에 인증**
- Given A, B가 인증했다
- When C와 D가 동시에 인증하면
- Then 두 인증이 모두 저장되고 투표는 한 번만 시작된다

**CERT-01-16 투표 없음 회차에서 삭제 후 다시 인증**
- Given 방 인원 2명(A, B)이 20:00에 모두 인증해 회차가 `투표 없음`이 됐고, A가 20:05에 인증을 삭제했다
- When A가 같은 날 21:00에 다시 인증하면
- Then 같은 회차에 새 인증이 저장된다

## CERT-02 인증 수정·삭제

상태: 미구현

### 기능 설명
인증 등록 후 10분 동안 수정·삭제할 수 있습니다. [WF 50·53]

### 입력
- 인증 ID
- 수정 내용 또는 삭제 요청

### 처리 규칙
1. 작성자 본인만 수정·삭제할 수 있다. [정책서]
2. 등록 후 10분 이내여야 한다. [정책서]
3. 10분 이내여도 투표가 시작되면 잠근다. (CERT-03) [정책서]
4. 수정으로 인증 보상을 다시 지급하지 않는다. [정책서]
5. 삭제하면 그 인증으로 지급된 개인 공양미와 진행 중인 솥 적립을 장부 기록만큼 회수한다. (RICE-02) [정책서]
6. 삭제 후 같은 회차에 다시 인증할 수 있고 보상도 다시 받는다. [정책서]
7. 잠금 사유는 `수정 시간 지남`과 `투표 시작`을 구분해서 돌려준다. [WF 53]
8. 수정은 등록과 같은 값을 모두 받아 통째로 바꾼다. 입력값 기준은 CERT-01과 같다. `참았어요`로 바꾸면 저장된 금액을 지운다. [구현 결정]
9. 수정할 때 사진은 새 사진으로 바꾸기, 기존 사진 유지, 사진 지우기 중 하나를 고른다. 바꾸거나 지운 기존 사진은 바로 삭제한다. (CERT-04) [구현 결정]
10. 수정할 때 기존 사진 유지 여부는 필수다. 빠지면 `COMMON_002`를 돌려주고 인증을 바꾸지 않는다. 새 사진과 기존 사진 유지를 함께 보내도 `COMMON_002`다. [구현 결정]
11. 수정은 요청 형식(`COMMON_002`) → 없거나 삭제된 인증(`CERT_002`) → 본인 인증 아님(`CERT_003`) → 수정 시간 지남(`CERT_004`) → 투표 시작(`CERT_005`) → 사진 키 확인(`COMMON_002`) 순서로 확인한다. [구현 결정]
12. 삭제는 없는 인증(`CERT_002`) → 본인 인증 아님(`CERT_003`) → 이미 삭제됨(성공) → 수정 시간 지남(`CERT_004`) → 투표 시작(`CERT_005`) 순서로 확인한다. 그래서 잠긴 뒤의 삭제 재시도도 성공이다. [구현 결정]

### 출력
- 수정된 인증 또는 삭제 상태
- 수정 가능 종료 시각
- 회수 결과

### 예외
- `CERT_002` (404): 없거나 삭제된 인증 (수정)
- `CERT_003` (403): 본인 인증이 아님
- `CERT_004` (409): 10분 경과. `수정 시간이 지나서 인증을 바꿀 수 없어요` [WF 53]
- `CERT_005` (409): 투표 시작. `투표가 시작돼서 인증을 바꿀 수 없어요` [WF 53]
- `COMMON_002` (400): 수정 내용의 입력값 오류 (CERT-01과 같은 기준)
- `COMMON_008` (401): 인증 필요
- 이미 삭제한 본인 인증을 다시 삭제하면 성공으로 돌려주고 회수를 반복하지 않는다 [구현 결정]

### 제외 범위
- 잠금 이후 추가 소비 덧붙이기 (제공하지 않음, CERT-03)
- 회수 금액 계산 (RICE-02)

### 완료 조건

**CERT-02-1 10분 안 수정**
- Given A가 5분 전에 인증했다
- When A가 한 줄 기록을 고치면
- Then 수정되고 공양미는 추가로 지급하지 않는다

**CERT-02-2 10분 경과**
- Given A가 11분 전에 인증했다
- When A가 수정하면
- Then `수정 시간 지남` 사유로 거부한다

**CERT-02-3 투표 시작 후**
- Given A가 3분 전에 인증했고 투표가 시작됐다
- When A가 수정하면
- Then `투표 시작` 사유로 거부한다

**CERT-02-4 본인 인증이 아님**
- Given A가 3분 전에 인증했다
- When B가 A의 인증을 수정하거나 삭제하면
- Then 거부한다

**CERT-02-5 삭제하면 회수**
- Given 방 인원 3명이고 A의 인증으로 A +10석, 솥 +10석이 적립됐다
- When A가 인증을 삭제하면
- Then A -10석, 솥 -10석이 회수된다

**CERT-02-6 삭제 후 다시 인증**
- Given A가 인증을 삭제했다
- When A가 같은 회차에 다시 인증하면
- Then 인증이 저장되고 보상을 다시 지급한다

**CERT-02-7 같은 삭제 요청 반복**
- Given A가 인증을 삭제했다
- When 같은 삭제 요청이 다시 오면
- Then 회수는 한 번만 기록된다

**CERT-02-8 수정과 투표 시작이 동시에**
- Given A가 3분 전에 인증했다
- When A의 수정과 투표 시작이 동시에 실행되면
- Then 투표 판정에 쓰는 A의 인증과 저장된 A의 인증이 같다

**CERT-02-9 참았어요로 바꾸면 금액 지움**
- Given A가 3분 전에 `못 참았어요`와 23,000원으로 인증했다
- When A가 `참았어요`로 수정하면
- Then 결과는 `참았어요`이고 저장된 금액은 없다

**CERT-02-10 수정하며 사진 지우기**
- Given A가 3분 전에 사진과 함께 인증했다
- When A가 사진을 유지하지 않고 새 사진 없이 수정하면
- Then 인증에 사진이 없고 기존 사진은 바로 삭제된다

**CERT-02-11 수정하며 사진 유지**
- Given A가 3분 전에 사진과 함께 인증했다
- When A가 사진을 유지하고 한 줄 기록만 바꿔 수정하면
- Then 사진은 그대로다

**CERT-02-12 사진 유지 여부 누락**
- Given A가 3분 전에 사진과 함께 인증했다
- When A가 사진 유지 여부를 보내지 않고 수정하면
- Then `COMMON_002`를 돌려주고 인증과 사진은 그대로다

**CERT-02-13 잠금 사유가 둘**
- Given A가 11분 전에 인증했고 투표도 시작됐다
- When A가 수정하면
- Then `CERT_004`를 돌려준다

**CERT-02-14 잠긴 뒤 삭제 재시도**
- Given A가 인증을 삭제했고 그 뒤 10분이 지났다
- When 같은 삭제 요청이 다시 오면
- Then 성공하고 회수는 추가로 기록하지 않는다

## CERT-03 인증 잠금

상태: 미구현

### 기능 설명
투표가 시작되는 순간 해당 회차의 모든 인증을 변경 불가 상태로 만듭니다.

### 입력
- 회차 상태 전이

### 처리 규칙
1. 전원 인증 또는 다음 날 03:00에 투표가 시작되면 그 회차 인증을 잠근다. [정책서]
2. 잠금 여부는 저장하지 않고 `등록 후 10분 경과` 또는 `회차가 투표 중이거나 발표됨`으로 계산한다. [구현 결정] 투표가 열리지 않은 회차(`NO_VOTE`)는 투표 시작이 없으므로 등록 후 10분까지 수정·삭제할 수 있다. [Q-32]
3. 잠금 후 추가 소비를 덧붙이는 기능은 제공하지 않는다. [정책서]
4. 마지막 인증자는 등록과 함께 투표가 시작되므로 수정 시간이 없다. [정책서]

### 출력
- 인증별 잠금 여부와 잠금 사유

### 예외
- 없음

### 제외 범위
- 투표 시작 조건 판단 (VOTE-01)

### 완료 조건

**CERT-03-1 투표 시작 시 잠금**
- Given A가 3분 전에 인증했다
- When 전원 인증으로 투표가 시작되면
- Then A의 인증은 잠기고 사유는 `투표 시작`이다

**CERT-03-2 마지막 인증자는 바로 잠김**
- Given A, B, C가 인증했다
- When D가 인증하면
- Then D의 인증은 등록 즉시 잠긴다

**CERT-03-3 03:00 시작 시 잠금**
- Given A가 02:55에 인증했고 전원 인증이 아니다
- When 03:00이 되어 투표가 시작되면
- Then A의 인증은 등록 10분이 지나지 않았어도 잠긴다

## CERT-04 인증 사진

상태: 미구현

### 기능 설명
선택한 인증 사진을 비공개로 저장하고 정해진 시점에 삭제합니다.

### 입력
- 업로드할 사진
- 인증 ID

### 처리 규칙
1. 사진 없이도 인증할 수 있다. [정책서]
2. 사진은 암호화된 비공개 저장소에 둔다. [정책서]
3. 업로드 URL은 임시 경로로 발급하고, 인증을 등록할 때 정식 경로로 옮긴다. [구현 결정]
4. 사진 조회 URL은 응답할 때마다 만료되는 URL로 만든다. [구현 결정]
5. 해당 회차 투표가 끝난 시점부터 7일 뒤 삭제한다. [정책서] 투표가 없는 회차(`NO_VOTE`)는 `투표 없음`으로 확정된 시각부터 7일 뒤 삭제한다. [Q-18] 방이 삭제돼 마감되지 않은 회차는 방 삭제 시각부터 7일 뒤 삭제한다. (ROOM-07 11번) 나간 멤버의 사진도 같은 기준을 따른다.
6. 본인 인증 삭제, 내 데이터 삭제 시 즉시 삭제한다. [정책서] [Q-49] 방을 나가거나 내보내져도 바로 지우지 않고 5번 규칙을 따른다. (ROOM-07, ROOM-08) [Q-48]
7. 인증에 쓰이지 않은 업로드 사진은 업로드 1일 뒤 저장소 규칙으로 삭제한다. [구현 결정]
8. 허용 파일 형식·크기·리사이징 정책은 [미정] Q-30

### 출력
- 사진 조회 URL
- 삭제 예정 시각

### 예외
- `COMMON_002` (400): 허용하지 않는 파일 형식 (업로드 URL 발급, 기준은 [미정] Q-30)
- `COMMON_008` (401): 인증 필요
- 업로드 실패가 인증 등록을 실패시키지 않는다
- 삭제 작업은 다시 실행해도 안전하다

### 제외 범위
- 신고로 인한 사진 숨김 (범위 제외)

### 완료 조건

**CERT-04-1 비공개 저장**
- Given A가 사진과 함께 인증했다
- When 저장 경로로 직접 접근하면
- Then 사진을 볼 수 없다

**CERT-04-2 7일 뒤 삭제**
- Given 사진이 있는 회차의 투표가 11/2 15:00에 끝났다
- When 11/9 15:00 이후 삭제 작업이 실행되면
- Then 사진이 삭제되고 이후 조회되지 않는다

**CERT-04-3 7일 전에는 유지**
- Given 사진이 있는 회차의 투표가 11/2 15:00에 끝났다
- When 11/9 14:59에 삭제 작업이 실행되면
- Then 사진은 남아 있다

**CERT-04-4 인증 삭제 시 즉시 삭제**
- Given A가 사진과 함께 인증했다
- When A가 인증을 삭제하면
- Then 사진도 바로 삭제된다

**CERT-04-5 삭제 작업 재실행**
- Given 삭제 대상 사진이 이미 삭제됐다
- When 삭제 작업이 다시 실행되면
- Then 오류 없이 끝난다

## CERT-05 미인증 처리

상태: 구현됨

### 기능 설명
투표 시작까지 인증하지 않은 멤버를 투표 후보에 반영하고 투표권을 주지 않습니다.

### 입력
- 투표 시작 시점의 방 멤버와 인증 상태

### 처리 규칙
1. 투표 시작 시점의 기존 멤버가 미인증이면 `인증 안 함` 후보로 포함한다. [정책서]
2. 그날 들어와서 인증하지 않은 멤버는 이번 회차 후보에서 제외한다. [정책서]
3. 휴식 중인 미인증 멤버는 `인증 안 함`으로 표시하지만 선택할 수 없다. (VOTE-02) [정책서]
4. `못 참았어요`로 인증한 멤버가 미인증 멤버보다 규칙상 불리하지 않아야 한다. [정책서]
5. 미인증 멤버는 그 회차 투표권이 없고 투표 보상도 없다. (VOTE-03) [11/8 회의]

### 출력
- 투표 후보용 인증 상태 스냅샷

### 예외
- 없음

### 제외 범위
- 콕 찌르기 (POKE-01)
- 인증 마감 알림 (NOTI-02)

### 완료 조건

**CERT-05-1 기존 멤버 미인증은 후보**
- Given 기존 멤버 B가 인증하지 않았다
- When 03:00에 투표가 시작되면
- Then B는 `인증 안 함`으로 선택할 수 있는 후보다

**CERT-05-2 오늘 들어온 미인증 멤버는 제외**
- Given D가 오늘 들어왔고 인증하지 않았다
- When 03:00에 투표가 시작되면
- Then D는 후보에 없고 투표권도 없다

**CERT-05-3 휴식 중 미인증 멤버**
- Given C가 휴식 중이고 인증하지 않았다
- When 03:00에 투표가 시작되면
- Then C는 `인증 안 함`으로 표시되고 선택할 수 없다

**CERT-05-4 미인증 멤버는 투표권 없음**
- Given 기존 멤버 B가 인증하지 않았다
- When 03:00에 투표가 시작되면
- Then B는 후보지만 투표할 수 없다
