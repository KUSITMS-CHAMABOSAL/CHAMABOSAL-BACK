# 사용자

내 정보, 이번 달 기록, 알림 설정, 내 데이터 삭제, 토스 알림 동의를 다룹니다. 공양미·방어권·꾸미기는 사용자 단위이고 닉네임·색상은 방 단위입니다. 로그인은 [`auth.md`](auth.md)를 따릅니다. 마지막으로 본 방은 기기에 저장하므로 서버 기능이 없고 USER-04는 비워 둡니다. (Q-39)

## USER-01 내 정보

상태: 미구현

### 기능 설명
앱을 열 때 어느 화면으로 갈지 판단할 값을 돌려줍니다.

### 입력
- 로그인한 사용자

### 처리 규칙
1. 방 목록에는 현재 멤버인 방만 넣고 삭제된 방은 뺀다. [PRD]
2. 참여 중인 방이 없으면 방 목록을 비워서 돌려준다. [WF 01]
3. 방마다 안 본 결과나 한 솥 축하가 있는지 돌려준다. 기준은 RESULT-02, POT-01을 따른다. [WF 48]
4. 참여 중인 방이 2개면 새 방을 만들 수 없다고 돌려준다. [PRD]
5. 착용 아이템 목록을 돌려준다. 착용은 사용자 단위라 방마다 나누지 않는다. (STORE-03) [PRD]
6. 사용자 ID는 응답에 내보내지 않는다. [구현 결정]

### 출력
- 콕 알림 설정, 인증·투표 알림 설정
- `CERT_REMINDER` 동의 여부
- 착용 아이템 목록
- 방 목록: 방 ID, 이름, 닉네임, 색상, 안 본 항목 여부
- 새 방을 만들 수 있는지

### 예외
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 받은 톡톡, 결과, 축하의 재생 순서 (ROOM-02)
- 마지막으로 본 방 저장과 선택 (클라이언트)
- 알림으로 들어올 때의 이동

### 완료 조건

**USER-01-1 참여 중인 방이 없음**
- Given A가 어떤 방에도 없다
- When 내 정보를 조회하면
- Then 방 목록은 비어 있고 새 방을 만들 수 있다고 돌려준다

**USER-01-2 방 2개**
- Given A가 방 2개에 참여 중이다
- When 내 정보를 조회하면
- Then 두 방을 돌려주고 새 방을 만들 수 없다고 돌려준다

**USER-01-3 나간 방 제외**
- Given A가 방 1을 나갔고 방 2에 참여 중이다
- When 내 정보를 조회하면
- Then 방 목록에는 방 2만 있다

**USER-01-4 안 본 결과 표시**
- Given A가 방 2의 최근 발표 결과를 보지 않았다
- When 내 정보를 조회하면
- Then 방 2의 안 본 항목 여부는 true다


## USER-02 인증 캘린더

상태: 미구현

### 기능 설명
내 보살 탭에서 방별로 한 달 인증 결과를 캘린더로 돌려줍니다. [WF 41] (최신 디자인 p14)

### 입력
- 방 ID
- 월 (선택, 비어 있으면 이번 달)

### 처리 규칙
1. 현재 멤버인 방만 조회할 수 있다. [구현 결정]
2. 이 방의 내 인증만 돌려준다. [구현 결정]
3. 월은 회차 날짜 기준이다. 05:00 전 인증은 전날 회차에 들어간다. (common.md) [구현 결정]
4. 날짜마다 `참았어요` 또는 `못 참았어요`를 돌려준다. [PRD]
5. 인증이 없는 날과 삭제한 인증은 넣지 않는다. [구현 결정]
6. 참은 횟수, 연속 인증, 지목 횟수는 돌려주지 않는다. 이 방의 이번 달 수치는 오늘 탭 멤버 목록(ROOM-02)에 있다. [구현 결정] (최신 디자인 p14)

### 출력
- 월
- 캘린더: 날짜, 결과

### 예외
- `ROOM_002` (403): 이 방 멤버가 아님
- `ROOM_005` (404): 없거나 삭제된 방
- `COMMON_002` (400): 월 형식 오류
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 여러 방 합산

### 완료 조건

**USER-02-1 이번 달 캘린더**
- Given A가 방 1에서 11/1 `참았어요`, 11/2 `못 참았어요`로 인증했다
- When 월 없이 방 1 캘린더를 조회하면
- Then 11월의 두 날짜와 결과를 돌려준다

**USER-02-2 다른 방 기록 제외**
- Given A가 11/3에 방 2에서만 인증했다
- When 방 1의 11월 캘린더를 조회하면
- Then 11/3이 없다

**USER-02-3 삭제한 인증 제외**
- Given A가 11/5에 방 1에서 인증했다가 10분 안에 삭제했다
- When 방 1의 11월 캘린더를 조회하면
- Then 11/5가 없다

**USER-02-4 지난 달 조회**
- Given A가 10/31에 방 1에서 인증했다
- When 방 1의 10월 캘린더를 조회하면
- Then 10/31 결과를 돌려준다

**USER-02-5 05:00 전 인증**
- Given A가 12/1 04:30에 방 1에서 인증했다
- When 방 1의 11월 캘린더를 조회하면
- Then 11/30 결과로 들어 있다

**USER-02-6 멤버가 아닌 방**
- Given A가 방 3의 멤버가 아니다
- When 방 3 캘린더를 조회하면
- Then `ROOM_002`를 돌려준다

## USER-03 알림 설정

상태: 구현됨

### 기능 설명
앱 안의 콕 알림, 인증·투표 알림 설정을 바꿉니다. [WF 41]

### 입력
- 콕 알림 설정 (선택)
- 인증·투표 알림 설정 (선택)

### 처리 규칙
1. 보낸 값만 바꾼다. [구현 결정]
2. 두 값의 기본값은 켜짐이다. [PRD]
3. 이 설정은 토스 알림 동의(NOTI-01)와 별개다. [PRD]
4. 실제 발송 조건은 POKE-02, NOTI-02를 따른다. [PRD]

### 출력
- 없음

### 예외
- `COMMON_002` (400): 입력값 오류
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 토스 앱의 서비스별 알림 설정 (서버가 알 수 없음)

### 완료 조건

**USER-03-1 한 값만 변경**
- Given 두 알림이 모두 켜져 있다
- When 콕 알림만 꺼서 보내면
- Then 콕 알림은 꺼지고 인증·투표 알림은 켜져 있다

**USER-03-2 값 없이 요청**
- Given 콕 알림이 꺼져 있다
- When 두 값을 모두 빼고 요청하면
- Then 설정은 바뀌지 않는다

## USER-05 내 데이터 삭제

상태: 미구현

### 기능 설명
모든 방에서 나가고 사용자를 삭제 상태로 바꿉니다. 6개월 안에 돌아오면 복구됩니다. [WF 41-3]

### 입력
- 로그인한 사용자

### 처리 규칙
1. 참여 중인 모든 방에서 나간다. 방마다 ROOM-07 규칙을 적용하고 나간 유형은 `DATA_DELETED`로 저장한다. [PRD]
2. 내 인증 사진을 즉시 삭제한다. (CERT-04) [Q-49]
3. 한 줄·금액·결과는 6개월 동안 남기고 CLEAN-01에서 정리한다. 기록은 바로 "떠난 보살"로 표시한다. [Q-49]
4. 삭제 시각을 저장하고 `users` 행은 6개월 보관한다. [PRD]
5. 삭제 후 토큰은 만료 전이어도 거절한다. (AUTH-02) [구현 결정]
6. 6개월 안에 돌아오면 공양미, 아이템, 방어권을 유지한다. (AUTH-01) [PRD]
7. 복구해도 나간 방으로 자동으로 돌아가지 않는다. [구현 결정]

### 출력
- 없음

### 예외
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 6개월 뒤 정리 (CLEAN-01, CLEAN-02)
- 복구 로그인 (AUTH-01)

### 완료 조건

**USER-05-1 모든 방에서 나감**
- Given A가 방 2개에 참여 중이다
- When 내 데이터를 삭제하면
- Then 두 방 모두 A가 `DATA_DELETED`로 나가고 삭제 시각이 저장된다

**USER-05-2 방장 위임**
- Given A가 방장이고 B가 다음으로 먼저 들어온 멤버다
- When A가 내 데이터를 삭제하면
- Then B가 방장이 된다

**USER-05-3 혼자인 방**
- Given A가 혼자 있는 방이 있다
- When A가 내 데이터를 삭제하면
- Then 그 방은 삭제된다

**USER-05-4 삭제 후 토큰**
- Given A가 내 데이터를 삭제했고 토큰이 만료 전이다
- When A가 그 토큰으로 API를 호출하면
- Then `COMMON_008`을 돌려준다

**USER-05-5 복구 후 방**
- Given A가 내 데이터를 삭제하고 6개월 안에 다시 로그인했다
- When 내 정보를 조회하면
- Then 공양미는 유지되고 방 목록은 비어 있다

**USER-05-6 사진 즉시 삭제**
- Given A의 인증에 사진이 있다
- When 내 데이터를 삭제하면
- Then 사진이 바로 삭제된다

**USER-05-7 바로 떠난 보살 표시**
- Given A의 인증과 투표 결과가 있다
- When A가 내 데이터를 삭제한 뒤 남은 멤버가 그 기록을 보면
- Then A는 "떠난 보살"로 표시된다

## NOTI-01 토스 알림 동의

상태: 미구현

### 기능 설명
클라이언트가 받은 토스 알림 동의 결과를 저장합니다. [WF 47]

### 입력
- 알림 종류: `CERT_REMINDER`
- 동의 결과: `newAgreement`, `alreadyAgreed`, `agreementRejected`

### 처리 규칙
1. 동의는 인증 마감 리마인드(`CERT_REMINDER`) 1종만 받는다. [PRD] 나머지 알림은 [미정] Q-14
2. `CERT_REMINDER`가 아닌 종류는 `COMMON_002`를 돌려준다. [구현 결정]
3. `newAgreement`, `alreadyAgreed`면 동의를 저장한다. [PRD]
4. `agreementRejected`면 저장하지 않는다. [PRD]
5. 이미 동의가 저장돼 있으면 처음 동의 시각을 유지한다. [구현 결정]
6. 같은 요청이 동시에 와도 동의는 1건만 저장한다. [구현 결정]
7. 동의를 저장해도 앱 안 알림 설정은 바뀌지 않는다. [PRD]

### 출력
- 없음

### 예외
- `COMMON_002` (400): 입력값 오류
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 토스 동의 화면 호출 (클라이언트)
- 알림 카드 표시와 닫기 (클라이언트)
- 알림 발송 (POKE-02, NOTI-02)

### 완료 조건

**NOTI-01-1 새 동의**
- Given A의 동의 기록이 없다
- When `newAgreement`를 보내면
- Then 동의가 저장되고 내 정보의 `CERT_REMINDER` 동의 여부는 true다

**NOTI-01-2 이미 동의함**
- Given A의 동의 기록이 있다
- When `alreadyAgreed`를 보내면
- Then 동의는 1건이고 처음 동의 시각이 유지된다

**NOTI-01-3 거부**
- Given A의 동의 기록이 없다
- When `agreementRejected`를 보내면
- Then 저장하지 않는다

**NOTI-01-4 지원하지 않는 종류**
- Given A가 로그인했다
- When `POKE` 동의 결과를 보내면
- Then `COMMON_002`를 돌려주고 저장하지 않는다

**NOTI-01-5 동시 요청**
- Given A의 동의 기록이 없다
- When 같은 동의 요청이 동시에 오면
- Then 동의는 1건만 저장된다
