# 상호작용 · 알림

콕, 인증 리액션, 예약 알림을 다룹니다. 알림 동의(NOTI-01)와 알림 딥링크(NOTI-03)는 따로 추가합니다.

## POKE-01 콕 찌르기

상태: 미구현

### 기능 설명
같은 방 멤버를 콕 찌릅니다. 인증 여부와 회차 상태에 상관없이 언제나 찌를 수 있습니다. [WF 10·20] [11/8 회의]

### 입력
- 방 ID
- 받는 멤버
- 찌른 횟수 (화면에서 모아 보낸 값)

### 처리 규칙
1. 같은 방의 활성 멤버끼리만 가능하다. 본인은 찌를 수 없다. [정책서]
2. 받는 사람이 인증했는지와 상관없이 보낼 수 있다. [11/8 회의]
3. 회차가 인증 중, 투표 중, 발표 후 어느 상태여도 보낼 수 있다. [11/8 회의]
4. 콕은 오늘 회차에 쌓는다. 오늘 회차 행이 없으면 만든다. [구현 결정]
5. 앱 안 누적 횟수에는 제한이 없다. [정책서]
6. 연타는 화면에서 1~2초 모아 횟수로 보내고, 서버는 받은 횟수를 더한다. 요청 한 번의 횟수는 1~30이다. [구현 결정] [11/8 회의: 연타 제한 요청]
7. 받는 사람 기준으로 보낸 사람별 횟수와 전체 횟수를 누적한다. [정책서]
8. 받는 사람이 인증하면 그 회차에 받은 콕을 초기화할지는 [미정] Q-54
9. 누적 횟수는 받는 사람 화면에 보여준다. 찌르는 사람에게도 보여줄지는 [미정] Q-55

### 출력
- 없음. 받는 사람의 `콕 ×n`은 오늘 탭(ROOM-02)에서 받은 수만 돌려준다. 누가 찔렀는지는 돌려주지 않는다. (최신 디자인에 "○○님이 찔렀어요" 안내가 없음) [구현 결정]

### 예외
- `POKE_001` (400): 본인에게 찌르기
- `ROOM_009` (404): 받는 사람이 이 방의 현재 멤버가 아님 (다른 방 멤버 포함)
- `ROOM_002` (403): 보내는 사람이 이 방 멤버가 아님
- `ROOM_005` (404): 없거나 삭제된 방
- `COMMON_002` (400): 찌른 횟수가 1~30이 아님
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 콕 푸시 발송 (POKE-02)
- 미인증자가 앱에 들어올 때 띄우는 인증 유도 팝업 (화면에서 처리) [11/8 회의]

### 완료 조건

**POKE-01-1 콕 누적**
- Given B가 오늘 회차에 인증하지 않았다
- When A가 B에게 3번, C가 B에게 2번 찌르면
- Then B 화면에는 `콕 ×5`가 보이고, 누가 찔렀는지는 보이지 않는다

**POKE-01-2 인증한 멤버에게도 가능**
- Given B가 오늘 회차에 인증했다
- When A가 B를 찌르면
- Then 저장된다

**POKE-01-3 본인에게는 불가**
- When A가 A를 찌르면
- Then 거부한다

**POKE-01-4 다른 방 멤버에게는 불가**
- Given E는 이 방 멤버가 아니다
- When A가 E를 찌르면
- Then 거부한다

**POKE-01-5 투표 중에도 가능**
- Given 오늘 회차가 전원 인증으로 투표 중이다
- When A가 B를 찌르면
- Then 저장된다

**POKE-01-6 회차 행이 없을 때**
- Given 오늘 방에서 아무도 인증하지 않아 회차 행이 없다
- When A가 B를 찌르면
- Then 오늘 회차 행이 만들어지고 콕이 저장된다

**POKE-01-7 요청 한 번의 횟수 상한**
- When A가 B에게 31번을 한 번에 보내면
- Then 거부한다

## POKE-02 콕 푸시

상태: 미구현

### 기능 설명
처음 받은 콕을 푸시로 알립니다.

### 입력
- 콕 찌르기 결과

### 처리 규칙
1. 받는 사람·방·회차 기준 처음 1번만 푸시한다. [정책서]
2. 08:00~23:00 사이에만 발송한다. [정책서]
3. 그 뒤의 콕은 앱 안에서만 누적한다. [정책서] 이미 보낸 푸시의 숫자는 바꿀 수 없어서, 횟수가 늘어나는 표시는 앱 안에서만 한다. [11/8 회의] [구현 결정]
4. 받는 사람의 콕 알림 설정이 꺼져 있으면 발송하지 않는다. [정책서]
5. 동의문 없이 발송할 수 있는지는 [미정] Q-14
6. 푸시 문구가 앱인토스 검수에서 반려되면 앱 안 표시만 사용한다. [정책서]
7. 발송 실패가 콕 저장을 되돌리지 않는다. [정책서]

### 출력
- 발송 여부와 성공 여부

### 예외
- 발송 실패: 기록만 남기고 콕은 그대로 저장한다

### 제외 범위
- 앱인토스 발송 연동 자체 (공통 푸시 발송 모듈)

### 완료 조건

**POKE-02-1 처음 콕은 푸시**
- Given B가 오늘 회차에 콕을 받은 적이 없고 콕 알림이 켜져 있다
- When 10:00에 A가 B를 찌르면
- Then B에게 푸시를 한 번 보낸다

**POKE-02-2 두 번째부터는 앱 안에서만**
- Given B가 오늘 회차에 콕 푸시를 이미 받았다
- When C가 B를 찌르면
- Then 푸시를 보내지 않는다

**POKE-02-3 발송 시간 밖**
- Given B가 오늘 회차에 콕을 받은 적이 없다
- When 23:30에 A가 B를 찌르면
- Then 푸시를 보내지 않고 콕은 저장한다

**POKE-02-4 알림 꺼짐**
- Given B의 콕 알림이 꺼져 있다
- When A가 B를 찌르면
- Then 푸시를 보내지 않는다

**POKE-02-5 동시에 처음 콕**
- Given B가 오늘 회차에 콕을 받은 적이 없다
- When A와 C가 동시에 B를 찌르면
- Then B에게 푸시는 한 번만 간다

## REACT-01 인증 리액션

상태: 미구현

### 기능 설명
다른 멤버의 인증에 공양미 또는 목탁 리액션을 남깁니다. [WF 11·12]

### 입력
- 인증 ID
- 리액션: `RICE` 또는 `MOKTAK`

### 처리 규칙
1. 한 사람은 한 인증에 하나만 남길 수 있다. [정책서]
2. 다른 리액션을 누르면 바꾼다. [정책서]
3. 같은 리액션을 다시 누르면 취소한다. [정책서]
4. 본인 인증에는 남길 수 없다. [정책서]
5. 투표 시작 전까지만 남기거나 바꿀 수 있다. [정책서] 투표가 열리지 않은 회차(`NO_VOTE`)의 기한은 [미정] Q-33
6. 수량만 공개하고 누가 눌렀는지는 공개하지 않는다. [정책서]
7. 리액션은 재화가 아니며 공양미 잔액을 바꾸지 않는다. [정책서]
8. 목탁 수는 결과 판정에 쓰지 않는다. (RESULT-01) [Q-79]
9. 남기기·바꾸기는 요청 형식(`COMMON_002`) → 없는 인증(`CERT_002`) → 방 멤버 아님(`ROOM_002`) → 본인 인증(`REACT_001`) → 투표 시작 후(`REACT_002`) 순서로 확인한다. [구현 결정]
10. 취소는 없는 인증(`CERT_002`) → 방 멤버 아님(`ROOM_002`) → 남긴 리액션 없음(성공) → 본인 인증(`REACT_001`) → 투표 시작 후(`REACT_002`) 순서로 확인한다. 그래서 투표 시작 뒤라도 남긴 리액션이 없으면 성공이다. [구현 결정]

### 출력
- 인증별 `RICE`, `MOKTAK` 수
- 내가 남긴 리액션

### 예외
- `CERT_002` (404): 없거나 삭제된 인증
- `ROOM_002` (403): 인증이 있는 방의 멤버가 아님 [구현 결정]
- `REACT_001` (403): 본인 인증
- `REACT_002` (409): 투표 시작 후
- `COMMON_002` (400): 없는 리액션 종류
- `COMMON_008` (401): 인증 필요
- 남긴 리액션이 없을 때 취소하면 성공으로 돌려준다 [구현 결정]

### 제외 범위
- 결과 판정 (RESULT-01)

### 완료 조건

**REACT-01-1 리액션 남기기**
- Given B가 인증했다
- When A가 `RICE`를 누르면
- Then B 인증의 `RICE` 수가 1이다

**REACT-01-2 리액션 바꾸기**
- Given A가 B의 인증에 `RICE`를 남겼다
- When A가 `MOKTAK`을 누르면
- Then `RICE` 0, `MOKTAK` 1이다

**REACT-01-3 리액션 취소**
- Given A가 B의 인증에 `RICE`를 남겼다
- When A가 `RICE`를 다시 누르면
- Then `RICE` 수가 0이다

**REACT-01-4 본인 인증에는 불가**
- Given A가 오늘 회차에 인증했다
- When A가 자기 인증에 리액션을 남기면
- Then 거부한다

**REACT-01-5 투표 시작 후 불가**
- Given 투표가 시작됐다
- When A가 B의 인증에 리액션을 남기면
- Then 거부한다

**REACT-01-6 누가 눌렀는지 비공개**
- Given A가 B의 인증에 `MOKTAK`을 남겼다
- When C가 B의 인증을 조회하면
- Then `MOKTAK` 수만 보이고 누른 사람은 보이지 않는다

**REACT-01-8 본인 인증이면서 투표 시작 후**
- Given A가 인증했고 투표가 시작됐다
- When A가 자기 인증에 리액션을 남기면
- Then `REACT_001`을 돌려준다

**REACT-01-9 투표 시작 뒤 남긴 리액션 없이 취소**
- Given A가 B의 인증에 리액션을 남기지 않았고 투표가 시작됐다
- When A가 리액션을 취소하면
- Then 성공한다

## NOTI-02 예약 알림

상태: 미구현

### 기능 설명
정해진 시각이나 상황에 맞춰 인증·투표·결과 알림을 보냅니다.

### 입력
- 회차 상태, 인증·투표·결과 확인 상태
- 사용자 알림 설정과 알림 동의

### 처리 규칙
| 알림 | 대상 | 시점 |
|---|---|---|
| 인증 마감 | 미인증 멤버 | 회차 당일 22:00 |
| 투표 열림 | 방 멤버 | 전원 인증으로 다음 날 05:00 전에 투표가 시작될 때 |
| 투표 독려 | 아직 투표하지 않은 명단 멤버. 투표권 없는 미인증 멤버도 앱 진입을 위해 포함 [11/8 회의] | 다음 날 08:00 |
| 결과 | 결과 미확인 멤버 | 집계 완료 후 |

1. 방이 2개인 사용자의 인증 마감 알림은 하나로 합친다. [정책서]
2. 인증 마감 알림은 토스 알림 동의가 있고 인증·투표 알림 설정이 켜져 있을 때만 보낸다. [구현 결정]
3. 나머지 알림은 인증·투표 알림 설정만 켜져 있으면 보낸다. [구현 결정] 동의문 없이 보낼 수 있는지는 [미정] Q-14
4. 05:00 작업으로 투표가 시작될 때 투표 열림 알림을 보낼지는 [미정] Q-24
5. 발송 직전에 대상을 다시 계산해, 그사이 인증·투표했거나 방을 나간 사람에게는 보내지 않는다. [정책서]
6. 같은 사용자·알림 종류·방·회차에는 한 번만 보낸다. 인증 마감 알림은 방 개수와 상관없이 방을 비워 기록해, 사용자·알림 종류·회차에 한 번만 보낸다. 실패 후 다시 보낼 때도 기록은 하나다. [구현 결정]
7. 발송 실패가 원래 처리를 되돌리지 않는다. [정책서]
8. 인증 마감 알림은 기능성 푸시로 보낸다. 사업자등록 없이 발송할 수 있다. [Q-31]
9. 회차 마감이 05:00로 바뀌어 인증 마감 알림을 22:00에 그대로 보낼지는 [미정] Q-58 [11/8 회의]

### 출력
- 알림별 발송 대상과 결과

### 예외
- 발송 실패: 기록만 남긴다

### 제외 범위
- 콕 푸시 (POKE-02)
- 알림 동의 받기 (NOTI-01)
- 알림을 눌렀을 때 이동 (NOTI-03)

### 완료 조건

**NOTI-02-1 인증 마감 알림**
- Given A가 오늘 회차에 인증하지 않았고 알림 동의와 설정이 켜져 있다
- When 22:00이 되면
- Then A에게 인증 마감 알림을 보낸다

**NOTI-02-2 인증한 사람은 제외**
- Given A가 21:59에 인증했다
- When 22:00이 되면
- Then A에게 인증 마감 알림을 보내지 않는다

**NOTI-02-3 방 2개는 하나로**
- Given A가 두 방 모두 인증하지 않았다
- When 22:00이 되면
- Then A에게 인증 마감 알림을 하나만 보낸다

**NOTI-02-4 동의 없음**
- Given A가 토스 알림 동의를 하지 않았다
- When 22:00이 되면
- Then A에게 인증 마감 알림을 보내지 않는다

**NOTI-02-5 투표 독려**
- Given A가 명단에 있고 아직 투표하지 않았다
- When 다음 날 08:00이 되면
- Then A에게 투표 독려 알림을 보낸다

**NOTI-02-6 같은 알림 중복 없음**
- Given A에게 오늘 회차 인증 마감 알림을 보냈다
- When 발송 작업이 다시 실행되면
- Then A에게 다시 보내지 않는다

**NOTI-02-7 발송 실패**
- Given 앱인토스 발송이 실패한다
- When 결과 알림을 보내면
- Then 실패를 기록하고 결과 확정은 그대로다

**NOTI-02-8 다시 들어온 멤버는 투표 독려 제외**
- Given C가 명단에 있고 투표 시작 뒤 방을 나갔다가 다시 들어왔으며 아직 투표하지 않았다
- When 다음 날 08:00이 되면
- Then C에게 투표 독려 알림을 보내지 않는다

**NOTI-02-10 미인증 멤버도 투표 독려**
- Given D가 명단에 있지만 인증하지 않아 투표권이 없다
- When 다음 날 08:00이 되면
- Then D에게도 투표 독려 알림을 보낸다

**NOTI-02-9 통합 알림 뒤 방이 줄어도 중복 없음**
- Given A가 두 방 모두 인증하지 않아 인증 마감 알림을 하나 받았고, 그 뒤 한 방을 나갔다
- When 발송 작업이 다시 실행되면
- Then 남은 방도 인증하지 않았지만 A에게 다시 보내지 않는다
