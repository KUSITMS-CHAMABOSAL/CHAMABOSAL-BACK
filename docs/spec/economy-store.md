# 공양미 · 곳간

공양미(단위: 석) 적립·회수·차감, 방 공동 진행도인 한 솥, 이마 방어권을 다룹니다. 수치는 [`common.md`](common.md)의 핵심 수치를 따릅니다.

공양미는 두 가지입니다. [정책서]

| 구분 | 개인 공양미 (곳간) | 팀 공양미 (공양미 한 솥) |
|---|---|---|
| 역할 | 아이템·방어권 구매 | 방의 목표 진행도, 기여 순위 기준 |
| 적립 | 모든 적립 사유 | 함께하는 행동(인증, 투표, 톡톡, 리액션)만 |
| 차감 | 구매, 인증 삭제 회수, 방 나가기 | 인증 삭제 회수만. 구매로 줄지 않음 |
| 범위 | 사용자 단위. 여러 방에서 모은 공양미를 합쳐 씀 | 방 단위 |

## RICE-01 개인 공양미 적립

상태: 미구현

### 기능 설명
인증·투표·톡톡·리액션·번뇌 완료·목표 달성으로 개인 공양미를 적립합니다.

### 입력
- 적립 사유: 인증, 투표, 톡톡 완료, 리액션, 번뇌 완료, 목표 달성 보너스
- 원인 ID: 인증 ID, 투표 ID, 톡톡 ID, 리액션을 남긴 인증 ID, 회차 ID, 솥 ID
- 적립이 일어난 방

### 처리 규칙
1. 방 인원이 2명 이상일 때만 적립한다. [정책서]
2. 인증하면 방마다 회차당 개인 +10석을 지급한다. [정책서]
3. 투표하면 방마다 회차당 개인 +5석을 지급한다. `오늘은 모두 보살`을 골라도 같다. [정책서] 투표권은 인증한 명단 멤버에게만 있어서 미인증 멤버는 투표 보상이 없다. (VOTE-03) [11/8 회의]
4. 지목된 사람에게 톡톡을 건너뛰지 않고 1번 이상 보내면 보낸 사람에게 회차당 개인 +5석을 지급한다. 0번(건너뛰기)이면 지급하지 않는다. (RESULT-03) [정책서] 보낸 뒤 지목된 사람이 방어해 톡톡이 무효가 되면 보상을 유지할지는 [미정] Q-93
5. 다른 멤버의 인증에 리액션을 처음 남기면 남긴 사람에게 개인 +1석을 지급한다. 인증 1건당 한 번만 주고, 리액션을 바꾸거나 취소하거나 다시 남겨도 더 주거나 회수하지 않는다. (REACT-01) [정책서] [Q-90] 리액션을 남긴 인증이 삭제될 때 회수할지는 [미정] Q-91
6. 지목된 사람이 받은 톡톡 횟수만큼 번뇌를 수행하면 개인 +10석을 지급한다. 팀 공양미에는 넣지 않는다. [정책서] 무엇을 수행 완료로 보는지와 받은 톡톡이 0번일 때는 [미정] Q-92
7. 방어권을 써서 결과가 `DEFENDED`가 되면 번뇌 완료 보상을 지급하지 않는다. (SHIELD-02) [정책서]
8. 방이 목표를 채우면 그 시점 방 멤버 전원에게 목표의 10%를 개인 공양미로 지급한다. 팀 공양미에는 넣지 않는다. (POT-01) [정책서] 10석 단위로 떨어지지 않아도 그대로 지급한다 (예: 350석 → 35석). [Q-81]
9. `참았어요`와 `못 참았어요`에 같은 양을 지급한다. [정책서]
10. 적립 기록마다 적립이 일어난 방을 남긴다. 방 나가기 차감(RICE-03)에 쓴다. [정책서]
11. 잔액은 저장하지 않고 장부(적립·사용·회수·차감 기록)의 합계로 계산한다. [구현 결정]
12. 같은 사유·원인 ID에는 한 번만 지급한다. 인증을 삭제하고 다시 인증하면 새 인증 ID라서 다시 지급한다. [PRD]

### 출력
- 변동량, 사유, 원인 ID, 방
- 변경 후 잔액
- 화면 표시 잔액: 음수면 0석 [WF 33]

### 예외
- 같은 원인으로 다시 요청해도 중복 지급하지 않는다

### 제외 범위
- 현금·토스 포인트 전환, 선물, 내기 (제공하지 않음)
- 팀 공양미 적립 (POT-01)
- 회수 (RICE-02), 방 나가기 차감 (RICE-03)
- 사용 (SHIELD-01, ITEM-01)

### 완료 조건

**RICE-01-1 인증 보상**
- Given 방 인원이 3명이다
- When A가 인증하면
- Then A에게 +10석이 기록된다

**RICE-01-2 투표 보상**
- Given 방 인원이 3명이다
- When A가 `오늘은 모두 보살`에 투표하면
- Then A에게 +5석이 기록된다

**RICE-01-3 혼자인 방**
- Given 방 인원이 1명이다
- When A가 인증하면
- Then 공양미를 기록하지 않는다

**RICE-01-4 같은 인증으로 중복 지급 없음**
- Given A의 인증으로 +10석이 기록됐다
- When 같은 인증 ID로 지급이 다시 실행되면
- Then 추가로 기록하지 않는다

**RICE-01-5 삭제 후 다시 인증**
- Given A가 인증해 +10석을 받고, 삭제해 -10석이 회수됐다
- When A가 같은 회차에 다시 인증하면
- Then 새 인증으로 +10석이 기록되고 그 회차 순 지급은 10석이다

**RICE-01-6 음수 잔액 표시**
- Given A의 장부 합계가 -10석이다
- When A가 잔액을 조회하면
- Then 화면 표시 잔액은 0석이다

**RICE-01-7 톡톡 완료 보상**
- Given B가 지목됐다
- When A가 B에게 톡톡 3번을 보내면
- Then A에게 +5석이 기록된다

**RICE-01-8 톡톡 건너뛰기는 보상 없음**
- Given B가 지목됐다
- When A가 톡톡을 0번으로 건너뛰면
- Then A에게 공양미를 기록하지 않는다

**RICE-01-9 리액션 보상은 처음 한 번**
- Given A가 B의 인증에 `RICE`를 남겨 +1석을 받았다
- When A가 `MOKTAK`으로 바꾸고, 취소하고, 다시 `RICE`를 남기면
- Then A의 리액션 보상은 +1석 한 번뿐이다

**RICE-01-10 번뇌 완료 보상**
- Given A가 지목돼 톡톡을 받았다
- When A가 번뇌를 수행 완료하면
- Then A에게 +10석이 기록되고 팀 공양미는 그대로다

**RICE-01-11 방어하면 번뇌 보상 없음**
- Given A가 지목됐다
- When A가 방어권을 써서 결과가 `DEFENDED`가 되면
- Then A에게 번뇌 완료 보상을 기록하지 않는다

**RICE-01-12 적립 기록에 방을 남김**
- Given A가 방 1과 방 2에 참여 중이다
- When A가 방 1에서 인증하면
- Then +10석 기록의 방은 방 1이다

## RICE-02 공양미 회수

상태: 미구현

### 기능 설명
삭제된 인증으로 지급했던 공양미를 회수합니다.

### 입력
- 삭제된 인증 ID

### 처리 규칙
1. 본인이 인증을 삭제하면 그 인증으로 지급된 개인 공양미를 장부 기록만큼 회수한다. 지급되지 않았으면 회수하지 않는다. [정책서]
2. 진행 중인 솥에 들어간 그 인증의 적립분도 회수한다. [정책서]
3. 이미 목표를 채운 솥에 들어간 적립분은 회수하지 않는다. [정책서]
4. 끝난 투표 결과는 바꾸지 않는다. [정책서]
5. 잔액이 음수가 될 수 있고, 0 이상이 될 때까지 구매를 막는다. [정책서] 0석 바닥은 방 나가기 차감(RICE-03)에만 적용한다. [Q-87]
6. 회수 기록에도 인증이 있던 방을 남긴다. [구현 결정]

### 출력
- 회수 기록

### 예외
- 같은 삭제로 다시 요청해도 회수는 한 번만 기록한다

### 제외 범위
- 운영자 조치에 따른 회수 (신고가 범위에서 빠짐)

### 완료 조건

**RICE-02-1 개인 회수**
- Given A의 인증으로 +10석이 기록됐다
- When A가 인증을 삭제하면
- Then A에게 -10석이 기록된다

**RICE-02-2 지급되지 않은 보상**
- Given 방 인원 1명일 때 인증해 보상이 없었다
- When A가 인증을 삭제하면
- Then 회수를 기록하지 않는다

**RICE-02-3 진행 중인 솥 회수**
- Given A의 인증 10석이 진행 중인 솥에 들어갔다
- When A가 인증을 삭제하면
- Then 솥 진행도가 10석 줄어든다

**RICE-02-4 목표를 채운 솥은 회수 안 함**
- Given A의 인증 10석이 들어간 솥이 이미 목표를 채웠다
- When A가 인증을 삭제하면
- Then 개인 공양미만 회수하고 솥 진행도는 그대로다

**RICE-02-5 음수 잔액**
- Given A의 잔액이 5석이다
- When A의 인증 삭제로 10석을 회수하면
- Then A의 잔액은 -5석이고 구매할 수 없다

**RICE-02-6 회수 중복 없음**
- Given A의 인증 삭제로 회수가 기록됐다
- When 회수가 다시 실행되면
- Then 추가로 기록하지 않는다

## RICE-03 방 나가기 차감

상태: 미구현

### 기능 설명
목표를 채우기 전에 방을 나가면 그 방에서 모은 개인 공양미를 곳간 잔액에서 차감합니다. [정책서]

### 입력
- 나가는 멤버 (ROOM-07)

### 처리 규칙
1. 방이 목표를 채우기 전에 나가면 차감한다. [정책서] 연장한 방(POT-01 7번)에서 다음 목표를 채우기 전에 나갈 때 차감하는지는 [미정] Q-89
2. 차감할 석은 그 방에서 적립된 개인 공양미(인증, 투표, 톡톡 완료, 리액션, 번뇌 완료, 목표 달성 보너스)에서 그 방의 회수를 뺀 값이다. [정책서] [Q-87] 나갔다가 다시 들어와 또 나가면 다시 들어온 시각 뒤에 기록된 것만 센다. 이전 나가기에서 정산이 끝났다고 본다(0석을 빼서 차감 기록이 없었어도 같다). [구현 결정]
3. 차감 뒤 잔액이 음수가 되면 잔액이 0석이 되는 만큼만 차감한다. [정책서] [Q-87] 나가기 전 잔액이 이미 0석 이하면 차감하지 않고 그대로 둔다. [Q-88]
4. 이미 산 아이템과 방어권은 그대로 둔다. [정책서]
5. 팀 공양미(솥 진행도)는 바꾸지 않는다. [구현 결정]
6. 나가기 확인 화면에 보여줄 차감 예정 석(그 방에서 모은 공양미)을 돌려준다. [정책서] 나가기 확인 화면 디자인(8-3)에 표시할 곳이 없어 지금은 만들지 않는다. 표시하기로 하면 조회 API를 추가한다. [구현 결정]
7. 차감은 나가기 처리와 같은 트랜잭션에서 한 번만 기록한다. [구현 결정] 다시 들어오면 같은 멤버 행을 다시 써서 멤버 ID로는 두 번째 나가기를 구분할 수 없으므로, 차감 기록에는 원인을 남기지 않는다. 한 번 나갈 때 한 번만 기록되는 것은 나가기가 현재 멤버만 방 행 락 안에서 처리되는 것으로 보장한다. 차감은 사용자 전체 잔액을 읽고 빼므로, 같은 사람의 나가기는 사용자 행 락으로 하나씩 처리한다(사용자 → 방 순서). [구현 결정]

### 출력
- 차감 예정 석 (나가기 확인 화면: "이 방에서 모은 공양미 200석이 사라져요")
- 차감 기록과 변경 후 잔액

### 예외
- 같은 나가기로 다시 요청해도 차감은 한 번만 기록한다

### 제외 범위
- 나가기 처리 자체 (ROOM-07)
- 내보내기 (ROOM-08). 내보내진 멤버도 차감할지는 [미정] Q-94. 정해질 때까지 스스로 나간 경우만 차감한다
- 내 데이터 삭제(USER-05)로 나가는 경우. 6개월 안에 돌아오면 공양미를 유지하므로 차감하지 않는다 (USER-05 6번)

### 완료 조건

**RICE-03-1 나가면 그 방 적립 차감**
- Given 목표를 채우지 않은 방 1에서 A가 200석을 모았고, A의 잔액은 350석이다
- When A가 방 1을 나가면
- Then A에게 -200석이 기록되고 잔액은 150석이다

**RICE-03-2 차감 뒤 음수면 0석**
- Given 방 1에서 A가 200석을 모았고, 아이템을 사서 잔액이 120석이다
- When A가 방 1을 나가면
- Then A에게 -120석이 기록되고 잔액은 0석이다

**RICE-03-3 회수는 빼고 차감**
- Given 방 1에서 A가 인증 3번으로 30석을 받고 그중 1번을 삭제해 10석이 회수됐다
- When A가 방 1을 나가면
- Then 차감할 석은 20석이다

**RICE-03-4 다른 방 적립은 그대로**
- Given A가 방 1에서 100석, 방 2에서 50석을 모았다
- When A가 방 1을 나가면
- Then 100석만 차감하고 방 2에서 모은 50석은 남는다

**RICE-03-5 아이템 유지**
- Given A가 100석 아이템을 보유했다
- When A가 방을 나가 공양미가 차감되면
- Then A는 그 아이템을 계속 보유한다

**RICE-03-6 목표를 채운 뒤 나가면 차감 없음**
- Given 방 1이 목표를 채워 기간이 끝났다
- When A가 방 1을 나가면
- Then 차감을 기록하지 않는다

**RICE-03-7 다시 들어온 뒤 또 나가기**
- Given A가 방 1에서 100석을 모아 나가며 -100석이 차감됐고, 다시 들어와 10석을 모았다
- When A가 방 1을 다시 나가면
- Then A에게 -10석이 기록된다

**RICE-03-8 이미 잔액이 음수**
- Given 방 1에서 A가 10석을 모았지만 인증 삭제 회수 등으로 잔액이 -10석이다
- When A가 방 1을 나가면
- Then 차감을 기록하지 않고 잔액은 -10석 그대로다

**RICE-03-9 0석을 빼고 나간 뒤 다시 들어와 또 나가기**
- Given A가 방 1에서 100석을 모았지만 다 써서 잔액 0석으로 나갔고(차감 기록 없음), 다시 들어와 방 1에서 10석, 방 2에서 100석을 모았다
- When A가 방 1을 다시 나가면
- Then A에게 -10석이 기록된다

**RICE-03-10 두 방을 동시에 나가기**
- Given A가 방 1과 방 2에서 100석씩 모았고, 80석을 써서 잔액이 120석이다
- When A가 방 1과 방 2를 동시에 나가면
- Then 차감은 모두 120석이고 잔액은 0석이다

## POT-01 공양미 한 솥

상태: 미구현

### 기능 설명
방마다 방 목표 석만큼 팀 공양미를 채웁니다.

### 입력
- 인증·투표·톡톡 완료·리액션 적립, 인증 삭제 회수
- 방 목표 석 (방을 만들 때 300~700석, 50석 단위) [Q-80]

### 처리 규칙
1. 방 인원이 2명 이상일 때 인증 +10석, 투표 +5석, 톡톡 완료 +5석, 리액션 +1석을 쌓는다. 적립 조건은 RICE-01과 같다. [정책서]
2. 번뇌 완료와 목표 달성 보너스는 쌓지 않는다. [정책서]
3. 개인 잔액에서 차감하지 않는 별도 진행도다. 아이템을 사도 줄지 않는다. [정책서]
4. 방 목표 석 이상이면 목표 달성으로 처리한다. [정책서]
5. 목표 달성 시점 방 멤버 전원에게 개인 공양미로 목표의 10%를 지급한다. (RICE-01 8번) [정책서]
6. 목표를 채우면 방 기간이 끝나고 방장이 연장하거나 종료한다. [정책서] 방장이 고르기 전에도 인증·투표·적립은 평소처럼 계속된다. [Q-86]
7. 연장하면 같은 목표로 새 솥을 0석부터 채우고, 목표를 넘친 석은 새 솥으로 이월한다. 새 솥을 채우면 다시 목표 달성 보너스를 준다. [Q-83]
8. 연장해도 사용자의 공양미와 산 아이템은 그대로다. [정책서]
9. 종료한 방은 삭제하지 않고 남긴다. [Q-84] 종료한 방을 화면에서 볼 수 있는지, 참여 방 2개에 세는지는 [미정] Q-85
10. 목표를 채울 때마다 방의 쌀가마 배지를 +1 한다. [정책서]
11. 솥 진행도는 0 아래로 내려가지 않는다. [정책서]
12. 목표 달성 축하 화면은 사용자마다 한 번만 보여준다. [WF 19]
13. 멤버별로 몇 번째 솥까지 봤는지만 저장하고, 방에 들어올 때 현재 완성 횟수로 채운다. [구현 결정]
14. 축하 화면에는 그 솥에 멤버별로 넣은 석과 순위를 보여준다. 넣은 석은 팀 공양미 적립(인증·투표·톡톡 완료·리액션)에서 회수를 뺀 값이다. 나간 멤버도 "떠난 보살"로 포함한다. [정책서] [디자인] [구현 결정]
15. 넣은 석이 같으면 같은 순위로 하고(예: 1, 1, 3) 같은 순위 안에서는 그 솥에 먼저 넣은 멤버를 앞에 둔다. [구현 결정]

### 출력
- 현재 솥 진행도와 목표 석
- 완성 횟수 (쌀가마 배지)
- 이월 석
- 미확인 축하 여부
- 다 채운 솥의 멤버별 넣은 석과 순위, 멤버 전원이 받은 보상 석

### 예외
- 동시 적립으로 목표를 넘겨도 목표 달성 보상은 한 번만 지급한다
- `POT_001` (404): 없거나 아직 다 채우지 않은 솥 (축하 화면 조회)
- `ROOM_002` (403): 이 방 멤버가 아님
- `ROOM_005` (404): 없거나 삭제된 방
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 개인 공양미 장부 (RICE-01, RICE-02, RICE-03)
- 방 목표 석 입력 (ROOM-01)
- 연장·종료 요청 처리와 화면

### 완료 조건

- When A가 인증해 10석이 들어가면
- Then 목표를 달성하고 멤버 전원에게 +30석, 쌀가마 배지 +1이다

**POT-01-2 동시 적립으로 달성**
- Given 목표 300석인 방의 솥 진행도가 295석이다
- When A와 B의 인증 적립이 동시에 들어가면
- Then 달성은 한 번이고 보상도 한 번이다

**POT-01-3 0 아래로 안 내려감**
- Given 솥 진행도가 5석이다
- When 10석을 회수하면
- Then 솥 진행도는 0석이다

**POT-01-4 축하는 한 번만**
- Given 솥이 목표를 채웠고 A가 축하 화면을 봤다
- When A가 다시 앱에 들어오면
- Then 축하 화면을 다시 보여주지 않는다

**POT-01-5 들어오기 전 달성은 축하 없음**
- Given 솥이 2번 목표를 채운 방이다
- When E가 방에 들어오면
- Then E에게 축하 화면을 보여주지 않는다

**POT-01-6 넣은 석과 같은 순위**
- Given 다 채운 솥에 A 120석, B 90석, C 90석이 들어갔고 B가 C보다 먼저 넣었다
- When 축하 화면을 조회하면
- Then 순위는 A 1위, B 2위, C 2위이고 B가 C보다 앞에 나온다

**POT-01-7 다 채우지 않은 솥**
- Given 방의 2번째 솥이 진행 중이다
- When 2번째 솥 축하 화면을 조회하면
- Then `POT_001`을 돌려준다

**POT-01-8 목표에 따른 보너스**
- Given 목표 500석인 방의 솥 진행도가 495석이다
- When A가 인증해 10석이 들어가면
- Then 멤버 전원에게 +50석을 지급한다

**POT-01-9 톡톡·리액션도 팀 공양미**
- Given 솥 진행도가 100석이다
- When A가 톡톡을 1번 이상 보내고 B가 C의 인증에 처음 리액션을 남기면
- Then 솥 진행도는 106석이다

**POT-01-10 번뇌 완료는 팀 공양미 아님**
- Given 솥 진행도가 100석이다
- When 지목된 A가 번뇌를 수행 완료하면
- Then A의 개인 공양미만 +10석이고 솥 진행도는 100석이다

**POT-01-11 연장하면 새 솥과 이월**
- Given 목표 300석인 방의 솥이 305석으로 목표를 채웠다
- When 방장이 연장하면
- Then 새 솥은 목표 300석, 진행도 5석에서 시작한다

**POT-01-12 연장해도 공양미 유지**
- Given A의 잔액이 120석이다
- When 방장이 연장하면
- Then A의 잔액은 120석이다

## SHIELD-01 방어권 구매

상태: 미구현

### 기능 설명
공양미 100석으로 이마 방어권을 구매합니다. [WF 33·35]

### 입력
- 구매 요청

### 처리 규칙
1. 보유 개수에 제한이 없다. [정책서] 방어권은 결과 발표 뒤에 쓰고 바로 결과에 반영되므로 `사용 중` 상태는 없다. [Q-20]
2. 잔액이 100석 이상이어야 한다. [정책서]
3. 구매 즉시 공양미 장부에 -100석을 기록한다. [정책서]
4. 동시 요청으로 잔액을 넘겨 살 수 없다. [구현 결정]

### 출력
- 방어권 ID
- 변경 후 잔액

### 예외
- `STORE_001` (409): 잔액 부족 또는 음수 (꾸미기 구매와 같은 code)
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 현금 판매 (제공하지 않음)
- 곳간 화면 조회 (송현빈 담당 `GET /api/store`)

### 완료 조건

**SHIELD-01-1 구매**
- Given A의 잔액이 120석이고 방어권이 없다
- When A가 방어권을 사면
- Then 방어권 1개를 보유하고 잔액은 20석이다

**SHIELD-01-2 보유 중에도 구매**
- Given A가 미사용 방어권 1개를 보유했고 잔액이 100석이다
- When A가 다시 사면
- Then 방어권 2개를 보유하고 잔액은 0석이다

**SHIELD-01-3 잔액 부족**
- Given A의 잔액이 90석이다
- When A가 방어권을 사면
- Then 거부한다

**SHIELD-01-4 동시 구매**
- Given A의 잔액이 150석이다
- When 구매 요청 2개가 동시에 오면
- Then 방어권은 1개만 생기고 100석은 한 번만 차감된다

## SHIELD-02 방어권 사용

상태: 미구현

### 기능 설명
결과에서 지목된 사용자가 결과를 처음 본 때부터 2분 안에 그 회차에 방어권을 사용합니다. [디자인 p92·p96] [Q-75]

### 입력
- 회차 ID

### 처리 규칙
1. 보유 중인 방어권이 있어야 한다. [정책서]
2. 그 회차 결과가 `PICKED`이고 요청한 사용자가 지목된 사람이어야 한다. [Q-75]
3. 지목된 사람이 그 결과를 처음 조회한 시각부터 2분 안이어야 한다. 서버는 지목된 사람이 결과를 처음 조회한 시각을 회차에 기록한다. (RESULT-02) [Q-75] [구현 결정] 결과를 조회하지 않고 바로 쓰면 그 요청 시각을 처음 조회 시각으로 기록한다. [구현 결정] 결과를 계속 열지 않을 때 방어 기회가 언제 끝나는지는 [미정] Q-77
4. 사용 횟수에 제한이 없다. [정책서]
5. 사용 즉시 보유한 방어권 하나를 소모하고 회차 결과를 `DEFENDED`로 바꾼다. 차순위 후보에게 지목을 넘기지 않는다. (RESULT-01) [정책서] [Q-75]
6. 방어하면 그 회차 번뇌 완료 보상(10석)을 받지 않는다. (RICE-01 7번) [정책서]
7. 다른 멤버는 2분을 기다리지 않고 바로 톡톡을 보낼 수 있다. 방어하면 그 회차에 보낸 톡톡은 무효가 되어 재생하지 않는다. (RESULT-03) [Q-75]
8. 인증하지 않아 `인증 안 함`으로 지목된 사람도 쓸 수 있는지는 [미정] Q-76
9. 이미 이 회차에 방어권을 쓴 지목된 사람이 다시 요청하면 방어권을 더 쓰지 않고 성공으로 돌려준다. 재시도해도 안전하다. [구현 결정]
10. 사용할 수 없는 사유가 여럿이면 사용자가 고칠 수 없는 사유부터 하나만 돌려준다: 없는 회차(`ROUND_001`) → 방 멤버 아님(`ROOM_002`) → 발표 전(`RESULT_001`) → 이미 방어함(성공) → 지목된 사람 아님(`DEFENSE_008`) → 방어 시간 지남(`DEFENSE_009`) → 방어권 없음(`DEFENSE_002`). [구현 결정]
11. 동시에 여러 회차에 써도 방어권 하나는 한 번만 소모한다. [구현 결정]

### 출력
- 방어권 사용 기록
- 바뀐 회차 결과

### 예외
- `DEFENSE_002` (409): 보유한 방어권 없음
- `DEFENSE_008` (403): 지목된 사람이 아님. 결과가 `PICKED`가 아닌 회차 포함
- `DEFENSE_009` (409): 방어 시간 지남 (결과를 처음 본 뒤 2분)
- `RESULT_001` (409): 아직 발표 전인 회차
- `ROUND_001` (404): 없는 회차
- `ROOM_002` (403): 이 방 멤버가 아님
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 결과 판정 (RESULT-01)
- 결과 화면의 방어 가능 여부와 마감 시각 (RESULT-02)

### 완료 조건

공통 Given: A는 미사용 방어권 1개를 보유했다. 회차 결과는 A `PICKED`다.

**SHIELD-02-1 사용**
- Given A가 결과를 처음 본 지 1분이 지났다
- When A가 방어권을 쓰면
- Then 방어권이 소모되고 회차 결과는 `DEFENDED`다

**SHIELD-02-2 방어 시간 지남**
- Given A가 결과를 처음 본 지 2분이 지났다
- When A가 방어권을 쓰면
- Then `DEFENSE_009`로 거부하고 결과는 `PICKED`다

**SHIELD-02-3 지목된 사람이 아님**
- Given B는 지목되지 않았고 방어권을 보유했다
- When B가 이 회차에 방어권을 쓰면
- Then `DEFENSE_008`로 거부한다

**SHIELD-02-4 같은 주에 다시 사용**
- Given A가 이번 주 다른 방에서 방어권을 썼고 다시 샀다
- When A가 결과를 본 지 1분 안에 방어권을 쓰면
- Then 사용된다

**SHIELD-02-5 방어권 없음**
- Given A가 방어권을 보유하지 않았다
- When A가 결과를 본 지 1분 안에 방어권을 쓰면
- Then `DEFENSE_002`로 거부한다

**SHIELD-02-6 결과를 보지 않고 바로 사용**
- Given A가 결과를 조회한 적이 없다
- When A가 방어권을 쓰면
- Then 사용되고 그 요청 시각이 처음 조회 시각으로 기록된다

**SHIELD-02-7 방어하면 톡톡 무효**
- Given B가 A에게 톡톡 5번을 보냈다
- When A가 2분 안에 방어권을 쓰면
- Then 결과는 `DEFENDED`이고 A가 받은 톡톡 조회는 빈 목록이다

**SHIELD-02-8 같은 요청 반복**
- Given A가 이 회차에 방어권을 썼다
- When 같은 사용 요청이 다시 오면
- Then 성공하고 방어권은 한 번만 소모된다

**SHIELD-02-9 방어권 하나로 두 방에서 동시 사용**
- Given A가 방어권 1개로 두 방에서 모두 지목됐고 두 결과를 처음 본 지 1분 안이다
- When 두 방에서 동시에 방어권을 쓰면
- Then 한 방에서만 사용된다

**SHIELD-02-10 사유가 여럿**
- Given B는 지목되지 않았고 방어권을 보유하지 않았다
- When B가 이 회차에 방어권을 쓰면
- Then `DEFENSE_008`로 거부한다

**SHIELD-02-11 방어권 두 개로 두 방에서 사용**
- Given A가 방어권 2개로 두 방에서 모두 지목됐고 두 결과를 처음 본 지 1분 안이다
- When 두 방에서 방어권을 쓰면
- Then 두 방 모두 `DEFENDED`이고 보유한 방어권은 0개다
