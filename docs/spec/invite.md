# 초대 · 입장

방은 비공개이고 초대 링크로만 들어옵니다. 멤버마다 초대 토큰이 하나 있어서 미리보기에 초대한 사람을 보여줍니다. 방 나가기와 내보내기는 [`room-membership.md`](room-membership.md)를 따릅니다.

## INVITE-01 초대 토큰

상태: 미구현

### 기능 설명
내 초대 토큰을 돌려줍니다. 클라이언트는 이 토큰으로 공유 링크를 만듭니다. [WF 46]

### 입력
- 방 ID

### 처리 규칙
1. 현재 멤버 누구나 받을 수 있다. [PRD]
2. 토큰이 없으면 만들고, 있으면 그대로 돌려준다. [PRD]
3. 토큰은 추측할 수 없는 임의 값으로 만든다. [구현 결정]
4. 토큰에 만료 시각은 없고 방이 삭제될 때 쓸 수 없게 된다. [PRD]
5. 나간 지 6개월 안에 다시 들어오면 같은 토큰을 쓰고, 지나서 들어오면 새 토큰을 쓴다. [PRD]
6. 같은 멤버의 요청이 동시에 와도 토큰은 하나다. [구현 결정]

### 출력
- 초대 토큰

### 예외
- `ROOM_002` (403): 이 방 멤버가 아님
- `ROOM_005` (404): 없거나 삭제된 방
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 공유 링크 생성과 공유 시트 (클라이언트)
- 멤버당 링크 여러 개

### 완료 조건

**INVITE-01-1 처음 발급**
- Given A의 토큰이 없다
- When A가 초대 토큰을 요청하면
- Then 토큰을 만들어 돌려준다

**INVITE-01-2 재사용**
- Given A의 토큰이 있다
- When A가 다시 요청하면
- Then 같은 토큰을 돌려준다

**INVITE-01-3 멤버가 아님**
- Given D가 이 방의 멤버가 아니다
- When D가 초대 토큰을 요청하면
- Then `ROOM_002`를 돌려준다

**INVITE-01-4 동시 요청**
- Given A의 토큰이 없다
- When 토큰 요청 2개가 동시에 오면
- Then 두 응답의 토큰이 같다

## INVITE-02 미리보기 · 입장 판단

상태: 미구현

### 기능 설명
초대 링크를 연 사용자가 들어갈 수 있는지 판단하고 미리보기 정보를 돌려줍니다. 막힌 경우도 성공 응답의 상태 값으로 화면을 나눕니다. [WF 02·43·66·67]

### 입력
- 초대 토큰

### 처리 규칙
1. 아래 순서로 판단하고 처음 걸린 상태를 돌려준다. [PRD]
   1. 방이 삭제됐거나 초대한 사람이 내보내졌다: `UNAVAILABLE` [WF 67]
   2. 이미 이 방 멤버다: `ALREADY_MEMBER`
   3. 내가 이 방에서 내보내졌다: `UNAVAILABLE` [WF 67]
   4. 참여 중인 방이 2개다: `ROOM_LIMIT` [WF 43]
   5. 방 인원이 함께할 인원만큼 찼다: `ROOM_FULL` [WF 66] [Q-50]
   6. 모두 통과했다: `JOINABLE` [WF 02]
2. 없는 토큰은 `UNAVAILABLE`로 돌려준다. [구현 결정]
3. `UNAVAILABLE`이면 방 정보를 비워서 돌려주고 사유는 표시하지 않는다. [PRD] [구현 결정]
4. 초대한 사람이 현재 멤버면 닉네임을 돌려준다. [PRD]
5. 초대한 사람이 스스로 나갔으면 링크는 유지하고 닉네임은 비워서 돌려준다. 내 데이터 삭제로 나간 경우도 같다. [PRD] [구현 결정]
6. 방이 가득 차도 링크는 유지한다. 자리가 나면 같은 링크로 들어올 수 있다. [PRD]
7. 나간 지 6개월이 지나지 않은 방이면 내 예전 닉네임을 돌려준다. [PRD]

### 출력
- 상태: `JOINABLE`, `ALREADY_MEMBER`, `ROOM_LIMIT`, `ROOM_FULL`, `UNAVAILABLE`
- 방: 방 ID, 이름, 목표, 인원 수, 함께할 인원
- 초대한 사람 닉네임
- 내 예전 닉네임

### 예외
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 입장 처리 (INVITE-03)
- 초대 코드 입력 (MVP 제외)

### 완료 조건

**INVITE-02-1 입장 가능**
- Given 함께할 인원이 4명인 방에 3명이 있고 D의 참여 방이 1개다
- When D가 A의 초대 링크를 열면
- Then `JOINABLE`과 방 정보, A의 닉네임을 돌려준다

**INVITE-02-2 삭제된 방**
- Given 방이 삭제됐다
- When D가 초대 링크를 열면
- Then `UNAVAILABLE`을 돌려주고 방 정보는 비어 있다

**INVITE-02-3 없는 토큰**
- Given 어떤 멤버의 토큰도 아닌 값이다
- When D가 초대 링크를 열면
- Then `UNAVAILABLE`을 돌려준다

**INVITE-02-4 초대한 사람이 내보내짐**
- Given A가 내보내졌다
- When D가 A의 초대 링크를 열면
- Then `UNAVAILABLE`을 돌려준다

**INVITE-02-5 초대한 사람이 스스로 나감**
- Given A가 스스로 나갔다
- When D가 A의 초대 링크를 열면
- Then `JOINABLE`을 돌려주고 초대한 사람 닉네임은 비어 있다

**INVITE-02-6 이미 멤버**
- Given B가 이 방 멤버다
- When B가 초대 링크를 열면
- Then `ALREADY_MEMBER`를 돌려준다

**INVITE-02-7 내가 내보내진 방**
- Given D가 이 방에서 내보내졌다
- When D가 다른 멤버의 초대 링크를 열면
- Then `UNAVAILABLE`을 돌려준다

**INVITE-02-8 방 2개**
- Given D의 참여 방이 2개이고 이 방이 가득 찼다
- When D가 초대 링크를 열면
- Then `ROOM_LIMIT`을 돌려준다

**INVITE-02-9 방이 가득 참**
- Given 함께할 인원이 4명인 방에 4명이 있고 D의 참여 방이 1개다
- When D가 초대 링크를 열면
- Then `ROOM_FULL`을 돌려준다

**INVITE-02-10 자리가 난 뒤 같은 링크**
- Given 방이 가득 차서 `ROOM_FULL`을 받았다
- When 멤버 1명이 나간 뒤 같은 링크를 열면
- Then `JOINABLE`을 돌려준다

**INVITE-02-11 예전 닉네임**
- Given D가 `지수`로 있다가 나간 지 5개월 됐다
- When D가 초대 링크를 열면
- Then 내 예전 닉네임 `지수`를 돌려준다

**INVITE-02-12 6개월이 지난 예전 닉네임**
- Given D가 나간 지 7개월 됐다
- When D가 초대 링크를 열면
- Then 내 예전 닉네임은 비어 있다

**INVITE-02-13 설정한 인원보다 적은 방**
- Given 함께할 인원이 3명인 방에 3명이 있고 D의 참여 방이 1개다
- When D가 초대 링크를 열면
- Then `ROOM_FULL`을 돌려준다

## INVITE-03 입장

상태: 미구현

### 기능 설명
초대 링크로 방에 들어옵니다. 나간 지 6개월 안이면 예전 멤버 행을 다시 씁니다. [WF 03·04]

### 입력
- 초대 토큰
- 닉네임

### 처리 규칙
1. INVITE-02와 같은 순서로 다시 확인한다. 미리보기와 입장 사이에 자리가 찰 수 있다. [PRD]
2. `UNAVAILABLE`은 `ROOM_006`, `ROOM_LIMIT`은 `ROOM_001`, `ROOM_FULL`은 `ROOM_003`을 돌려준다. [구현 결정]
3. 이미 멤버면 새로 만들지 않고 기존 멤버 정보를 돌려준다. [구현 결정]
4. 닉네임은 1~8자이고 한글(완성형), 영문, 숫자만 쓸 수 있다. [PRD]
5. 현재 멤버와 나간 지 6개월이 지나지 않은 멤버의 닉네임은 쓸 수 없다. 영문 대소문자는 구분하지 않는다. [PRD]
6. 나간 지 6개월이 지나지 않았으면 예전 멤버 행을 다시 쓴다. 나간 정보를 비우고 들어온 시각을 새로 기록한다. [PRD]
7. 예전 행을 다시 쓰면 지난 기록, 지목 횟수, 연속 지목, 초대 토큰이 이어진다. [PRD]
8. 예전 행을 다시 쓸 때 닉네임 중복 검사에서 내 행은 제외하고, 예전 닉네임과 다른 값도 쓸 수 있다. [PRD]
9. 예전 색상을 다른 멤버가 쓰고 있으면 남은 색 중 랜덤으로 정한다. [PRD]
10. 나간 지 6개월이 지났으면 새 멤버 행을 만든다. 예전 행은 "떠난 보살"로 남는다. [PRD]
11. `left_at + 6개월` 시각까지를 6개월 안으로 본다. 내 데이터 삭제 복구 기준(AUTH-01)과 같다. [구현 결정]
12. 새 멤버의 색상은 방 멤버가 쓰지 않는 색 중 랜덤으로 정한다. [PRD]
13. 들어올 때 결과·한 솥 확인 상태를 현재 값으로 채운다. 다시 들어올 때도 같다. (RESULT-02, POT-01) [PRD]
14. 오늘 회차가 인증 중이면 이번 회차부터, 투표가 시작됐으면 다음 회차부터 참여한다. [PRD]
15. 들어와도 이미 시작된 투표 명단은 바뀌지 않는다. [PRD]
16. 동시에 입장해도 함께할 인원, 참여 방 2개, 닉네임·색상 중복을 넘지 않는다. [PRD]
17. 입장을 언제 처리할지는 [미정] Q-38. 기획 문서는 [참여하기]를 누를 때 확인하고, 프론트 협의안은 WF 03 제출 때 입장까지 한 번에 처리한다.

### 출력
- 방 ID
- 내 멤버 ID, 닉네임, 색상

### 예외
- `ROOM_001` (409): 참여 중인 방이 2개
- `ROOM_003` (409): 방이 가득 참
- `ROOM_004` (409): 이미 쓰는 닉네임 (`field: nickname`)
- `ROOM_006` (403): 들어갈 수 없는 방
- `COMMON_002` (400): 입력값 오류
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 나간 사람의 지난 기록 표시 방식 ("떠난 보살"은 각 조회 기능에서 처리)
- 입장 알림

### 완료 조건

**INVITE-03-1 입장**
- Given `JOINABLE` 상태다
- When D가 닉네임으로 입장하면
- Then 멤버가 되고 남은 색 중 하나가 배정된다

**INVITE-03-2 미리보기 뒤 자리가 참**
- Given D가 `JOINABLE`을 받은 뒤 방이 가득 찼다
- When D가 입장하면
- Then `ROOM_003`을 돌려준다

**INVITE-03-3 내보내진 사람**
- Given D가 이 방에서 내보내졌다
- When D가 입장하면
- Then `ROOM_006`을 돌려주고 멤버를 만들지 않는다

**INVITE-03-4 참여 방 2개**
- Given D의 참여 방이 2개다
- When D가 입장하면
- Then `ROOM_001`을 돌려준다

**INVITE-03-5 이미 멤버**
- Given B가 이 방 멤버다
- When B가 입장을 다시 요청하면
- Then 새 멤버를 만들지 않고 기존 멤버 정보를 돌려준다

**INVITE-03-6 닉네임 중복**
- Given 같은 방에 `Jisu`가 있다
- When D가 `jisu`로 입장하면
- Then `ROOM_004`를 돌려준다

**INVITE-03-7 6개월 안에 다시 들어옴**
- Given D가 `지수`로 나간 지 5개월 됐고 연속 지목이 2다
- When D가 `지수`로 입장하면
- Then 같은 멤버 행이 현재 멤버가 되고 연속 지목은 2다

**INVITE-03-8 다시 들어오며 닉네임 변경**
- Given D가 `지수`로 나간 지 5개월 됐다
- When D가 `지수2`로 입장하면
- Then 같은 멤버 행의 닉네임이 `지수2`로 바뀐다

**INVITE-03-9 색상이 겹침**
- Given D가 `MINT`로 나갔고 지금 다른 멤버가 `MINT`다
- When D가 6개월 안에 다시 들어오면
- Then 현재 멤버가 쓰지 않는 색이 배정된다

**INVITE-03-10 색상이 안 겹침**
- Given D가 `MINT`로 나갔고 지금 `MINT`를 쓰는 멤버가 없다
- When D가 6개월 안에 다시 들어오면
- Then D의 색상은 `MINT`다

**INVITE-03-11 6개월이 지나 다시 들어옴**
- Given D가 나간 지 7개월 됐다
- When D가 입장하면
- Then 새 멤버 행이 생기고 예전 행은 나간 상태로 남는다

**INVITE-03-12 들어오기 전 결과와 축하**
- Given 방에 발표된 결과가 있고 한 솥이 2번 완성됐다
- When D가 입장한 뒤 오늘 탭을 조회하면
- Then 안 본 결과와 안 본 축하가 없다

**INVITE-03-13 인증 중에 입장**
- Given 어제 회차는 투표 중이고 오늘 회차는 인증 중이다
- When D가 입장하면
- Then D는 오늘 회차에 인증할 수 있고 어제 회차 명단에는 없다

**INVITE-03-14 오늘 투표가 시작된 뒤 입장**
- Given 오늘 회차가 전원 인증으로 투표 중이다
- When D가 입장하면
- Then 오늘 회차 명단은 그대로이고 D는 다음 회차부터 참여한다

**INVITE-03-15 마지막 자리에 동시 입장**
- Given 함께할 인원이 4명인 방에 3명이 있다
- When D와 E가 동시에 입장하면
- Then 1명만 멤버가 되고 다른 1명은 `ROOM_003`을 받는다

**INVITE-03-16 방 2개에 동시 입장**
- Given D의 참여 방이 1개다
- When D가 서로 다른 두 방에 동시에 입장하면
- Then 1개 방에만 들어가고 다른 요청은 `ROOM_001`을 받는다

**INVITE-03-17 투표 시작을 기다리는 회차에 입장**
- Given 어제 회차가 투표 중이고 오늘 회차는 전원 인증해 시작을 기다린다
- When D가 입장한 뒤 어제 회차가 마감되면
- Then 오늘 회차는 전원 인증 상태가 아니므로 투표를 시작하지 않고 D는 오늘 회차에 인증할 수 있다

**INVITE-03-18 다시 들어오면 지난 기록 복원**
- Given D가 나가서 지난 기록이 "떠난 보살"로 보인다
- When D가 6개월 안에 다시 들어오면
- Then 지난 기록이 D의 닉네임으로 보인다
