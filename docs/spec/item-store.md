# 곳간 · 꾸미기 아이템

곳간 화면과 꾸미기 아이템의 구매, 착용을 다룹니다. 공양미 장부는 RICE-01, RICE-02를 쓰고 따로 만들지 않습니다. 방어권 구매와 사용은 SHIELD-01, SHIELD-02를 따릅니다.

## STORE-01 곳간 조회

상태: 미구현

### 기능 설명
공양미 잔액, 방어권 상태, 꾸미기 아이템 목록을 돌려줍니다. [WF 33·34·35·38]

### 입력
- 로그인한 사용자

### 처리 규칙
1. 공양미는 화면 표시 잔액으로 돌려준다. (RICE-01) [WF 33]
2. 아이템은 상점 노출 순서대로 돌려준다. [구현 결정]
3. 아이템마다 보유 여부와 착용 여부를 돌려준다. [PRD]
4. 방어권 상태는 `NONE`, `OWNED`, `IN_USE`로 돌려준다. [PRD]
5. `IN_USE`는 방어권을 쓴 회차의 결과 발표 전까지이고 쓴 방의 이름을 함께 돌려준다. [PRD] 결과 발표 전에 그 방이 삭제되면 `IN_USE`를 끝낸다. 방어권은 소모된 상태로 남는다. (ROOM-07) [구현 결정]
6. `IN_USE`일 때 방어권을 더 살 수 있는지는 [미정] Q-20
7. 이번 주에 방어권을 썼는지 돌려준다. [PRD]

### 출력
- 공양미 표시 잔액
- 방어권: 상태, 사용 중인 방 이름, 이번 주 사용 여부
- 아이템 목록: 아이템 ID, 코드, 이름, 가격, 슬롯, 보유 여부, 착용 여부

### 예외
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 방어권 구매와 사용 (SHIELD-01, SHIELD-02)
- 방어권 방 선택 시트
- 곳간의 보살 표시 (클라이언트가 기기에 저장한 방과 USER-01 방 목록으로 표시)

### 완료 조건

**STORE-01-1 곳간 조회**
- Given A가 아이템 1개를 보유하고 착용했다
- When 곳간을 조회하면
- Then 아이템 6종이 노출 순서대로 오고 그 아이템만 보유·착용으로 표시된다

**STORE-01-2 음수 잔액**
- Given A의 장부 합계가 -10석이다
- When 곳간을 조회하면
- Then 공양미 표시 잔액은 0석이다

**STORE-01-3 방어권 보유**
- Given A가 미사용 방어권을 보유했다
- When 곳간을 조회하면
- Then 방어권 상태는 `OWNED`다

**STORE-01-4 방어권 사용 중**
- Given A가 방 1의 이번 회차에 방어권을 썼고 결과 발표 전이다
- When 곳간을 조회하면
- Then 방어권 상태는 `IN_USE`이고 사용 중인 방 이름은 방 1이다

**STORE-01-5 결과 발표 후**
- Given A가 쓴 방어권의 회차 결과가 발표됐고 보유한 방어권이 없다
- When 곳간을 조회하면
- Then 방어권 상태는 `NONE`이고 이번 주 사용 여부는 true다

**STORE-01-6 방어권을 쓴 방이 삭제됨**
- Given A가 이번 주 방 1의 회차에 방어권을 썼고 결과 발표 전에 방 1이 삭제됐으며, 그 뒤 방어권을 다시 사지 않았다
- When 곳간을 조회하면
- Then 방어권 상태는 `NONE`이고 이번 주 사용 여부는 true다

## STORE-02 아이템 구매

상태: 미구현

### 기능 설명
공양미로 꾸미기 아이템을 사고 바로 착용합니다. [WF 34]

### 입력
- 아이템 ID

### 처리 규칙
1. 아이템은 6종이다: 50석 (루돌프 코, 목도리, "절약왕" 띠), 100석 (산타 모자, 돼지저금통 모자, 영수증 왕관) [PRD]
2. 없는 아이템, 이미 보유, 잔액 부족 순서로 확인한다. [구현 결정]
3. 한 번 사면 영구 보유한다. [PRD]
4. 잔액이 가격 이상이어야 한다. 음수 잔액이면 살 수 없다. (RICE-02) [PRD]
5. 구매 즉시 공양미 장부에 가격만큼 차감을 기록한다. [PRD]
6. 사면 바로 착용하고, 같은 슬롯에 끼고 있던 아이템은 벗긴다. [PRD]
7. 동시 요청으로 잔액을 넘겨 사거나 같은 아이템을 두 번 살 수 없다. [구현 결정]

### 출력
- 공양미 표시 잔액
- 구매 뒤 착용 중인 아이템 ID 목록

### 예외
- `STORE_001` (409): 공양미 부족
- `STORE_002` (404): 없는 아이템
- `STORE_003` (409): 이미 보유
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 공양미 장부 구현 (RICE-01, RICE-02)
- 인앱 결제 (MVP 제외)
- 슬롯·아이템 추가 (P1)

### 완료 조건

**STORE-02-1 구매**
- Given A의 잔액이 120석이다
- When A가 100석 아이템을 사면
- Then 보유·착용 상태가 되고 잔액은 20석이다

**STORE-02-2 잔액과 가격이 같음**
- Given A의 잔액이 50석이다
- When A가 50석 아이템을 사면
- Then 구매되고 잔액은 0석이다

**STORE-02-3 끼고 있던 아이템 벗김**
- Given A가 아이템 X를 착용 중이다
- When A가 아이템 Y를 사면
- Then Y만 착용 상태이고 X는 보유 상태로 남는다

**STORE-02-4 잔액 부족**
- Given A의 잔액이 90석이다
- When A가 100석 아이템을 사면
- Then `STORE_001`을 돌려주고 장부에 기록하지 않는다

**STORE-02-5 음수 잔액**
- Given A의 장부 합계가 -5석이다
- When A가 50석 아이템을 사면
- Then `STORE_001`을 돌려준다

**STORE-02-6 없는 아이템**
- Given 없는 아이템 ID다
- When A가 구매하면
- Then `STORE_002`를 돌려준다

**STORE-02-7 이미 보유**
- Given A가 아이템 X를 보유했다
- When A가 X를 다시 사면
- Then `STORE_003`을 돌려주고 잔액은 그대로다

**STORE-02-8 같은 아이템 동시 구매**
- Given A의 잔액이 200석이다
- When 100석 아이템 X의 구매 요청 2개가 동시에 오면
- Then 1번만 구매되고 100석만 차감된다

**STORE-02-9 다른 아이템 동시 구매**
- Given A의 잔액이 120석이다
- When 서로 다른 100석 아이템의 구매 요청 2개가 동시에 오면
- Then 1개만 구매되고 다른 요청은 `STORE_001`을 받는다

## STORE-03 착용 · 벗기

상태: 미구현

### 기능 설명
착용할 아이템 목록을 받아 착용 상태를 통째로 바꿉니다. 착용은 모든 방에 같이 보입니다. [WF 18·34]

### 입력
- 착용할 아이템 ID 목록 (비어 있으면 모두 벗기)

### 처리 규칙
1. 보낸 목록으로 착용 상태를 바꾼다. 목록에 없는 아이템은 벗긴다. [구현 결정]
2. 보유한 아이템만 착용할 수 있다. 없는 아이템도 보유하지 않은 아이템으로 본다. [구현 결정]
3. 슬롯마다 하나만 착용한다. 같은 슬롯의 아이템을 둘 이상 보내면 `COMMON_002`를 돌려준다. [PRD] [구현 결정]
4. 빈 목록이면 착용 중인 아이템을 모두 벗긴다. [PRD]
5. 착용은 사용자 단위라 모든 방에 같이 적용한다. [PRD]
6. 착용은 투표와 벌칙에 영향을 주지 않는다. [PRD]
7. 동시에 요청해도 한 요청의 목록으로만 저장되고 슬롯마다 하나다. [구현 결정]
8. 슬롯은 지금 머리 위(`HEAD`) 1칸이다. 칸을 늘릴지는 [미정] Q-53

### 출력
- 없음

### 예외
- `STORE_004` (409): 보유하지 않은 아이템 착용
- `COMMON_002` (400): 같은 슬롯 아이템 중복 등 입력값 오류
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 방마다 다른 착용
- 사기 전 미리 착용해 보기 (클라이언트 처리)

### 완료 조건

**STORE-03-1 착용**
- Given A가 아이템 X를 보유했고 착용 중이 아니다
- When [X]를 보내면
- Then X가 착용 상태다

**STORE-03-2 다른 아이템으로 교체**
- Given A가 X를 착용 중이고 같은 슬롯의 Y를 보유했다
- When [Y]를 보내면
- Then Y만 착용 상태다

**STORE-03-3 모두 벗기**
- Given A가 X를 착용 중이다
- When 빈 목록을 보내면
- Then 착용 중인 아이템이 없다

**STORE-03-4 보유하지 않은 아이템**
- Given A가 Y를 보유하지 않았다
- When [Y]를 보내면
- Then `STORE_004`를 돌려주고 착용 상태는 그대로다

**STORE-03-5 모든 방에 적용**
- Given A가 방 2개에 참여 중이다
- When [X]를 보내면
- Then 두 방의 오늘 탭에서 A의 착용 아이템 목록이 [X]다

**STORE-03-6 동시 요청**
- Given A가 같은 슬롯의 X와 Y를 보유했다
- When [X]와 [Y] 요청이 동시에 오면
- Then 착용 상태인 아이템은 X와 Y 중 하나다

**STORE-03-7 같은 슬롯 중복**
- Given A가 같은 슬롯의 X와 Y를 보유했다
- When [X, Y]를 보내면
- Then `COMMON_002`를 돌려주고 착용 상태는 그대로다
