# 로그인 · 토큰

앱인토스 익명 식별키로 사용자를 구분합니다. 로그인 화면과 약관 동의 화면은 없습니다. 챌린지의 `인증`과 구분하기 위해 기능 ID는 `AUTH`를 씁니다.

## AUTH-01 로그인

상태: 미구현

### 기능 설명
앱인토스 일회용 인증 코드로 사용자를 확인하고 서비스 토큰을 발급합니다. 처음 온 사용자는 새로 만듭니다.

### 입력
- `authorizationCode`: 앱인토스에서 받은 일회용 코드 (5분, 1회용)

### 처리 규칙
1. 인증 코드를 앱인토스 `anon-key/exchange` API(mTLS)로 교환해 `anonKey`를 받는다. [PRD]
2. 클라이언트가 보낸 `anonKey`는 받지 않는다. [PRD]
3. `anonKey`로 사용자를 찾고, 없으면 새로 만든다. [PRD]
4. 이름, 전화번호 등 개인정보는 받지 않는다. [PRD]
5. 삭제 후 6개월 안에 돌아온 사용자는 복구하고 공양미, 아이템, 방어권을 유지한다. [PRD] 복구한 사용자의 `isNewUser`는 `false`다. [구현 결정]
6. 삭제 후 6개월이 지난 사용자는 기존 정보를 정리하고 신규 사용자로 처리한다. [PRD]
7. 같은 `anonKey`로 동시에 로그인해도 사용자는 1명만 만든다. [구현 결정]
8. 유효 시간 3600초의 액세스 토큰을 발급한다. [구현 결정] [미정] Q-16

### 출력
- `accessToken`: 서비스 액세스 토큰
- `expiresIn`: 유효 시간(초)
- `isNewUser`: 새로 만든 사용자 여부 (복구한 사용자는 `false`)

### 예외
- `AUTH_001` (400): 인증 코드가 틀렸거나 만료됨
- `AUTH_002` (502): 앱인토스 호출 실패
- `COMMON_002` (400): 입력값 오류

### 제외 범위
- 닉네임 설정과 방 입장
- 약관 동의 기록 저장 ([미정] Q-11)

### 완료 조건

**AUTH-01-1 처음 온 사용자**
- Given 해당 `anonKey`의 사용자가 없다
- When 유효한 인증 코드로 로그인하면
- Then 사용자를 만들고 토큰과 `isNewUser: true`를 돌려준다

**AUTH-01-2 기존 사용자**
- Given 해당 `anonKey`의 사용자가 있다
- When 유효한 인증 코드로 로그인하면
- Then 사용자를 새로 만들지 않고 토큰과 `isNewUser: false`를 돌려준다

**AUTH-01-3 6개월 안에 돌아온 사용자**
- Given 삭제한 지 6개월이 지나지 않은 사용자가 있다
- When 같은 `anonKey`로 로그인하면
- Then 사용자를 복구하고 공양미, 아이템, 방어권을 유지하며 `isNewUser: false`를 돌려준다

**AUTH-01-4 6개월이 지난 사용자**
- Given 삭제한 지 6개월이 지난 사용자가 있다
- When 같은 `anonKey`로 로그인하면
- Then 신규 사용자로 처리하고 `isNewUser: true`를 돌려준다

**AUTH-01-5 잘못된 인증 코드**
- Given 틀렸거나 만료된 인증 코드가 있다
- When 로그인하면
- Then `AUTH_001`을 돌려주고 사용자를 만들지 않는다

**AUTH-01-6 앱인토스 호출 실패**
- Given 앱인토스 API 호출이 실패한다
- When 로그인하면
- Then `AUTH_002`를 돌려주고 사용자를 만들지 않는다

**AUTH-01-7 동시 첫 로그인**
- Given 해당 `anonKey`의 사용자가 없다
- When 같은 `anonKey`로 로그인 요청이 동시에 오면
- Then 사용자는 1명만 만들어진다

## AUTH-02 토큰 인증

상태: 미구현

### 기능 설명
로그인을 뺀 API 요청의 액세스 토큰을 검증합니다.

### 입력
- `Authorization: Bearer {accessToken}` 헤더

### 처리 규칙
1. `POST /api/auth/login`을 뺀 API는 토큰이 필요하다. [구현 결정]
2. 토큰이 없거나 유효하지 않거나 만료되면 `COMMON_008`을 돌려준다. [구현 결정]
3. 토큰이 만료되면 클라이언트가 인증 코드를 다시 받아 로그인한다. [구현 결정] [미정] Q-16
4. 내 데이터를 삭제한 사용자의 토큰은 만료 전이어도 거절하고 `COMMON_008`을 돌려준다. [구현 결정]

### 출력
- 인증된 사용자 정보를 요청 처리에 전달

### 예외
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 리프레시 토큰 재발급

### 완료 조건

**AUTH-02-1 유효한 토큰**
- Given 유효한 액세스 토큰이 있다
- When 토큰이 필요한 API를 호출하면
- Then 요청을 처리한다

**AUTH-02-2 토큰 없음**
- Given 토큰이 없다
- When 토큰이 필요한 API를 호출하면
- Then `COMMON_008`을 돌려준다

**AUTH-02-3 만료된 토큰**
- Given 만료된 액세스 토큰이 있다
- When 토큰이 필요한 API를 호출하면
- Then `COMMON_008`을 돌려준다

**AUTH-02-4 삭제한 사용자의 토큰**
- Given 내 데이터를 삭제한 사용자의 만료 전 토큰이 있다
- When 토큰이 필요한 API를 호출하면
- Then `COMMON_008`을 돌려준다
