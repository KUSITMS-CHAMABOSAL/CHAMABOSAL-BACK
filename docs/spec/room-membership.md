# 방 · 멤버

방 만들기, 오늘 탭, 닉네임, 나가기, 내보내기를 다룹니다. 수치와 회차 상태는 [`common.md`](common.md), 입장은 [`invite.md`](invite.md)를 따릅니다. 알림 카드 닫음은 기기에 저장하므로 서버 기능이 없고 ROOM-05는 비워 둡니다. (Q-39) 멤버 프로필과 방 정보는 오늘 탭의 멤버 목록으로 그리므로 ROOM-03은 비워 둡니다.

## ROOM-01 방 만들기

상태: 미구현

### 기능 설명
방을 만들고 만든 사람을 방장 멤버로 등록합니다. [WF 45·03·04]

### 입력
- 방 이름
- 절약 목표: `DELIVERY`, `CAFE`, `SHOPPING`, `ETC`
- 함께할 인원: 2~4명
- 닉네임

### 처리 규칙
1. 참여 중인 방이 2개면 만들 수 없다. [PRD]
2. 방 이름 앞뒤 띄어쓰기는 저장할 때 제거하고, 제거한 값으로 글자 수를 검사한다. [PRD] [구현 결정]
3. 방 이름은 1~12자이고 한글(완성형), 영문, 숫자, 띄어쓰기만 쓸 수 있다. [PRD]
4. 방 이름은 만든 뒤 수정할 수 없다. [PRD]
5. `ETC`는 입력 칸 없이 그대로 저장한다. [PRD]
6. 닉네임은 1~8자이고 한글(완성형), 영문, 숫자만 쓸 수 있다. [PRD]
7. 만든 사람을 방장으로 등록한다. [PRD]
8. 보살 색상은 서버가 4종 중 랜덤으로 정한다. [PRD]
9. 방을 만든 날부터 첫 회차가 시작된다. 그 회차의 인증은 만든 시각부터 받는다. [PRD]
10. 같은 사용자의 동시 요청으로 참여 방이 2개를 넘지 않는다. [구현 결정]
11. 방을 언제 만들지는 [미정] Q-37. 기획 문서는 WF 45에서 방을 만들고 WF 03에서 뒤로 가면 삭제하며, 프론트 협의안은 WF 03 제출 때 방과 멤버를 한 번에 만든다.
12. 함께할 인원은 2~4명이고 만든 뒤 수정할 수 없다. [Q-50]

### 출력
- 방 ID
- 내 멤버 ID, 닉네임, 색상

### 예외
- `ROOM_001` (409): 참여 중인 방이 2개
- `COMMON_002` (400): 입력값 오류
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 초대 링크 공유 (INVITE-01)
- 방 이름 수정, 초대 코드 입력 (MVP 제외)
- 빈 방 정리 (CLEAN-03)

### 완료 조건

**ROOM-01-1 방 만들기**
- Given A의 참여 방이 1개다
- When 방 이름, 목표, 함께할 인원, 닉네임으로 방을 만들면
- Then 방이 생기고 A가 방장 멤버가 되며 색상이 배정된다

**ROOM-01-2 방 2개 제한**
- Given A의 참여 방이 2개다
- When 방을 만들면
- Then `ROOM_001`을 돌려주고 방을 만들지 않는다

**ROOM-01-3 방 이름 앞뒤 띄어쓰기**
- Given 방 이름이 ` 배달 끊기 `다
- When 방을 만들면
- Then 방 이름은 `배달 끊기`로 저장된다

**ROOM-01-4 띄어쓰기만 입력**
- Given 방 이름이 띄어쓰기로만 되어 있다
- When 방을 만들면
- Then `COMMON_002`를 돌려준다

**ROOM-01-5 잘못된 닉네임**
- Given 닉네임에 이모지나 자모 단독 글자가 있다
- When 방을 만들면
- Then `COMMON_002`를 돌려준다

**ROOM-01-6 만든 날 첫 회차**
- Given A가 오늘 20:00에 방을 만들었다
- When A가 20:10에 인증하면
- Then 오늘 회차의 인증으로 등록된다

**ROOM-01-7 동시 생성**
- Given A의 참여 방이 1개다
- When 방 만들기 요청 2개가 동시에 오면
- Then 방은 1개만 더 생긴다

**ROOM-01-8 잘못된 함께할 인원**
- Given 함께할 인원이 1명 또는 5명이다
- When 방을 만들면
- Then `COMMON_002`를 돌려주고 방을 만들지 않는다

## ROOM-02 오늘 탭

상태: 미구현

### 기능 설명
방 정보, 한 솥 진행도, 오늘 회차의 멤버별 인증 상태를 돌려줍니다. [WF 05·06·49]

### 입력
- 방 ID

### 처리 규칙
1. 현재 멤버만 조회할 수 있다. [PRD]
2. 삭제된 방은 `ROOM_005`, 멤버가 아니면 `ROOM_002`를 돌려준다. 두 경우 모두 화면은 WF 72다. [PRD] [구현 결정]
3. 회차 날짜가 오늘인 회차를 기준으로 돌려준다. 전원 인증으로 투표가 시작돼도 오늘 회차를 돌려준다. [구현 결정]
4. 오늘 회차 행이 아직 없어도 인증 0명인 회차로 돌려준다. 조회할 때 행을 만들지 않고 회차 ID는 비워서 돌려준다. 행은 첫 인증이나 첫 콕 때 만든다. (POKE-01) [구현 결정]
5. 인증 전인 멤버의 인증 정보는 비워서 돌려준다. [구현 결정]
6. 인증 수정·삭제 잠금 사유는 `TIME_OVER`, `VOTE_STARTED`로 구분한다. (CERT-03) [PRD] 수정 마감 시각도 함께 돌려준다. [구현 결정]
7. 리액션은 내 리액션만 돌려주고 누가 눌렀는지는 돌려주지 않는다. (REACT-01) [PRD] 받은 수는 화면에 없어 돌려주지 않는다. [미정] Q-52
8. 사진 URL은 응답할 때마다 만들고, 삭제된 사진은 비워서 돌려준다. (CERT-04) [구현 결정]
9. 받은 콕은 받은 수만 나에게 돌려준다. 누가 찔렀는지는 돌려주지 않는다. (POKE-01) [PRD] [구현 결정]
10. 등록하면 전원 인증이 되는 멤버에게는 마지막 인증자임을 돌려준다. [WF 55]
11. 방어권 사용 여부는 돌려주지 않는다. 다른 멤버의 사용 여부는 결과 발표 전까지 숨긴다. (SHIELD-02) [PRD] [구현 결정]
12. 멤버의 이번 달 참은 횟수, 이번 달 지목 횟수, 착용 아이템 목록을 함께 돌려준다. 멤버 프로필과 방 정보 화면에 쓴다. [PRD] [WF 09]
13. 앱을 열 때 재생할 항목으로 받은 톡톡, 안 본 결과, 안 본 한 솥 축하를 돌려준다. 재생 순서는 톡톡, 결과, 축하, 방 홈이다. [PRD]
14. 어제 회차가 투표 중이어도 마지막 인증자로 표시한다. 등록하면 어제 회차 투표가 닫히고 오늘 투표가 시작된다. (VOTE-01) [Q-17]
15. 회차 상태는 `인증 중`, `투표 중`, `발표`, `투표 없음` 중 하나로 돌려준다. 회차 행이 없으면 `인증 중`이다. [구현 결정]
16. 인증한 인원은 현재 멤버 중 오늘 회차에 인증한 사람 수다. 현재 멤버 전원이 인증했으면 전원 인증으로 돌려준다. [구현 결정]
17. 이번 달 참은 횟수와 지목 횟수는 이 방 기록만 센다. 지목은 방어 성공을 세지 않는다. 집계 기준은 USER-02와 같다. [구현 결정]
18. 방에 투표 중인 회차가 있는지 돌려준다. 어제 회차도 포함한다. 방장의 내보내기 버튼 상태에 쓴다. (ROOM-08) [구현 결정]

### 출력
- 방: 방 ID, 이름, 목표, 인원 수, 함께할 인원, 내가 방장인지, 쌀가마 배지, 투표 중인 회차가 있는지
- 한 솥: 진행도, 목표 석
- 회차: 회차 ID, 상태, 인증한 인원, 전원 인증 여부
- 멤버 목록: 멤버 ID, 닉네임, 색상, 착용 아이템 목록, 나인지, 이번 달 참은 횟수, 이번 달 지목 횟수, 인증 정보
- 나: 마지막 인증자 여부, 받은 콕 수
- 진입 항목: 재생할 톡톡 회차, 안 본 결과 회차, 안 본 축하 여부

### 예외
- `ROOM_002` (403): 이 방 멤버가 아님
- `ROOM_005` (404): 없거나 삭제된 방
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 인증, 콕, 리액션 등록
- 투표 탭 (VOTE-05)
- 실시간 갱신 (화면에 들어올 때 다시 조회)
- 알림 카드 표시 판단 (클라이언트가 방 인원 수, 동의 여부, 기기 저장값으로 판단)

### 완료 조건

**ROOM-02-1 멤버별 인증 상태**
- Given 멤버 3명 중 A, B가 인증했다
- When C가 오늘 탭을 조회하면
- Then 인증한 인원은 2이고 C의 인증 정보는 비어 있다

**ROOM-02-2 멤버가 아님**
- Given D가 이 방의 멤버가 아니다
- When D가 오늘 탭을 조회하면
- Then `ROOM_002`를 돌려준다

**ROOM-02-3 삭제된 방**
- Given 방이 삭제됐다
- When 오늘 탭을 조회하면
- Then `ROOM_005`를 돌려준다

**ROOM-02-4 회차가 겹침**
- Given 어제 회차는 투표 중이고 오늘 회차는 인증 중이다
- When 오늘 탭을 조회하면
- Then 오늘 회차를 돌려준다

**ROOM-02-5 전원 인증 뒤**
- Given 오늘 회차가 전원 인증으로 05:00 전에 투표를 시작했다
- When 오늘 탭을 조회하면
- Then 오늘 회차를 `투표 중`, 전원 인증으로 돌려주고 인증 잠금 사유는 `VOTE_STARTED`다

**ROOM-02-6 회차 행 없음**
- Given 오늘 회차 행이 아직 없다
- When 오늘 탭을 조회하면
- Then 회차 ID는 비어 있고 인증한 인원 0명으로 오늘 회차를 돌려준다

**ROOM-02-7 마지막 인증자**
- Given 멤버 3명 중 A, B가 인증했다
- When C가 오늘 탭을 조회하면
- Then C는 마지막 인증자로 표시된다

**ROOM-02-8 방어권 사용 여부 숨김**
- Given A가 이번 회차에 방어권을 썼다
- When B가 오늘 탭을 조회하면
- Then 응답에 A의 방어권 사용 여부가 없다

**ROOM-02-9 어제 회차가 투표 중일 때 마지막 인증**
- Given 어제 회차가 투표 중이고 오늘 회차는 멤버 3명 중 A, B가 인증했다
- When C가 오늘 탭을 조회하면
- Then C는 마지막 인증자로 표시되지 않는다

**ROOM-02-10 전원 인증 뒤 투표 대기**
- Given 어제 회차가 투표 중이고 오늘 회차는 멤버 3명이 모두 인증했다
- When 오늘 탭을 조회하면
- Then 오늘 회차를 `인증 중`, 전원 인증으로 돌려준다

**ROOM-02-11 인증 뒤 나간 멤버**
- Given 멤버 4명 중 A, B가 인증했고 B가 방을 나갔다
- When 오늘 탭을 조회하면
- Then 인증한 인원은 1명이고 전원 인증이 아니다

**ROOM-02-12 이 방 기록만 집계**
- Given B가 이번 달 이 방에서 `참았어요` 2번, 다른 방에서 3번 인증했다
- When A가 오늘 탭을 조회하면
- Then B의 이번 달 참은 횟수는 2다

**ROOM-02-13 방어 성공 제외**
- Given B의 이번 달 이 방 결과가 `PICKED` 1번, `DEFENDED` 1번이다
- When A가 오늘 탭을 조회하면
- Then B의 이번 달 지목 횟수는 1이다

**ROOM-02-14 어제 회차가 투표 중**
- Given 어제 회차가 투표 중이고 오늘 회차는 인증 중이다
- When 오늘 탭을 조회하면
- Then 투표 중인 회차가 있다고 돌려주고 오늘 회차 상태는 `인증 중`이다

## ROOM-04 닉네임 수정

상태: 미구현

### 기능 설명
이 방에서 쓰는 내 닉네임을 바꿉니다. [WF 42]

### 입력
- 방 ID
- 닉네임

### 처리 규칙
1. 현재 멤버만 수정할 수 있다. [PRD]
2. 닉네임은 1~8자이고 한글(완성형), 영문, 숫자만 쓸 수 있다. [PRD]
3. 현재 멤버와 나간 지 6개월이 지나지 않은 멤버의 닉네임은 쓸 수 없다. [PRD]
4. 중복은 영문 대소문자를 구분하지 않고 판단한다. [PRD]
5. 중복 검사에서 내 행은 제외한다. [PRD]
6. 기존 닉네임과 같으면 저장하지 않고 성공으로 돌려준다. [WF 42]
7. 같은 닉네임으로 동시에 요청해도 1명만 성공한다. [PRD]

### 출력
- 없음

### 예외
- `ROOM_002` (403): 이 방 멤버가 아님
- `ROOM_004` (409): 이미 쓰는 닉네임 (`field: nickname`)
- `ROOM_005` (404): 없거나 삭제된 방
- `COMMON_002` (400): 입력값 오류
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 다른 방 닉네임 (방마다 따로 수정)

### 완료 조건

**ROOM-04-1 수정**
- Given A의 닉네임이 `민지`다
- When `민지2`로 수정하면
- Then 닉네임이 바뀐다

**ROOM-04-2 현재 멤버와 중복**
- Given 같은 방에 `Jisu`가 있다
- When A가 `jisu`로 수정하면
- Then `ROOM_004`를 돌려주고 닉네임은 그대로다

**ROOM-04-3 나간 지 6개월 안 된 멤버와 중복**
- Given `하린`이 나간 지 5개월 됐다
- When A가 `하린`으로 수정하면
- Then `ROOM_004`를 돌려준다

**ROOM-04-4 나간 지 6개월 지난 멤버**
- Given `하린`이 나간 지 7개월 됐다
- When A가 `하린`으로 수정하면
- Then 닉네임이 바뀐다

**ROOM-04-5 내 닉네임의 대소문자만 변경**
- Given A의 닉네임이 `jisu`다
- When `Jisu`로 수정하면
- Then 닉네임이 바뀐다

**ROOM-04-6 같은 닉네임**
- Given A의 닉네임이 `민지`다
- When `민지`로 수정하면
- Then 성공하고 닉네임은 그대로다

**ROOM-04-7 동시 수정**
- Given 같은 방의 A와 B가 있다
- When 두 사람이 같은 닉네임으로 동시에 수정하면
- Then 1명만 성공하고 다른 1명은 `ROOM_004`를 받는다

## ROOM-06 결과 · 한 솥 확인

상태: 미구현

### 기능 설명
방에서 결과와 한 솥 축하를 어디까지 봤는지 저장합니다. 무엇을 보여줄지는 RESULT-02, POT-01을 따릅니다.

### 입력
- 방 ID
- 결과 확인일 때 회차 ID
- 한 솥 확인일 때 본 완성 횟수

### 처리 규칙
