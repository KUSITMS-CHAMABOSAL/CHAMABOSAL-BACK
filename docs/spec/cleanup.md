# 정리 배치

나간 멤버의 기록, 삭제한 사용자, 빈 방을 정리합니다. 인증 사진 삭제는 CERT-04, 쓰이지 않은 업로드 사진은 저장소 수명 주기 규칙을 따릅니다. 모든 배치는 다시 실행해도 안전해야 합니다.

## CLEAN-01 떠난 보살 기록

상태: 미구현

### 기능 설명
나간 지 6개월이 지난 멤버의 사진, 한 줄 기록, 쓴 금액을 삭제합니다.

### 입력
- 나간 시각이 있는 멤버

### 처리 규칙
1. 매일 실행한다. [PRD]
2. `left_at + 6개월` 시각이 지난 멤버의 인증에서 남은 사진을 삭제하고 한 줄 기록과 쓴 금액을 비운다. [Q-19]
3. 나간 유형이 `LEFT`, `KICKED`, `DATA_DELETED`인 멤버를 모두 대상으로 한다. [PRD] [Q-39]
4. 투표 결과는 지우지 않고 "떠난 보살"로 남긴다. [Q-19]
5. 6개월 안에 다시 들어온 멤버는 나간 시각이 비어 대상에서 빠진다. (INVITE-03) [PRD]

### 출력
- 없음

### 예외
- 이미 정리한 기록은 다시 실행해도 오류 없이 넘어간다

### 제외 범위
- 회차 종료 7일 뒤 사진 삭제 (CERT-04)
- 사용자 행 정리 (CLEAN-02)

### 완료 조건

**CLEAN-01-1 6개월이 지난 기록**
- Given A가 나간 지 6개월이 지났고 사진, 한 줄, 금액이 있다
- When 배치가 실행되면
- Then A의 사진이 삭제되고 한 줄과 금액이 비워진다

**CLEAN-01-2 6개월이 지나지 않은 기록**
- Given A가 나간 지 5개월 됐다
- When 배치가 실행되면
- Then A의 한 줄과 금액은 그대로다

**CLEAN-01-3 다시 들어온 멤버**
- Given A가 나갔다가 6개월 안에 다시 들어와 현재 멤버다
- When 처음 나간 시각에서 6개월이 지나 배치가 실행되면
- Then A의 기록은 그대로다

**CLEAN-01-4 내 데이터 삭제로 나감**
- Given A가 내 데이터를 삭제한 지 6개월이 지났다
- When 배치가 실행되면
- Then A의 한 줄과 금액이 비워진다

**CLEAN-01-5 다시 실행**
- Given 배치가 이미 A의 기록을 정리했다
- When 배치가 다시 실행되면
- Then 오류 없이 끝난다

**CLEAN-01-6 투표 결과 유지**
- Given A가 지목된 회차가 있고 A가 나간 지 6개월이 지났다
- When 배치가 실행된 뒤 그 회차 결과를 조회하면
- Then 결과와 득표수는 그대로이고 A는 "떠난 보살"로 표시된다

**CLEAN-01-7 내보내진 멤버**
- Given A가 내보내진 지 6개월이 지났고 한 줄과 금액이 있다
- When 배치가 실행되면
- Then A의 한 줄과 금액이 비워진다

## CLEAN-02 삭제한 사용자

상태: 미구현

### 기능 설명
내 데이터를 삭제한 지 6개월이 지난 사용자의 식별키와 멤버 연결을 끊습니다.

### 입력
- 삭제 시각이 있는 사용자

### 처리 규칙
1. 매일 실행한다. [PRD]
2. `deleted_at + 6개월` 시각이 지난 사용자를 대상으로 한다. 그 시각까지는 복구할 수 있다. (AUTH-01) [PRD]
3. `users` 행은 남기고 `toss_anon_key`를 비운다. [PRD]
4. 그 사용자의 `room_members.user_id`를 비운다. [PRD]
5. 로그인이 AUTH-01 6번으로 키를 먼저 비운 사용자도 멤버 연결을 끊는다. [구현 결정]
6. 복구한 사용자는 삭제 시각이 비어 대상에서 빠진다. [PRD]
7. 이후 같은 `anonKey`로 오면 신규 사용자이고 예전 공양미, 아이템, 방어권을 이어받지 않는다. [PRD]

### 출력
- 없음

### 예외
- 이미 정리한 사용자는 다시 실행해도 오류 없이 넘어간다

### 제외 범위
- 멤버의 한 줄·금액 삭제 (CLEAN-01)
- 공양미, 아이템, 방어권 행 삭제 (정리 규칙 없음)

### 완료 조건

**CLEAN-02-1 6개월이 지난 사용자**
- Given A가 내 데이터를 삭제한 지 6개월이 지났다
- When 배치가 실행되면
- Then `users` 행은 남고 식별키와 A의 멤버 연결이 비워진다

**CLEAN-02-2 6개월이 지나지 않은 사용자**
- Given A가 내 데이터를 삭제한 지 5개월 됐다
- When 배치가 실행되면
- Then A의 식별키와 멤버 연결은 그대로다

**CLEAN-02-3 복구한 사용자**
- Given A가 삭제 후 6개월 안에 복구했다
- When 처음 삭제 시각에서 6개월이 지나 배치가 실행되면
- Then A의 식별키는 그대로다

**CLEAN-02-4 로그인이 먼저 키를 비움**
- Given 6개월이 지나 돌아온 A의 로그인으로 예전 행의 식별키가 비워졌다
- When 배치가 실행되면
- Then 예전 행의 멤버 연결이 비워지고 새 사용자는 그대로다

**CLEAN-02-5 정리 후 로그인**
- Given 배치가 A를 정리했다
- When 같은 `anonKey`로 로그인하면
- Then 새 사용자를 만들고 공양미는 0석이다

**CLEAN-02-6 다시 실행**
- Given 배치가 이미 A를 정리했다
- When 배치가 다시 실행되면
- Then 오류 없이 끝난다

## CLEAN-03 빈 방

상태: 미구현

### 기능 설명
방 만들기 중 이탈해서 현재 멤버 0명으로 남은 방을 삭제합니다. 방을 WF 03 제출 때 만들기로 정하면 빈 방이 생기지 않아 이 기능을 뺍니다. [미정] Q-32

### 입력
- 삭제되지 않은 방

### 처리 규칙
1. 현재 멤버가 0명인 방의 삭제 시각을 기록한다. [PRD]
2. 빈 방은 참여 방 개수에 세지 않는다. [PRD]
3. 매일 실행하고 만든 지 24시간이 지난 방만 대상으로 한다. 방 만들기 중인 방을 지우지 않기 위해서다. [구현 결정]
4. 멤버가 들어온 방은 삭제하지 않는다. 배치와 닉네임 제출이 동시에 일어나도 같다. [구현 결정]

### 출력
- 없음

### 예외
- 이미 삭제된 방은 다시 실행해도 오류 없이 넘어간다

### 제외 범위
- 마지막 멤버가 나간 방 삭제 (ROOM-07)

### 완료 조건

**CLEAN-03-1 빈 방 삭제**
- Given 현재 멤버가 0명이고 만든 지 24시간이 지난 방이 있다
- When 배치가 실행되면
- Then 방의 삭제 시각이 기록된다

**CLEAN-03-2 멤버가 있는 방**
- Given 현재 멤버가 1명인 방이 있다
- When 배치가 실행되면
- Then 방은 그대로다

**CLEAN-03-3 동시 닉네임 제출**
- Given 현재 멤버가 0명이고 만든 지 24시간이 지난 방이 있다
- When 배치와 닉네임 제출이 동시에 실행되면
- Then 멤버가 생겼다면 방은 삭제되지 않는다

**CLEAN-03-4 다시 실행**
- Given 배치가 이미 빈 방을 삭제했다
- When 배치가 다시 실행되면
- Then 오류 없이 끝나고 삭제 시각은 그대로다

**CLEAN-03-5 방금 만든 빈 방**
- Given 현재 멤버가 0명이고 만든 지 1시간 된 방이 있다
- When 배치가 실행되면
- Then 방은 그대로다
