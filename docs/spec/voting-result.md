# 투표 · 결과

투표 시작부터 결과 발표, 이마 톡톡, 연속 지목 휴식까지 다룹니다. 회차 상태와 투표 명단은 [`common.md`](common.md)를 따릅니다.

## VOTE-01 투표 시작

상태: 미구현

### 기능 설명
전원 인증 또는 다음 날 03:00에 투표를 시작하고 명단과 판정 데이터를 고정한다.

### 입력
- 방의 현재 회차
- 활성 멤버와 인증 상태
- 휴식 상태

### 처리 규칙
1. 활성 멤버 전원이 인증하면 즉시 시작한다. 전원에는 그날 들어온 멤버와 휴식 중인 멤버도 포함한다. [정책서]
2. 전원 인증이 아니면 다음 날 03:00에 시작한다. [정책서]
3. 시작 시점 활성 멤버를 투표 명단으로 저장한다. 명단 중 시작 시점까지 인증한 멤버에게만 투표권을 준다. [정책서] [11/8 회의]
4. 명단이 3명 미만이면 투표를 생성하지 않고 회차를 `투표 없음`으로 바꾼 뒤 친구 초대 상태를 반환한다. [정책서] 인증한 멤버가 1명뿐이어도 투표를 연다. [11/8 회의] 인증한 멤버가 0명이면 명단이 3명 이상이어도 `투표 없음`이다. [정책서]
5. 인증·휴식 상태를 결과 판정용으로 고정한다. [구현 결정]
6. 투표를 시작할 때 바로 보내는 알림은 없다. 투표 알림은 시작 방식과 상관없이 다음 날 08:00에 보낸다. (NOTI-02) [정책서] [Q-24]
7. `투표 없음`이 되면 그 시점에 다음 회차 인증을 연다. (CERT-01 8번) [Q-82]

### 출력
- 투표 회차
- 명단 및 후보 스냅샷
- 늦어도 닫히는 시각: 회차 날짜 다음 날 15:00

### 예외
- 동일 시작 조건을 여러 서버가 처리해도 투표는 하나만 생성한다.

### 제외 범위
- 후보 계산 (VOTE-02)
- 투표 알림 발송 (NOTI-02)

### 완료 조건

**VOTE-01-1 전원 인증하면 바로 시작**
- Given 활성 멤버 4명(오늘 들어온 1명, 휴식 중 1명 포함) 중 3명이 인증한 `인증 중` 회차
- When 남은 1명이 인증하면
- Then 즉시 투표가 시작되고 명단은 4명이다

**VOTE-01-2 전원 인증이 아니면 다음 날 03:00에 시작**
- Given 활성 멤버 4명 중 2명이 인증한 11/5 회차
- When 11/6 03:00이 되면
- Then 투표가 시작되고 늦어도 닫히는 시각은 11/6 15:00이다

**VOTE-01-3 3명 미만이면 투표 없음**
- Given 활성 멤버가 2명인 방의 11/5 회차
- When 11/6 03:00이 되면
- Then 투표를 만들지 않고 회차는 `투표 없음` 상태가 되며 친구 초대 상태를 반환한다
- And 11/6 회차 인증이 바로 열린다

**VOTE-01-4 판정 데이터 고정**
- Given A가 인증한 상태에서 투표가 시작됐다
- When 투표 중에 A가 인증을 삭제하면
- Then 거부되고 판정에 쓰는 A의 인증은 그대로다

**VOTE-01-5 동시 시작 요청**
- Given 마지막 인증 처리와 03:00 작업이 같은 회차에 동시에 실행된다
- When 둘 다 투표 시작을 시도하면
- Then 투표는 하나만 생성된다

**VOTE-01-6 시작할 때 바로 알림 없음**
- Given 23:00에 남은 1명만 인증하면 전원 인증이 된다
- When 그 1명이 인증해 투표가 시작되면
- Then 바로 보내는 투표 알림은 없고 다음 날 08:00 투표 알림 대상이 된다

**VOTE-01-7 미인증 멤버는 투표권 없음**
- Given 활성 멤버 4명 중 A, B만 인증했다
- When 다음 날 03:00에 투표가 시작되면
- Then 명단은 4명이고 투표권은 A, B에게만 있다

**VOTE-01-8 인증한 멤버가 1명이어도 투표**
- Given 활성 멤버 3명 중 A만 인증했다
- When 다음 날 03:00이 되면
- Then 투표가 시작되고 A만 투표권이 있다

**VOTE-01-9 인증한 멤버가 0명이면 투표 없음**
- Given 활성 멤버 3명이 아무도 인증하지 않았고 콕으로 회차 행이 있다
- When 다음 날 03:00이 되면
- Then 투표를 만들지 않고 회차는 `투표 없음` 상태가 된다

## VOTE-02 후보 결정

상태: 구현됨

### 기능 설명
투표자마다 본인을 뺀 후보를 제공한다. 휴식 중인 사용자는 선택할 수 없게 표시한다.

### 입력
- 투표 명단
- 인증 상태
- 휴식 상태

### 처리 규칙
1. 투표 명단의 멤버를 기본 후보로 한다. [정책서]
2. 투표자 본인은 후보에서 제외한다. [정책서]
3. 휴식 중인 멤버는 후보 목록에 `휴식 중`으로 표시하되 선택할 수 없다. [WF 22]
4. 기존 멤버의 미인증은 후보에 포함한다. [정책서]
5. 투표 시작 이후 참여한 멤버는 명단과 후보에서 제외한다. [정책서]
6. 후보와 별도로 `오늘은 모두 보살`을 항상 제공한다. [정책서]
7. 그날 들어와서 인증하지 않은 멤버는 후보에서 제외한다. [정책서]

### 출력
- 후보의 보살·닉네임
- 인증 상태와 인증 내용
- 후보별 선택 가능 여부와 불가 사유(`휴식 중`)
- `오늘은 모두 보살`

### 예외
- 후보가 한 명뿐이어도 `오늘은 모두 보살`을 선택할 수 있다.

### 제외 범위
- 투표 제출 검증 (VOTE-03)

### 완료 조건

공통 Given: 명단은 A, B, C, D이고 A가 투표자다.

**VOTE-02-1 본인 제외**
- When A가 후보를 조회하면
- Then B, C, D와 `오늘은 모두 보살`이 나오고 A는 없다

**VOTE-02-2 본인 투표 서버 차단**
- When A가 A에게 투표하는 요청을 직접 보내면
- Then 서버가 거부한다

**VOTE-02-3 휴식 중 표시**
- Given C가 휴식 중이다
- When A가 후보를 조회하면
- Then C는 `휴식 중`, 선택 불가로 나온다

**VOTE-02-4 휴식 중 투표 서버 차단**
- Given C가 휴식 중이다
- When A가 C에게 투표하는 요청을 직접 보내면
- Then 서버가 거부한다

**VOTE-02-5 기존 멤버 미인증은 후보**
- Given 기존 멤버 B가 인증하지 않았다
- When A가 후보를 조회하면
- Then B는 선택 가능한 후보다

**VOTE-02-6 오늘 들어온 미인증 멤버 제외**
- Given D가 오늘 들어왔고 인증하지 않았다
- When A가 후보를 조회하면
- Then D는 후보에 없다

**VOTE-02-7 시작 후 참여자 제외**
- Given 투표 시작 뒤 E가 방에 들어왔다
- When A가 후보를 조회하면
- Then E는 명단과 후보에 없다

**VOTE-02-8 후보가 한 명뿐일 때**
- Given B만 선택 가능한 후보다
- When A가 후보를 조회하면
- Then A는 B 또는 `오늘은 모두 보살`을 선택할 수 있다

## VOTE-03 투표 제출

상태: 구현됨

### 기능 설명
투표권이 있는 명단 사용자(투표 시작 시점까지 인증한 멤버)가 후보 또는 `오늘은 모두 보살`에 한 번 투표한다. WF 22·23·59.

### 입력
- 투표 회차 ID
- 선택한 후보 또는 `ALL_BOSAL`

### 처리 규칙
1. 투표 명단에 있고 투표 시작 시점까지 인증한 사용자만 제출할 수 있다. [정책서] [11/8 회의]
2. 투표 전에 변경 불가 안내를 확인한다. [정책서]
3. 1인 1표이며 제출 후 변경·취소할 수 없다. [정책서]
4. 본인은 선택할 수 없다. [정책서]
5. 투표 보상은 정상 제출과 함께 한 번만 적립한다. [정책서]
6. `오늘은 모두 보살` 선택에도 같은 보상을 지급한다. [정책서]
7. 마지막 미투표자가 제출하면 즉시 투표를 마감한다. [정책서]
8. 투표 중에는 후보별 득표 수를 공개하지 않는다. 투표한 사람 수와 투표권 있는 인원만 공개한다. [정책서] [WF 24]
9. 투표 시작 뒤 나갔다가 다시 들어온 멤버는 이번 회차에 투표할 수 없다. 나가기 전에 이미 낸 표는 유지한다. [PRD]
10. 인증하지 않아 투표권이 없는 사용자는 그 사유로 거부한다. 화면은 다음 날 인증을 권하는 안내를 띄운다. [11/8 회의]

### 출력
- 투표 완료 상태
- 개인 +5석, 방 솥 +5석 적립 결과
- 결과 공개 여부

### 예외
- `ROUND_001` (404): 없는 회차
- `ROOM_002` (403): 이 방 멤버가 아님
- `VOTE_001` (409): 투표 중이 아님 (시작 전이거나 마감 후). 표를 저장하지 않고, 화면은 결과나 투표 탭 상태를 다시 조회한다
- `VOTE_002` (403): 명단 밖 (투표 시작 뒤 들어왔거나 나갔다가 다시 들어옴)
- `VOTE_003` (403): 투표권 없음 (투표 시작 시점까지 인증하지 않음)
- `VOTE_004` (409): 이미 투표함. 기존 표를 유지하고 추가 보상을 지급하지 않는다
- `VOTE_005` (400): 본인 선택
- `VOTE_006` (400): 선택할 수 없는 후보 (휴식 중, 후보가 아님)
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 투표 마감 판단 (VOTE-04)
- 공양미 계산 (RICE-01)

### 완료 조건

공통 Given: 명단은 A, B, C, D이고 모두 인증했으며 투표 중이다.

**VOTE-03-1 정상 제출**
- When A가 B에게 투표하면
- Then A는 투표 완료 상태가 되고 A +5석, 방 솥 +5석이 한 번 적립된다

**VOTE-03-2 모두 보살 선택도 같은 보상**
- When A가 `오늘은 모두 보살`을 선택하면
- Then A +5석, 방 솥 +5석이 적립된다

**VOTE-03-3 명단 밖 사용자 거부**
- Given E가 투표 시작 뒤 들어왔다
- When E가 투표하면
- Then 거부한다

**VOTE-03-4 중복 제출**
- Given A가 이미 B에게 투표했다
- When A가 C에게 다시 투표하면
- Then A의 표는 B로 유지되고 추가 보상은 없다

**VOTE-03-5 마감 후 제출**
- Given 투표가 마감됐다
- When A가 투표하면
- Then 표를 저장하지 않고 `VOTE_001`을 돌려준다

**VOTE-03-6 투표 중 득표 비공개**
- Given A, B가 투표했다
- When 누구든 투표 현황을 조회하면
- Then `2/4`만 나오고 후보별 득표 수는 없다

**VOTE-03-7 마지막 두 표 동시 제출**
- Given A, B가 투표했다
- When C와 D가 동시에 투표하면
- Then 마감과 결과는 한 번만 생기고 C, D 보상은 각각 한 번이다

**VOTE-03-8 다시 들어온 멤버는 투표 불가**
- Given C가 투표 시작 뒤 방을 나갔다가 다시 들어왔다
- When C가 투표하면
- Then 거부한다

**VOTE-03-9 미인증 멤버는 투표 불가**
- Given D가 이 회차에 인증하지 않고 투표가 시작됐다
- When D가 투표하면
- Then `투표권 없음` 사유로 거부하고 보상은 없다

## VOTE-04 투표 마감

상태: 구현됨

### 기능 설명
투표권 있는 명단 멤버 전원이 투표하거나 회차 날짜 다음 날 15:00이 되면 투표를 마감한다.

### 입력
- 투표 명단과 제출된 표
- 현재 시각

### 처리 규칙
1. 투표권 있는 명단 멤버 전원이 투표하면 즉시 마감한다. 미인증 멤버는 기다리지 않는다. [정책서] [11/8 회의]
2. 미투표자가 남아 있으면 회차 날짜 다음 날 15:00에 자동 마감한다. [정책서]
3. 미투표자는 기권 처리한다. [정책서]
4. 1번과 2번 어느 쪽으로 마감해도 즉시 결과를 계산하고 발표한다. [정책서] [Q-56]
5. 마감 전에 나간 명단 멤버가 이미 낸 표는 집계에 포함한다. 투표하지 않고 나간 멤버는 기권으로 보고, 전원 투표 조기 마감은 남은 명단 멤버 중 투표권 있는 사람 기준으로 판단한다. [PRD] 나갔다가 다시 들어온 명단 멤버를 남은 명단에 넣을지는 [미정] Q-36
6. 2번으로 마감한 투표도 결과 판정, 이마 톡톡, 지목 횟수, 연속 지목, 방어권을 1번과 똑같이 처리한다. [Q-56]
7. 마감하면 그 즉시 다음 회차 인증을 연다. (CERT-01 8번) [정책서] [Q-82]

### 출력
- 마감 시각
- 투표 결과
- 결과 미확인 사용자 목록

### 예외
- 아무도 투표하지 않은 채 2번으로 마감되면 `모두 무사`다. (RESULT-01)
- 투표 중에 나간 명단 멤버가 후보로 남는지, 지목될 수 있는지는 아직 정하지 않았다. [미정] Q-27

### 제외 범위
- 결과 판정 규칙 (RESULT-01)
- 결과 알림 (NOTI-02)

### 완료 조건

공통 Given: 명단은 A, B, C, D이고 모두 인증했으며 투표 중이다.

**VOTE-04-1 전원 투표 즉시 마감**
- Given A, B, C가 투표했다
- When D가 투표하면
- Then 즉시 마감하고 결과를 계산한다

**VOTE-04-2 15:00 자동 마감**

**VOTE-04-3 마감하면 다음 회차 인증 열림**

**VOTE-04-5 나간 멤버가 낸 표는 유지**

**VOTE-04-6 투표하지 않고 나간 멤버는 기권**

**VOTE-04-7 미인증 멤버는 기다리지 않음**

- Then 즉시 마감하고 결과를 계산한다

## RESULT-01 결과 판정

2. 아니면 최다 득표 후보를 지목한다. [정책서]

7. 마감 전에 나간 멤버가 이미 낸 표도 `실제 투표자`에 넣는다. (VOTE-04 5번) [PRD]

## RESULT-02 결과 확인

상태: 미구현

### 기능 설명
마감 후 사용자가 아직 보지 않은 가장 최근 결과 하나를 확인한다. WF 25·29·30·31.

### 입력
- 방 ID
- 조회한 사용자

### 처리 규칙
1. 앱 진입 시 현재 방의 미확인 결과 중 가장 최근 하나만 보여준다. [정책서]
2. 결과에는 후보별 득표 수를 표시한다. [정책서]
3. 누가 누구에게 투표했는지는 표시하지 않는다. [정책서]
4. `PICKED` 결과에서 지목된 사용자를 뺀 방 활성 멤버 전원에게 이마 톡톡 기회를 제공한다. 투표하지 않은 멤버도 포함한다. [정책서] [WF 25]
5. `ALL_BOSAL`, `ALL_SAFE`, `DEFENDED`에는 이마 톡톡이 없다. `PICKED`였다가 방어로 `DEFENDED`가 되면 그 전에 보낸 톡톡도 무효다. (SHIELD-02) [정책서] [Q-75] 15:00에 자동 마감된 투표(VOTE-04 2번)도 같은 기준을 따른다. [Q-56]
6. 지목된 사람이 `PICKED` 결과를 처음 조회하면 그 시각을 기록한다. 결과에는 방어 마감 시각, 보유한 방어권 개수, 지금 방어권을 쓰면 성공하는지를 항상 담는다. 방어 마감 시각(처음 조회 + 2분)은 지목된 사람의 `PICKED` 결과에서만, 보유한 방어권 개수는 지목된 사람의 `PICKED`·`DEFENDED` 결과에서만 값을 채우고 그 밖에는 비운다(`null`). 사용 성공 여부는 그 밖에는 `false`다. 보유 개수는 결과 화면의 `보유 방어권 n개` 표시에 쓴다. 방어권은 여러 개 가질 수 있다. (SHIELD-01) (SHIELD-02) [Q-75] [디자인 결과·이마톡톡-13] [구현 결정]
7. 톡톡 기한이 지난 뒤 처음 결과를 열면 결과는 보여주되 톡톡 없이 `톡톡 시간이 지났어요`를 안내한다. [WF 25]
8. 결과를 확인하면 그 회차와 이전 회차 결과를 모두 확인한 것으로 처리한다. 멤버별로 마지막으로 본 회차 날짜 하나만 저장한다. [구현 결정]
9. 방에 들어오거나 다시 들어올 때 확인 상태를 가장 최근 발표 회차로 채운다. 들어오기 전의 결과는 보여주지 않는다. [구현 결정]

### 출력
- 결과 화면 데이터
- 나를 뺀, 그 회차 톡톡을 끝낸 멤버 수 [WF 25]
- 지목된 사람의 인증 결과와 쓴 금액 (디자인 p91) [구현 결정]
- 방어 마감 시각, 보유한 방어권 개수, 방어권 사용 가능 여부 (지목된 사람이 아니면 `null`, `null`, `false`)
- 결과 확인 상태
- 이어서 보여줄 진입 이벤트

### 예외
- `ROUND_001` (404): 없는 회차
- `ROOM_002` (403): 이 방 멤버가 아님
- `RESULT_001` (409): 아직 발표 전인 회차
- `COMMON_008` (401): 인증 필요

### 완료 조건

**RESULT-02-1 최근 하나만 노출**

- When 앱에 들어오면

**RESULT-02-4 지목된 사람의 방어 마감**
- Given A가 `PICKED`이고 방어권 2개를 보유했다
- When A가 11/3 08:00에 결과를 처음 조회하면
- Then 방어 마감 시각은 08:02, 보유한 방어권은 2개, 방어권 사용 가능 여부는 true다
- And B가 같은 결과를 조회하면 방어 마감 시각과 보유 개수는 `null`, 사용 가능 여부는 `false`다

**RESULT-02-5 톡톡 기한 지남**
- Given A가 `PICKED`이고 다음 투표가 이미 열렸다
- When C가 이 결과를 처음 열면
- Then 결과는 보이고 톡톡 없이 `톡톡 시간이 지났어요`가 나온다

## RESULT-03 이마 톡톡

상태: 미구현

### 기능 설명
지목되지 않은 방 멤버가 지목 사용자의 이마를 회차당 10번 두드린다. WF 26·27·28.

### 입력
- 결과 회차
- 발신 사용자
- 탭 횟수

### 처리 규칙
1. 발신자당 회차에 한 세트만 가능하다. [정책서]
2. 최대 10번이며 건너뛸 수 있다. [정책서]
3. 중간에 화면을 나가면 그 회차 세트는 종료하고 친 횟수만 저장한다. [정책서]
4. 다음 투표가 열리기 전까지만 가능하다. 투표는 겹치지 않는다. (VOTE-04) [11/8 회의]
5. 수신자에게 실시간 재생하지 않고 앱 열기 또는 오늘 탭 재진입 때 재생한다. [정책서]
6. 받은 톡톡 조회는 아직 재생하지 않은 톡톡만 돌려준다. 재생 완료를 저장하면 그때까지 받은 톡톡이 모두 재생됨으로 바뀌어 조회 결과는 빈 목록이 되고, 그 뒤에 도착한 톡톡만 다시 나온다. [구현 결정]
7. 지목된 사람의 방어 시간(SHIELD-02) 중에도 바로 보낼 수 있다. 지목된 사람이 방어하면 그 회차 톡톡은 무효가 되어 재생하지 않고, 받은 톡톡 조회는 빈 목록이다. [Q-75]
8. 1번 이상 보내면 보낸 사람에게 개인 +5석, 방 솥 +5석을 적립한다. 0번(건너뛰기)은 적립하지 않는다. (RICE-01 4번) [정책서]
9. 지목된 사람이 받은 톡톡 횟수만큼 번뇌를 수행하면 개인 +10석을 적립한다. (RICE-01 6번) [정책서] 무엇을 수행 완료로 보는지는 [미정] Q-92

### 출력
- 발신자별 전달 횟수
- 보낸 사람의 개인·방 솥 공양미 적립 결과
- 수신자의 미재생 톡톡 목록
- 재생 완료 상태

### 예외
- 지목 사용자 본인, 방 활성 멤버가 아닌 사용자, 이미 완료한 발신자는 추가 전송할 수 없다. 투표 시작 후 들어온 멤버는 보낼 수 있다. [정책서] [WF 25]
- `ROUND_001` (404): 없는 회차
- `ROOM_002` (403): 방 활성 멤버가 아님
- `TAP_001` (409): 처음부터 톡톡이 없는 회차. 결과가 `PICKED`가 아님 (방어된 결과 포함)
- `TAP_002` (403): 지목된 본인이 보냄
- `TAP_003` (409): 이미 톡톡함. 저장된 횟수는 그대로다
- `TAP_004` (409): 톡톡 시간 지남. `PICKED` 결과인데 그 뒤 다음 투표가 열림
- `TAP_005` (403): 받은 톡톡 조회·재생 완료를 지목된 사람이 아닌 사용자가 요청
- `COMMON_002` (400): 횟수가 0~10이 아님
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 톡톡 연출 (화면에서 처리)

### 완료 조건

공통 Given: A가 지목됐고 B는 같은 방 활성 멤버다.

**RESULT-03-1 10회 상한**
- Given B가 10번을 쳤다
- When 같은 요청이 재시도되면
- Then 저장된 횟수는 10이다

**RESULT-03-2 중간에 나감**
- Given B가 4번 치고 화면을 나갔다
- When B가 다시 들어와 톡톡을 시도하면
- Then 저장된 횟수는 4이고 추가로 칠 수 없다

**RESULT-03-3 건너뛰기**
- When B가 건너뛰면

**RESULT-03-4 기한 지남**
- Given 다음 투표가 열렸다
- When B가 톡톡을 보내면

**RESULT-03-5 보낼 수 없는 사용자**

- Given E가 투표 시작 뒤 들어왔다

- Then 저장된다

**RESULT-03-7 재생**

- When A가 앱을 열면
- Then B의 톡톡 5번이 재생되고, 다음 앱 진입 때는 다시 재생되지 않는다

**RESULT-03-10 방어 시간 중 톡톡**

**RESULT-03-12 톡톡 완료 보상**

## RESULT-04 연속 지목 휴식

상태: 미구현

### 기능 설명
같은 방에서 3회 연속 지목된 사용자를 다음 1회 후보에서 제외한다.

### 입력
- 회차 결과

### 처리 규칙
1. `PICKED`와 `DEFENDED` 결과에서 지목된 사용자의 연속 지목을 1 증가시킨다. [정책서] [WF 31·63]
2. 이번 달 지목 횟수는 `PICKED`에서만 증가하고 `DEFENDED`에서는 늘지 않는다. [정책서] [WF 63]
3. 다른 사용자 지목, 모두 보살, 모두 무사 또는 휴식 완료 시 연속 카운트를 0으로 만든다. 다른 사용자가 방어한 결과도 다른 사용자 지목으로 볼지는 아직 정하지 않았다. [미정] Q-23 나가 있는 동안의 결과를 다시 들어온 멤버의 연속 지목에 반영할지는 [미정] Q-35
4. 3회 연속이면 다음 회차에 `휴식 중` 상태로 후보에서 제외한다. [정책서]
5. 휴식 회차가 끝나면 상태와 연속 카운트를 초기화한다. [정책서]

### 출력
- 연속 지목 횟수
- 다음 회차 휴식 여부

### 예외
- 없음

### 제외 범위
- 이번 달 지목 횟수 화면 표시 (내 보살)

### 완료 조건

**RESULT-04-1 3회 연속이면 휴식**
- Given A가 3회 연속 `PICKED`다
- When 다음 회차 투표가 시작되면
- Then 다음 회차 후보 목록에서 A는 `휴식 중`, 선택 불가다

**RESULT-04-2 방어도 연속에 포함**
- Given A가 `PICKED` → `DEFENDED` → `PICKED`다
- When 다음 회차 투표가 시작되면
- Then A는 다음 회차에 휴식하고, 이번 달 지목 횟수는 2다

**RESULT-04-3 다른 사람 지목이면 초기화**
- Given A가 2회 연속 지목됐다
- When 다음 결과에서 B가 `PICKED`면
- Then A의 연속 지목은 0이다

**RESULT-04-4 모두 보살·모두 무사면 초기화**
- Given A가 2회 연속 지목됐다
- When 다음 결과가 `ALL_BOSAL` 또는 `ALL_SAFE`면
- Then A의 연속 지목은 0이다

**RESULT-04-5 휴식 완료**
- Given A가 휴식한 회차가 끝났다
- When 그다음 회차 투표가 시작되면
- Then A의 휴식 상태와 연속 지목은 0이고, 그다음 회차에는 후보다

**RESULT-04-6 방별 독립**
- Given A가 방 1에서 3회 연속 지목됐다
- When 방 2에서 투표가 시작되면
- Then 방 2에서 A는 휴식 중이 아니다

**RESULT-04-7 6개월 안에 다시 들어오면 유지**
- Given A가 2회 연속 지목된 상태로 방을 나갔다
- When A가 나간 지 6개월 안에 같은 방에 다시 들어오면
- Then A의 연속 지목은 2다

**RESULT-04-8 6개월이 지나 다시 들어오면 새로 시작**
- Given A가 2회 연속 지목된 상태로 방을 나갔다
- When A가 6개월이 지나 같은 방에 다시 들어오면
- Then A는 새 멤버로 들어오고 연속 지목은 0이다

참고: 다른 사람의 `DEFENDED` 시나리오는 Q-23가 결정되면 추가한다.
