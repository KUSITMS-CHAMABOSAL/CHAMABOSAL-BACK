# 나발

인증을 빠뜨리면 보살의 나발(머리카락 한 알)이 빠지고, 공양미로 나발을 다시 심습니다. 보살은 꾸미기·공양미처럼 사용자 단위라 모든 방에 같은 모습으로 보입니다. 시간 기준은 [`common.md`](common.md), 공양미 장부는 RICE-01을 따릅니다.

## NABAL-01 나발 빠짐

상태: 구현됨

### 기능 설명
회차 인증이 마감되면 그 회차에 인증하지 않은 방마다 보살의 나발을 1개씩 뺍니다. [나발 정책서]

### 입력
- 인증이 마감된 회차 날짜
- 그 회차 날짜 기준 사용자의 현재 방과 인증 기록

### 처리 규칙
1. 나발은 38개이고 0~37번으로 구분한다. 빠진 번호를 서버에 저장한다. [공양미 정책서] [나발 정책서]
2. 나발 상태는 사용자 단위다. 방마다 나누지 않고, 모든 방에 같은 모습으로 보인다. [Q-100] [Q-101]
3. 회차 인증 마감(다음 날 03:00) 뒤에 그 회차 날짜를 판정한다. [나발 정책서] [구현 결정]
4. 그 회차 날짜에 인증하지 않은 방마다 1개씩 뺀다. 두 방 다 빠뜨리면 2개다. [Q-100]
5. 인증하지 않은 방은 판정 시점의 현재 멤버인 방 중 그 회차 날짜에 삭제하지 않은 내 인증이 없는 방이다. [구현 결정]
6. 그 회차 날짜에 들어온 방은 인증하지 않아도 세지 않는다. 투표 후보와 같은 기준이다. (CERT-05 2번) [구현 결정]
7. 내 데이터를 삭제한 사용자와 참여 중인 방이 없는 사용자는 판정하지 않는다. [구현 결정]
8. 빠질 번호는 서버가 남은 나발 중 랜덤으로 정한다. 38개가 모두 빠졌으면 더 빼지 않는다. [Q-103]
9. 같은 사용자·방·회차 날짜는 한 번만 판정한다. 배치가 다시 돌아도 두 번 빠지지 않는다. [구현 결정]
10. 나발이 빠져도 투표, 공양미, 방어권에는 영향이 없다. [나발 정책서]

### 출력
- 빠진 나발 번호, 방, 회차 날짜 기록

### 예외
- 한 사용자 처리에 실패해도 다른 사용자는 계속 처리한다

### 제외 범위
- 나발 빠짐 화면, 회귀 스토리 화면, 필수 문구 표시 (클라이언트)
- 나발 심기 (NABAL-03)

### 완료 조건

**NABAL-01-1 미인증이면 1개 빠짐**
- Given A가 방 1에만 참여 중이고 11/10 회차에 인증하지 않았다
- When 11/11 03:00 판정이 돌면
- Then A의 나발이 1개 빠지고 방 1, 11/10 회차 기록이 남는다

**NABAL-01-2 인증했으면 안 빠짐**
- Given A가 11/10 회차에 방 1에서 인증했다
- When 11/11 03:00 판정이 돌면
- Then A의 나발은 그대로다

**NABAL-01-3 한 방만 빠뜨림**
- Given A가 방 1, 방 2에 참여 중이고 11/10 회차에 방 1에서만 인증했다
- When 11/11 03:00 판정이 돌면
- Then A의 나발이 1개 빠진다

**NABAL-01-4 두 방 다 빠뜨림**
- Given A가 방 1, 방 2에 참여 중이고 11/10 회차에 둘 다 인증하지 않았다
- When 11/11 03:00 판정이 돌면
- Then A의 나발이 2개 빠진다

**NABAL-01-5 그날 들어온 방**
- Given A가 방 1에서 인증했고 11/10 22:00에 방 2에 들어와 인증하지 않았다
- When 11/11 03:00 판정이 돌면
- Then A의 나발은 그대로다

**NABAL-01-6 삭제한 인증**
- Given A가 11/10 회차에 방 1에서 인증했다가 삭제했다
- When 11/11 03:00 판정이 돌면
- Then A의 나발이 1개 빠진다

**NABAL-01-7 다시 돌아도 한 번**
- Given A의 방 1, 11/10 회차 판정으로 나발이 1개 빠졌다
- When 판정이 다시 돌면
- Then A의 나발은 더 빠지지 않는다

**NABAL-01-8 모두 빠짐**
- Given A의 나발 38개가 모두 빠졌다
- When A가 인증하지 않고 판정이 돌면
- Then 더 빠지지 않는다

**NABAL-01-9 참여 방 없음**
- Given A가 참여 중인 방이 없다
- When 판정이 돌면
- Then A의 나발은 그대로다

## NABAL-02 나발 상태와 확인

상태: 구현됨

### 기능 설명
내 정보(USER-01)에 내 보살의 나발 상태를 담고, 빠지는 연출을 본 뒤 확인을 저장합니다. 클라이언트는 앱을 열 때 이 값으로 연출을 보여줄지 정합니다. [나발 정책서]

### 입력
- 로그인한 사용자
- 확인 저장: 본 마지막 나발 기록 ID

### 처리 규칙
1. 내 정보에 빠진 나발 번호, 아직 안 본 빠진 나발 번호, 마지막 나발 기록 ID, 처음 빠졌는지를 돌려준다. [나발 정책서] [구현 결정]
2. 아직 안 본 빠진 나발이 있으면 클라이언트가 처음 앱에 들어올 때 빠지는 연출을 보여준다. [나발 정책서]
3. 처음 빠졌는지는 이전에 본 나발 기록도 심은 나발 기록도 없을 때다. 클라이언트는 이때 보살 → 중생 회귀 스토리 화면을 보여준다. [나발 정책서] [구현 결정]
4. 빠진 나발이 하나라도 있으면 중생, 없으면 보살이다. [나발 정책서] [구현 결정]
5. 확인을 저장하면 보낸 기록 ID 이하의 내 나발 기록을 본 것으로 처리한다. 화면을 그린 뒤 새로 빠진 나발은 다음에 보여준다. [구현 결정]
6. 다른 사용자의 기록은 바꾸지 않는다. [구현 결정]

### 출력
- 내 정보: 빠진 나발 번호, 안 본 빠진 나발 번호, 마지막 나발 기록 ID, 처음 빠졌는지
- 확인 저장: 없음

### 예외
- `COMMON_002` (400): 기록 ID 없음
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 빠지는 연출, 회귀 스토리, 필수 문구 "모든 설정은 절약에 재미를 더하기 위한 창작적 표현이에요" (클라이언트)
- 다른 멤버 보살의 빠진 나발 표시. 오늘 탭(ROOM-02 12번) 등 보살을 그리는 각 기능에서 붙인다 [Q-101]

### 완료 조건

**NABAL-02-1 안 본 빠진 나발**
- Given A의 나발 1개가 빠졌고 아직 보지 않았다
- When 내 정보를 조회하면
- Then 그 번호가 빠진 나발과 안 본 빠진 나발에 모두 있다

**NABAL-02-2 확인 저장**
- Given A가 안 본 빠진 나발을 받았다
- When 마지막 나발 기록 ID로 확인을 저장하면
- Then 안 본 빠진 나발은 비고 빠진 나발은 그대로다

**NABAL-02-3 처음 빠짐**
- Given A의 나발이 처음으로 빠졌다
- When 내 정보를 조회하면
- Then 처음 빠졌다고 돌려준다

**NABAL-02-4 두 번째 빠짐**
- Given A가 전에 빠진 나발을 확인했고 나발이 또 빠졌다
- When 내 정보를 조회하면
- Then 처음 빠진 것이 아니다

**NABAL-02-5 화면을 그린 뒤 빠진 나발**
- Given A가 기록 1까지 받았고 그 뒤 기록 2가 생겼다
- When 기록 1로 확인을 저장하면
- Then 기록 2는 안 본 빠진 나발로 남는다

## NABAL-03 나발 심기

상태: 구현됨

### 기능 설명
사용자가 고른 빠진 나발을 1개당 공양미 15석으로 다시 심습니다. [나발 정책서] [공양미 정책서]

### 입력
- 심을 나발 번호 목록

### 처리 규칙
1. 나발 1개를 심는 데 15석이 든다. 여러 개를 한 번에 심으면 개수 × 15석이다. [공양미 정책서] [구현 결정]
2. 심을 번호는 사용자가 화면에서 고른다. [Q-103]
3. 빠진 나발만 심을 수 있다. 목록 중 하나라도 빠지지 않은 나발이면 아무것도 심지 않는다. [공양미 정책서] [구현 결정]
4. 잔액이 필요한 석 이상이어야 한다. 음수 잔액이면 심을 수 없다. (RICE-02) [구현 결정]
5. 심으면 공양미 장부에 나발마다 15석 사용을 기록한다. [공양미 정책서]
6. 빠진 나발을 모두 심으면 보살로 돌아온다. [나발 정책서] [구현 결정]
7. 번호가 0~37이 아니거나 목록이 비었거나 같은 번호가 두 번 있으면 `COMMON_002`, 빠지지 않은 나발이면 `NABAL_001`을 돌려준다. [구현 결정]
8. 같은 나발을 동시에 심어도 공양미는 한 번만 쓴다. [구현 결정]

### 출력
- 공양미 표시 잔액
- 남은 빠진 나발 번호

### 예외
- `COMMON_002` (400): 번호 범위 밖, 빈 목록, 중복 번호
- `NABAL_001` (409): 빠지지 않은 나발
- `STORE_001` (409): 공양미 부족
- `COMMON_008` (401): 인증 필요

### 제외 범위
- 곳간 화면의 나발 심기 표시 (STORE-01)

### 완료 조건

**NABAL-03-1 나발 심기**
- Given A의 7번 나발이 빠졌고 잔액이 20석이다
- When 7번을 심으면
- Then 7번이 돌아오고 잔액은 5석이다

**NABAL-03-2 여러 개 심기**
- Given A의 3번, 7번 나발이 빠졌고 잔액이 40석이다
- When 3번, 7번을 심으면
- Then 둘 다 돌아오고 잔액은 10석이다

**NABAL-03-3 보살로 복귀**
- Given A의 빠진 나발이 7번 하나다
- When 7번을 심으면
- Then 빠진 나발이 없어 보살이다

**NABAL-03-4 빠지지 않은 나발**
- Given A의 3번 나발은 빠지지 않았고 7번은 빠졌다
- When 3번, 7번을 심으면
- Then `NABAL_001`을 돌려주고 7번은 빠진 채이며 공양미는 그대로다

**NABAL-03-5 공양미 부족**
- Given A의 7번 나발이 빠졌고 잔액이 10석이다
- When 7번을 심으면
- Then `STORE_001`을 돌려주고 7번은 빠진 채다

**NABAL-03-6 동시 요청**
- Given A의 7번 나발이 빠졌고 잔액이 30석이다
- When 7번 심기 요청 2개가 동시에 오면
- Then 1번만 심고 15석만 쓴다
